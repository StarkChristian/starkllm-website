ヘルプ

ヘルプとトラブルシューティング

StarkLLMが起動しない、または回答がおかしいと思ったら、ここから始めてください。どの手順にも確認方法があるので、どの部分が足りないのかがわかります。

チェックリスト問題サポートを受ける制限

各部分の関係

StarkLLMは1つのプログラムではありません。2つの部分が連携して動き、もう一方はデスクトップアプリが代わりに起動します：

StarkLLMアプリ（StarkLLM.exe）

エンジン（データベース、検索インデックス、バックエンド、ウェブインターフェース）を含み、v2.2以降はそれをWindows上で直接実行します。Docker DesktopもWSL2も不要です。起動のたびにOllamaを確認し、足りないモデルをダウンロードし、エンジンを起動してからStarkLLMを表示します。足りない部分があれば、それがどれで、どう直せばよいかを表示します。StarkLLMを終了すると、エンジンも停止します。

Ollama

言語モデルと埋め込みモデルを、お使いのPC上で実行します。ドキュメントと質問はPCの中にとどまります。Ollama自体がオンラインになるのは、モデルのダウンロードとOllama自身の更新確認のときだけです。Ollamaがない場合、StarkLLMは「Install Ollama for me」（Ollamaをインストールする）を表示し、署名された公式版をインストールします。その後Ollamaを起動し、モデルをダウンロードします。

Docker Desktop（任意、上級者向け）

v2.2以降は不要です。Docker Desktopを使いたい場合は、タスクトレイのメニューで「Use Docker Desktop for the engine (advanced)」（エンジンにDocker Desktopを使う〔上級者向け〕）を選んでください。StarkLLMは同じデータのまま、エンジンをDocker Desktopで実行します。

ソースコードから（任意）

開発者は、GitHubのソースコードからdocker compose up --build -dでエンジンをビルドして実行できます。

2.2より前のバージョンにはDocker DesktopとWSL2が必要でした。またv2.0.0（2026年10月24日より前）は何も起動しませんでした。v2.6.0 をインストールしてください。

正直に申し上げます：これらの手順は、アプリが起動のたびに行うチェックと、実際のテストをもとにまとめたものです。すべてのWindows PCで試せたわけではありません。ここに書かれている内容と実際の表示が違う場合は、info@starkllm.comまでお知らせください。このページを修正します。

手順ごとに確認方法を載せたインストールのチェックリスト

手順は順番どおりに進めてください。各手順の確認が通るまで、次に進まないでください。コマンドを実行するには、ターミナル（WindowsターミナルまたはPowerShell）を開いてください。

  1. 1. Windowsとディスクの空き容量StarkLLMはWindows 10または11（64ビット）で動作します。Docker DesktopとWSL2は不要です。アプリ、エンジン、AIモデルのために、ディスクの空き容量を15 GB以上確保してください。
    winver
    確認：winverでWindows 10またはWindows 11と表示されること。エクスプローラーで、ユーザーフォルダーのあるドライブ（通常はC:）に15 GB以上の空きがあること。
  2. 2. StarkLLMをインストールして起動するダウンロードページからStarkLLM-v2.6.0-Setup.exeをダウンロードしてインストールし、StarkLLMを起動します。エンジンはインストーラーに含まれています。確認：StarkLLMのウィンドウが開き、起動の進行状況が表示されること。「StarkLLM could not start」（StarkLLMを起動できませんでした）と表示された場合は、足りないものが一覧表示され、「Retry」（再試行）ボタンがあります。
  3. 3. OllamaOllamaがない場合、ウィンドウに「Install Ollama for me」が表示されます。StarkLLMがollama.comから公式インストーラー（約2 GB）をダウンロードし、署名を確認してからインストールします。管理者権限は必要ありません。ollama.comからご自身でOllamaをインストールすることもできます。
    ollama --version
curl http://localhost:11434/api/tags
    確認：2つ目のコマンドがJSON（モデルの一覧。空の場合もあります）を出力すること。
  4. 4. 2つのモデル初回起動時に、StarkLLMはチャットモデルと小さな埋め込みモデル（標準ではqwen2.5:7bとnomic-embed-text、合わせて約5 GB）をダウンロードし、進行状況を表示します。Ollamaにすでに適したモデルがあれば、代わりにそれを使います。
    ollama list
    確認：ollama listにチャットモデルと埋め込みモデルが表示されること。ダウンロードが失敗した場合は、ウィンドウにモデル名が表示されます。その名前でollama pullを実行し、「Retry」を押してください。メモリが少ない場合（8 GBのPC）は、qwen2.5:3bを使い、チャットで選択してください。
  5. 5. 最初のテストStarkLLMはこのPCのユーザーとして自動的にサインインします。アカウントを作る必要はありません。確認：ワークスペースを作成し、小さなテキストファイルをアップロードできること。ステータスが「indexed」（インデックス化済み）に変わります。続いてその内容について質問し、回答にファイル名が示されることを確認してください。

問題と対処法

問題をクリックすると、考えられる原因と解決策が表示されます。多くの方が出会う順に並べています。

インストールと起動

1. Windowsに「Windows protected your PC」（WindowsによってPCが保護されました、SmartScreen）と表示される、またはSmart App Controlがインストーラーをブロックする

考えられる原因：v2.1.2以降、インストーラー、StarkLLM.exe、アンインストーラーは「Open Source Developer Christian Stark」によって署名されているため、Windowsは発行元を確認できます。それでもWindowsは、まだあまり見かけないファイルについて警告することがあります。v2.1.2より前のバージョンには署名がありませんでした。

対処法：

  1. 発行元を確認してください：インストーラーを右クリックし、「Properties」（プロパティ）を選んで「Digital Signatures」（デジタル署名）タブを開きます。署名者は「Open Source Developer Christian Stark」で、「Details」（詳細）に「This digital signature is OK」（このデジタル署名は正常です）と表示されなければなりません。
  2. SHA-256ハッシュを、ダウンロードページに載っているものと比較してください。
  3. 両方が一致すれば続行してください（SmartScreenでは「More info」（詳細情報）、続いて「Run anyway」（実行））。一致しない場合はファイルを実行せず、もう一度ダウンロードしてinfo@starkllm.comまでお知らせください。
  4. Smart App Control、SmartScreen、その他のセキュリティ設定をオフにしないでください。正しく署名されたインストーラーをSmart App Controlがブロックする場合は、info@starkllm.comまでお知らせください。
2. Smart App Controlやセキュリティソフトがエンジンのプログラムファイルをブロックする

考えられる原因：v2.2.1以降、エンジンのすべてのプログラムファイル（Pythonパッケージ、Tesseract）は「Open Source Developer Christian Stark」によって署名されているため、Smart App Controlはそれらの実行を許可します。それでも、別のアプリケーション制御のルールやセキュリティソフトがファイルをブロックすることがあり、その場合エンジンは起動しません。

対処法：

  1. 起動ページに、ブロックされたファイルとエンジンのログ（%APPDATA%\StarkLLM\engine-native.log）が表示されます。
  2. Smart App Controlやセキュリティソフトをオフにしないでください。ファイル名をGitHubのStarkLLMのページかinfo@starkllm.comまでお知らせください。
  3. 解決するまでは、タスクトレイのメニューで「Use Docker Desktop for the engine (advanced)」を選ぶこともできます（WSL2を使うDocker Desktopが必要です）。
3. 「Ollama is not installed」（Ollamaがインストールされていません）または「Ollama is not running」（Ollamaが実行されていません）

考えられる原因：StarkLLMはAIモデルをOllama（無料）で実行し、127.0.0.1:11434にあることを前提としています。

対処法：

  1. 起動ページで「Install Ollama for me」を押すか、ollama.comからご自身でOllamaをインストールしてください。
  2. Ollamaがインストール済みの場合：スタートメニューから起動し、タスクトレイにアイコンが表示されるのを待ってから「Retry」を押してください。
  3. PCから確認してください：
  4. curl http://localhost:11434/api/tags
4. 「pull model manifest: file does not exist」、「model not found」、またはモデルが大きすぎてPCが固まる

考えられる原因：そのモデル名がOllamaに存在しないか、選んだモデルがPCのメモリよりはるかに多くのメモリを必要としています（27Bモデルには約17 GBの空きメモリが必要です）。古いstart-here.txtと.env.exampleにはqwen3.8:27bとqwen3-embedding:0.6bが書かれていました。

対処法：

  1. 標準のセットアップのモデルを使ってください：
  2. ollama pull qwen2.5:7b
ollama pull nomic-embed-text
  3. または、モデル選択（左下の「AI MODEL」）でインストール済みのモデルを選んでください。
  4. 別の埋め込みモデルでインデックス化したドキュメントは、もう一度アップロードする必要があります（ベクトルのサイズが違うためです）。
5. 「Another StarkLLM engine already uses port 5173」（別のStarkLLMエンジンがすでにポート5173を使用しています）、またはポートが使用中のためエンジンが起動しない

考えられる原因：エンジンはPCのポート5173（127.0.0.1）でアプリを提供します。別のプログラム、または以前にDocker DesktopでインストールしたStarkLLMのコンテナーが、すでにそのポートを使っています。StarkLLMは自分の古いコンテナーは自動で停止しますが、ほかのプログラムは停止できません。

対処法：

  1. そのプログラムを探して終了してください：
  2. netstat -ano | findstr :5173
tasklist /FI "PID eq <最後の列の番号>"
  3. またはStarkLLMを別のポートに移してください：setx STARKLLM_UI_PORT 5174を実行し、タスクトレイのメニューでStarkLLMを終了してから、もう一度起動します。
6. 初回起動にとても時間がかかる、またはダウンロードが失敗する

考えられる原因：初回起動ではAIモデル（約5 GB）と、許可した場合はOllama（約2 GB）をダウンロードします。インターネットが遅い、会社のプロキシ、VPN、ウイルス対策ソフトのスキャン、ディスクがほぼいっぱい、といった理由で遅くなったり止まったりします。

対処法：

  1. ディスクの空き容量を15 GB以上確保してください（モデル約5 GBに加え、Ollama、アプリ、エンジン）。
  2. ウィンドウには各ダウンロードの進行状況が表示されます。TLSや接続のエラーは、ネットワークがブロックされていることを示します。別のネットワークを試してください。
  3. 原因を取り除いたら「Retry」を押してください。ダウンロード済みのモデルは再びダウンロードされません。
7. ウィンドウに「StarkLLM could not start」と表示される

考えられる原因：アプリはOllamaとエンジンを自分で起動し、ある手順が失敗するとこのページを表示します。

対処法：

  1. ページの赤い行を読んでください。足りない部分が示されています（Ollama、使用中のポート、Windowsがブロックしたプログラムファイル、またはログの最後の行が付いたエンジンのエラー）。
  2. その部分を直して「Retry」を押してください。ログは%APPDATA%\StarkLLMにあります：engine.log（アプリ）とengine-native.log（エンジン）。
  3. インストールや更新の後の初回起動は、負荷の高いPCでは数分かかることがあります。待っている間、ウィンドウにその旨が表示されます。
8. 起動後、ウィンドウが空のまま、またはエラーページが表示される

考えられる原因：エンジンがまだ起動中か、停止しています。

対処法：

  1. 1〜2分待ってから、タスクトレイのメニューで「Reload Application」（アプリケーションを再読み込み）を選んでください。
  2. それでも空のままなら、タスクトレイのメニューでStarkLLMを終了し、もう一度起動してください。
  3. エラーは通常、エンジンのログの最後の20行に書かれています（PowerShellで開きます）：
  4. notepad "$env:APPDATA\StarkLLM\engine-native.log"
9. エンジンにDocker Desktopを使っていて（上級者向け）、起動しない

考えられる原因：タスクトレイのメニューで「Use Docker Desktop for the engine (advanced)」を選んでいる場合、2.2より前のバージョンと同じく、StarkLLMにはWSL2を使うDocker Desktopが必要です。「error during connect ... dockerDesktopLinuxEngine」や「WSL 2 installation is incomplete」といったエラーはDocker Desktopが出しているものです。

対処法：

  1. Docker Desktopを起動し、そのエンジンが動き出すまで待ってください。docker infoに「Server:」の項目が表示されなければなりません。
  2. WSL2がない場合は、管理者のターミナルでwsl --installを実行し、再起動してください。BIOS/UEFIで仮想化が有効になっている必要があります。
  3. または内蔵のエンジンに戻してください：タスクトレイのメニューで「Use Docker Desktop for the engine (advanced)」のチェックを外します。チャット、ドキュメント、設定はどちらでも同じです。
  4. docker info
wsl --status

チャットとモデルの使用

10. 「Model ... not found in Ollama. Please ensure it is pulled」

考えられる原因：チャットが、インストールされていないモデルを要求しています（標準はqwen2.5:7b）。v2.0.1では、新しくインストールするたびにチャットがllama3.2:3bを要求していました（「Model 'llama3.2:3b' not found」）。v2.0.2は、アプリがダウンロードしたモデルを使います。

対処法：

  1. 最新バージョンに更新するか（「Settings → About StarkLLM → Check for updates」）、モデル選択（左下の「AI MODEL」）でインストール済みのモデルを選んでください。
  2. インストール済みのモデルを一覧表示し、足りないモデルをダウンロードしてください。
  3. ollama list
ollama pull qwen2.5:7b
11. 「Not enough free memory to run model ...」、「Error generating response: 500 Server Error ...」、または回答がいつまでも返ってこない

考えられる原因：モデルが空きメモリに収まらず、Ollamaが停止しました。7Bモデルには約5〜6 GBの空きメモリが必要です。メモリが足りないとWindows自体もとても遅くなります。v2.0.1以降、チャットはこのことをわかりやすい言葉で伝えます。v2.0.0では生の「500 Server Error」が表示されていました。

対処法：

  1. ブラウザー、ゲーム、その他の大きなプログラムを閉じてから、もう一度お試しください。
  2. たとえばqwen2.5:3b（約2 GB）のような小さいモデルにし、チャットで選択してください。
  3. Ollamaが何を読み込んでいるかを確認してください。
  4. ollama pull qwen2.5:3b
ollama ps
12. 「Ollama is offline.」（Ollamaがオフラインです）と表示される、またはチャットがまったく応答しない

考えられる原因：Ollamaが実行されていないか、セキュリティソフトがOllamaへの接続をブロックしています。StarkLLMは127.0.0.1:11434（Docker Desktopのエンジンではhost.docker.internal:11434）でOllamaに接続します。

対処法：

  1. Ollamaを起動し、PCから確認してください：
  2. curl http://localhost:11434/api/tags
  3. ファイアウォールやセキュリティソフトでOllamaを許可してください。
  4. その後、タスクトレイのメニューで「Reload Application」を選ぶか、StarkLLMを終了してもう一度起動してください。
13. 回答がとても遅い

考えられる原因：適したGPUがない場合、OllamaはCPUで計算します。また最初の回答ではモデルを読み込む必要があります（私たちのテストでは約20秒）。16コアのデスクトップPCでは、短い回答におよそ10〜40秒かかりました。ノートPCはさらに遅くなります。

対処法：

  1. 性能の低いPCでは小さいモデル（qwen2.5:3b）を使ってください。
  2. 短く具体的な質問をしてください。長い回答ほど時間がかかります。
  3. VRAM 8 GB以上の専用NVIDIA GPUがあれば、ずっと速くなります。v2.3以降、StarkLLMはOllamaに内蔵グラフィックス（AMD Radeon、Intel Arc/Iris）も使わせます。タスクトレイのメニューの「Use the integrated graphics for AI」（AIに内蔵グラフィックスを使う）でオフにできます。
  4. インデックス化にも時間がかかります。ドキュメントのテキストの断片がすべて埋め込みモデルに送られるためです。
14. 回答が空のまま、または「考え中」の点がいつまでも消えない（qwen3、deepseek-r1などの思考型モデル）

考えられる原因：思考型モデルは、まず非表示のテキストで考えます。v2.0.2までは、そのためにトークンの上限をすべて使ってしまい、回答を返さないことがありました。v2.0.3は思考の段階を省いた回答をOllamaに求め、空の回答はエラーとして表示されます。

対処法：

  1. 最新バージョンに更新してください（「Settings → About StarkLLM → Check for updates」）。
  2. モデルに先に考えさせたい場合：Windowsの環境変数OLLAMA_THINK=trueを設定し、Settingsで「Max Tokens」（最大トークン数）を増やして、StarkLLMを再起動してください。

ドキュメントと回答の品質

15. アシスタントがドキュメントを無視して一般的な知識で答える（または何かをでっち上げる）

考えられる原因：v2.0.0では、メッセージにdocumentやfileのような英語のきっかけとなる単語が含まれているときだけ、ドキュメントの検索が始まりました。v2.0.1以降は、質問のたびにワークスペースのドキュメントが検索されます。それでも起こる場合は、たいてい質問とドキュメントで使っている言葉や言語が違います。

対処法：

  1. 最新バージョンに更新してください（「Settings → About StarkLLM → Check for updates」）。
  2. ドキュメントの言語で、ドキュメントと同じ言葉を使って質問してください。
  3. 回答に出典のファイルが示されているか、必ず確認してください。出典のファイルがなければ、ドキュメントは使われていません。
16. ファイルがアップロードできない、またはステータスが「failed」（失敗）で終わる

考えられる原因：ファイルの種類に対応していないか、ファイルが空または壊れているか、100 MB（録音の場合は500 MB）より大きいためです。

対処法：

  1. 対応形式：ドキュメントはPDF、DOCX、XLSX、PPTX、EPUB、TXT、MD、CSV、JSON、XML、HTML、ログ、画像（PNG、JPG、WEBP、TIFF）で最大100 MB。録音はMP3、M4A、WAV、OGG、FLAC、MP4・MOV・MKV動画の音声などで最大500 MB。
  2. まずPCでそのファイルを開いてみてください。壊れたPDFはここでも失敗します。
  3. スキャンしたPDFや画像には文字認識（OCR）が必要で、時間がかかります。元のテキストファイルがあれば、そちらを使ってください。
  4. 名前を変えるだけの工夫（たとえば.exeを.txtにする）は役に立ちません。
17. CSV、Excel、JSONファイルが「indexed」と表示されるのに、中身がまったく見つからない（Wordファイル内の表も同様）

考えられる原因：これはv2.0.0の問題でした。これらのファイルは、インデックスに何も入っていないのにインデックス化済みと表示されていました。v2.0.1以降、CSV、XLSX、JSON、XML、ログ、Markdown、Wordファイル内の表はインデックス化されます（種類ごとにテストファイルで確認済み）。

対処法：

  1. 最新バージョンに更新し（「Settings → About StarkLLM → Check for updates」）、ファイルをもう一度アップロードしてください。
  2. 新しいファイルは、頼りにする前に、答えがわかっている質問でテストしてください。
18. 回答に「ドキュメントに見つかりません」とあるが、その情報はドキュメントに書かれている

考えられる原因：検索で選ばれるのは、ほんの数か所の箇所だけです。質問が別の言葉を使っている場合、質問がドキュメントとは別の言語の場合（ドイツ語の契約書について英語で質問すると見つからないことがよくあります）、または文や句読点のない長いファイル（機械のログなど）をインデックス化した場合に、情報を見逃すことがあります。

対処法：

  1. ドキュメントの言語で、ドキュメントに出てくる用語、数字、IDをそのまま使って質問してください。
  2. 質問をより具体的にしてください（ファイル名、章、型番を挙げる）。
  3. 長いログや表は、期間やテーマごとに小さなファイルに分けてください。
  4. 回答には出典のファイルが示されます。開いて確認してください。
19. 回答に、ドキュメントの古い版と新しい版が混ざっている

考えられる原因：ワークスペースにアップロードしたドキュメントは、すべてまとめて検索されます。日付や「差し替え済み」の注記がなければ、モデルはどの版が有効なのかを判断できません。

対処法：

  1. 古くなったドキュメントをワークスペースから削除するか、古い版を別のワークスペースに分けてください。
  2. 有効期間を本文に書いてください（「〜から有効」「〜により差し替え」）。
  3. はっきり指定して質問してください：「2026年の契約書によると〜」。
20. 名前、数字、よく似た部品番号が取り違えられる

考えられる原因：ローカルで動く7Bモデルは、よく似た値（たとえばFT-48とFT-480）を取り違えたり、計算を間違えたりすることがあります。私たち自身のテストでも、同じ質問に正しく答える回と間違える回がありました。

対処法：

  1. 重要なことについては、示された出典を開いて、数字をご自身で確認してください。
  2. 質問は1つずつ、正確な型番や部品番号を挙げてください。
  3. PCで実行できるなら、より大きなモデル（qwen2.5:14b、メモリ約10 GBが必要）のほうが信頼できます。
21. 要約で大事な点が抜ける、または英語とドイツ語以外の言語での回答が読みにくい

考えられる原因：小さなモデルは要約が大まかで、英語とドイツ語以外では弱くなります。日本語で質問することはでき、StarkLLMはモデルに質問と同じ言語で答えるよう指示します（結果は選んだローカルモデルによります）。ただしメニューとボタンは英語、ドイツ語、スペイン語、フランス語、イタリア語、トルコ語のいずれかです。

対処法：

  1. 必要な点を挙げてください：「契約期間、料金、解約の通知期間の3点で要約してください」。
  2. こうした作業には、より大きなモデルを使ってください。
  3. 質問はドキュメントの言語で書いてください。回答は質問の言語に合わせて書かれます。
22. ドキュメントに指示が書かれている（「これまでの指示をすべて無視して〜」）

考えられる原因：ドキュメント内のテキストが、モデルを操ろうとすることがあります（プロンプトインジェクション）。私たちのテストでは、モデルはそのような文を無視して本来の質問に答えましたが、保証はありません。

対処法：

  1. 信頼できるドキュメントだけをインデックス化してください。
  2. 出どころのわからないドキュメントから得た回答は、慎重に扱ってください。

アカウント、データ、削除

23. パスワードを忘れた

考えられる原因：ご自身のPCでは、StarkLLMはこのPCのユーザーとしてパスワードなしでサインインします（v2.0.7以降）。この問題は、パスワードのあるアカウントにだけ関係します。StarkLLMにはまだパスワードのリセット機能がありません（サインイン中の「Change Password」〔パスワードの変更〕だけです）。

対処法：

  1. 普段お使いのパスワードを試してください。
  2. 最後の手段として、新しいアカウントを登録してください。そのワークスペースは別になります。古いアカウントのデータは同じデータフォルダーに残りますが、開くことはできません。
24. データはどこにありますか？バックアップするには？

考えられる原因：すべてがお使いのPCの中にあります。

対処法：

  1. デスクトップアプリ：データベース、検索インデックス、アップロードしたファイルは%APPDATA%\StarkLLM\dataにあります。ナレッジベースのフォルダーはDocuments\StarkLLM Knowledge Base（ドキュメント\StarkLLM Knowledge Base）です。ソースコードから実行している場合：プロジェクトフォルダー内のdata\ とknowledge_base_data\ です。
  2. 設定にはバックアップと復元の機能があります。v2.0.1以降、使えるのは最初のアカウント（管理者）だけです。バックアップにはすべてのアカウントのデータが含まれるため、安全に保管してください。
  3. フォルダーを手でコピーする前に、StarkLLMを終了してください。
25. StarkLLMを停止またはアンインストールするには？

考えられる原因：StarkLLMとOllamaは別々のプログラムで、それぞれ個別に削除します。

対処法：

  1. 停止：タスクトレイのメニューで「Quit StarkLLM」（StarkLLMを終了）を選びます。エンジンも一緒に停止します。Ollamaは、そのアイコンから終了するまで、自分のタスクトレイのアイコンで動き続けます。
  2. プログラムの削除：Windowsの「設定 >アプリ > StarkLLM」。%APPDATA%\StarkLLM\dataにあるデータは、そのフォルダーをご自身で削除するまで残ります。
  3. ディスクの空き容量を増やす：ollama rm <名前>でモデルを削除できます。2.2より前にDocker Desktopのエンジンを使っていた場合は、docker image prune -aで古いイメージを削除できます。
  4. ollama list
ollama rm qwen2.5:7b

ウェブタスク、ターミナル、スマートフォン

26. スマートフォンがPCとペアリングできない、または接続できない

考えられる原因：スマートフォンとの接続がオフになっている、スマートフォンが同じ自宅のネットワークになく外出先での接続も許可されていない、またはWindowsファイアウォールがStarkLLMをブロックしています。「Also away from home (through the relay)」（外出先でも〔リレー経由〕）がオフの場合、スマートフォンがPCに接続できるのは自宅のネットワークだけです。

対処法：

  1. PCで「Settings › Phone」（設定 › スマートフォン）を開き、接続をオンにしてQRコードを表示します。5分以内にStarkLLMアプリで読み取ってください（コードは1回だけ使えます）。
  2. ペアリングは自宅でだけ行えます。スマートフォンとPCは同じ自宅のネットワーク（Wi-Fi）にある必要があります。
  3. モバイルデータや別のWi-FiからスマートフォンがPCに接続できるのは、「Settings › Phone」でそのスマートフォンについて「Also away from home (through the relay)」がオンで、PCの電源が入っていてStarkLLMが実行中の場合だけです。そのときスマートフォンには「Connected · away from home」（接続済み・外出先）と表示されます。
  4. StarkLLMにネットワークからの接続を許可するかをWindowsが尋ねてきたら、プライベートネットワークだけを許可してください。StarkLLMがファイアウォールを自分で変更することはありません。
  5. 「Fully offline」（完全オフライン）にすると接続は閉じられます。スマートフォンを使うにはオフにしてください。
  6. 接続の試みはすべて「Settings › Privacy & network」（設定 › プライバシーとネットワーク）に記録されます。
27. ウェブタスクやターミナルのタスクが早く止まる、またはあまり進まない

考えられる原因：ウェブタスクとターミナルには、複数の手順を計画できるモデルが必要です。小さな7Bモデルは安全に止まりますが、こなせるタスクは多くありません。

対処法：

  1. PCのメモリが十分にあれば、こうしたタスクには14B以上のローカルモデル（たとえばqwen3:14b）を選んでください。
  2. タスクは1〜2文ではっきり説明し、ウェブサイト名やファイル名を挙げてください。
  3. サインイン、支払い、「ロボットではありません」の確認は、常にお客様ご自身が行います。StarkLLMのウィンドウで済ませてから、「Continue」（続行）を押してください。
  4. ollama list
ollama pull qwen3:14b

v2.6.0 の既知の制限

包み隠さずお伝えします：

初回起動に時間がかかる
約5 GBのAIモデルをダウンロードします（インターネット接続が必要）。エンジンはインストーラーに含まれています。Ollamaは、StarkLLMまたはご自身で一度インストールします。
回答が間違っていることがある
標準の7Bモデルは、よく似た値を取り違えたり、計算を間違えたり、情報を見逃したりすることがあります。重要な判断の際は、必ず示された出典を確認してください。
ドキュメントと別の言語での質問
埋め込みモデルは英語で最も強いため、ドイツ語のドキュメントについて英語で質問すると、答えが得られないことがよくあります。ドキュメントの言語で質問してください。
最初の画像で画像モデルをダウンロードする
最初のPNGやJPG（またはスキャンしたPDFのページ）を追加すると、StarkLLMは画像モデルllava（約4.4 GB）を一度だけダウンロードします。それが終わるまで、ドキュメントには「Embedding」と表示されます。
句読点のない長いファイル
ログなどのファイルは非常に大きな断片としてインデックス化されることがあり、その中の個々の値は見つけにくくなります。
古い版と新しい版
本文に書かれていない限り、アシスタントはどの版のドキュメントが有効なのかを知りません。
すべてのWindows PCで試したわけではない
すべてのWindows PCで試すことはできませんでした。お使いのPCである手順が失敗した場合は、info@starkllm.comまでお知らせください。
バックグラウンドのサービス
StarkLLMを終了すると、そのエンジンも停止します。Ollamaは、終了するまで自分のタスクトレイのアイコンで動き続けます。Docker Desktopのエンジン（上級者向け）を使っている場合は、ウィンドウを閉じた後もエンジンがDockerで動き続けます。
チャットでのコードの実行
Pythonのコードブロックの「Run」（実行）は、StarkLLMが独自のサンドボックスを持つまで、内蔵のエンジンではオフです。Docker Desktopのエンジン（上級者向け）では、これまでどおり動作します。
1つのインストールにつき管理者は1人
最初のアカウントは、ほかのアカウントのドキュメントも含めて、データベース全体をバックアップできます。インストールを共有するのは、信頼できる人とだけにしてください。
パスワードのリセットがない
問題23をご覧ください。
速度
CPUだけのPCは遅くなります。問題13をご覧ください。
ウェブタスクとターミナルには大きめのモデルが必要
14B以上のローカルモデル（たとえばqwen3:14b）で最もよく動作します。小さな7Bモデルは安全に止まりますが、こなせるタスクは多くありません。問題27をご覧ください。
スマートフォンアプリはプレビュー版
Androidアプリはテスト段階としてGoogle Playで提供されています。Google Playから入手したい場合は、メールアドレスをinfo@starkllm.comまでお送りください。Google Playへのリンクをお送りします。自宅のネットワークで動作し、許可したスマートフォンに限り、外出先でもStarkLLMリレー経由で動作します（スマートフォンからPCまで暗号化）。問題26をご覧ください。
最初の録音で音声モデルをダウンロードする
最初に録音を追加すると、Whisper large-v3-turbo（約1.6 GB）を一度だけダウンロードします。完全オフラインのときは、小さいほうの音声入力モデルが使われます。
ターミナルのコマンドはネットワークの一覧に表示されない
ターミナルで許可したコマンド（たとえばnpm installやgit push）と、追加したツールサーバーは、お客様ご自身のプログラムとして実行されます。それらの接続は「Settings › Privacy & network」には表示されません。StarkLLMが完全オフラインの間は、インターネットを使うコマンドは拒否されます。

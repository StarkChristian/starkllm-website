Hilfe

Hilfe & Problemlösung

Wenn StarkLLM nicht startet oder eine Antwort falsch aussieht, beginnen Sie hier. Jeder Schritt hat einen Test, damit Sie sehen, welcher Teil fehlt.

Springe zu: Checkliste · Probleme · Hilfe holen · Grenzen

Wie die Teile zusammenspielen

StarkLLM ist nicht ein einzelnes Programm. Zwei Teile arbeiten zusammen, und die Desktop-App startet den anderen für Sie:

Die StarkLLM-App (StarkLLM.exe)

Enthält die Engine (Datenbank, Suchindex, Backend und Weboberfläche) und führt sie seit v2.2 direkt unter Windows aus: ohne Docker Desktop, ohne WSL2. Bei jedem Start prüft sie Ollama, lädt fehlende Modelle, startet die Engine und zeigt dann StarkLLM. Fehlt ein Teil, sagt sie, welcher es ist und wie Sie ihn beheben. Wenn Sie StarkLLM beenden, stoppt auch die Engine.

Ollama

Führt das Sprachmodell und das Embedding-Modell auf Ihrem eigenen PC aus. Ihre Dokumente und Fragen bleiben auf Ihrem PC; Ollama selbst geht nur für Modell-Downloads und seine eigene Update-Prüfung online. Fehlt Ollama, bietet StarkLLM „Ollama für mich installieren“ an und installiert die offizielle, signierte Version; danach startet es Ollama und lädt die Modelle.

Docker Desktop (optional, für Fortgeschrittene)

Seit v2.2 nicht mehr nötig. Wer es vorzieht, wählt im Menü des Infobereichs „Docker Desktop für die Engine verwenden (für Fortgeschrittene)“; StarkLLM führt seine Engine dann in Docker Desktop aus, mit denselben Daten.

Aus dem Quellcode (optional)

Entwickler können die Engine aus dem Quellcode auf GitHub mit docker compose up --build -d bauen und starten.

Versionen vor 2.2 brauchten Docker Desktop und WSL2, und v2.0.0 (vor dem 24. Oktober 2026) startete gar nichts. Bitte installieren Sie v2.5.0.

Ehrlicher Hinweis: Die Schritte stammen aus den Prüfungen, die die App bei jedem Start ausführt, und aus echten Testläufen. Wir konnten nicht jeden Windows-PC testen. Weicht etwas von dem ab, was Sie sehen, schreiben Sie uns an info@starkllm.com, dann korrigieren wir diese Seite.

  2. 2. StarkLLM installieren und startenLaden Sie StarkLLM-v2.5.0-Setup.exe von der Download-Seite, installieren Sie es und starten Sie StarkLLM. Die Engine ist Teil des Installers.Test: Das StarkLLM-Fenster öffnet sich und zeigt den Fortschritt des Starts. Zeigt es „StarkLLM konnte nicht gestartet werden“, nennt es, was fehlt, und bietet „Erneut versuchen“ an.
  3. 3. OllamaFehlt Ollama, bietet das Fenster „Ollama für mich installieren“ an: StarkLLM lädt den offiziellen Installer von ollama.com (etwa 2 GB), prüft seine Signatur und installiert ihn; Administratorrechte sind nicht nötig. Sie können Ollama auch selbst von ollama.com installieren.

    ollama list
    Test: ollama list zeigt ein Chatmodell und ein Embedding-Modell. Ist ein Download gescheitert, nennt das Fenster das Modell: Führen Sie ollama pull mit diesem Namen aus und klicken Sie auf „Erneut versuchen“. Wenig Speicher (PC mit 8 GB)? Nehmen Sie qwen2.5:3b und wählen es im Chat aus.

Stellen Sie danach eine Frage dazu und prüfen Sie, dass die Antwort die Datei nennt.

Probleme und was zu tun ist

Klicken Sie auf ein Problem, um die wahrscheinliche Ursache und die Lösung zu sehen. Die Reihenfolge entspricht dem, was Nutzern meist als Erstes begegnet.

Installieren und Starten

1. Windows meldet „Der Computer wurde durch Windows geschützt“ (SmartScreen) oder Smart App Control blockiert den Installer

Wahrscheinliche Ursache: Seit v2.1.2 sind Installer, StarkLLM.exe und Deinstallationsprogramm von „Open Source Developer Christian Stark“ signiert, damit Windows den Herausgeber überprüfen kann. Windows kann trotzdem vor einer Datei warnen, die es noch selten gesehen hat. Versionen vor v2.1.2 hatten noch keine Signatur.

Was zu tun ist:

  1. Prüfen Sie den Herausgeber: Rechtsklick auf den Installer, „Eigenschaften“, Registerkarte „Digitale Signaturen“. Als Signaturgeber muss „Open Source Developer Christian Stark“ stehen, und unter „Details“ muss „Diese digitale Signatur ist gültig.“ stehen.
  2. Vergleichen Sie den SHA-256-Hash mit dem auf der Download-Seite.
  3. Stimmen beide, fahren Sie fort (bei SmartScreen: „Weitere Informationen“, dann „Trotzdem ausführen“). Wenn nicht, führen Sie die Datei nicht aus: Laden Sie sie erneut herunter und schreiben Sie uns an info@starkllm.com.
  4. Schalten Sie Smart App Control, SmartScreen und andere Sicherheitseinstellungen nicht ab. Blockiert Smart App Control einen korrekt signierten Installer, schreiben Sie uns an info@starkllm.com.
2. Smart App Control oder eine Sicherheitssoftware blockiert eine Programmdatei der Engine

Wahrscheinliche Ursache: Seit v2.2.1 ist jede Programmdatei der Engine (Python-Pakete, Tesseract) von „Open Source Developer Christian Stark“ signiert, damit Smart App Control sie ausführen lässt. Eine andere Regel zur Anwendungssteuerung oder eine Sicherheitssoftware kann trotzdem eine Datei blockieren; dann startet die Engine nicht.

Was zu tun ist:

  1. Die Startseite nennt die blockierte Datei und das Engine-Protokoll (%APPDATA%\StarkLLM\engine-native.log).
  2. Schalten Sie Smart App Control und Ihre Sicherheitssoftware nicht ab. Melden Sie den Dateinamen auf der StarkLLM-Seite bei GitHub oder an info@starkllm.com.
  3. Bis zur Lösung können Sie im Menü des Infobereichs „Docker Desktop für die Engine verwenden (für Fortgeschrittene)“ wählen (braucht Docker Desktop mit WSL2).
3. „Ollama ist nicht installiert“ oder „Ollama läuft nicht“

Wahrscheinliche Ursache: StarkLLM führt seine KI-Modelle mit Ollama (kostenlos) aus und erwartet es unter 127.0.0.1:11434.

Was zu tun ist:

  1. Klicken Sie auf der Startseite auf „Ollama für mich installieren“, oder installieren Sie Ollama selbst von ollama.com.
  2. Ist Ollama installiert: Starten Sie es über das Startmenü, warten Sie auf sein Symbol im Infobereich und klicken Sie auf „Erneut versuchen“.
  3. Prüfen Sie es vom PC aus:
  4. curl http://localhost:11434/api/tags
4. „pull model manifest: file does not exist“, „model not found“ oder der PC friert ein, weil das Modell viel zu groß ist

Wahrscheinliche Ursache: Den Modellnamen gibt es in Ollama nicht, oder das gewählte Modell braucht viel mehr Speicher, als der PC hat (ein 27B-Modell braucht etwa 17 GB freien Speicher). Alte Kopien von start-here.txt und .env.example nannten qwen3.8:27b und qwen3-embedding:0.6b.

Was zu tun ist:

  1. Nehmen Sie die Modelle der Standardeinrichtung:
  2. ollama pull qwen2.5:7b
ollama pull nomic-embed-text
  3. Oder wählen Sie in der Modellauswahl (KI-Modell unten links) ein installiertes Modell.
  4. Mit einem anderen Embedding-Modell indexierte Dokumente müssen erneut hochgeladen werden (die Vektoren haben eine andere Größe).
5. „Another StarkLLM engine already uses port 5173“, oder die Engine startet nicht, weil der Port belegt ist

Wahrscheinliche Ursache: Die Engine stellt die App auf Port 5173 Ihres PCs (127.0.0.1) bereit. Ein anderes Programm oder die StarkLLM-Container einer früheren Installation mit Docker Desktop belegen ihn schon. Seine eigenen alten Container stoppt StarkLLM selbst; andere Programme kann es nicht beenden.

Was zu tun ist:

  1. Finden Sie das Programm und beenden Sie es:
  2. netstat -ano | findstr :5173
tasklist /FI "PID eq <Zahl aus der letzten Spalte>"
  3. Oder verlegen Sie StarkLLM auf einen anderen Port: Führen Sie setx STARKLLM_UI_PORT 5174 aus, beenden Sie StarkLLM im Menü des Infobereichs und starten Sie es neu.
6. Der erste Start dauert sehr lange oder ein Download scheitert

Wahrscheinliche Ursache: Der erste Start lädt die KI-Modelle (etwa 5 GB) und, wenn Sie es erlauben, Ollama (etwa 2 GB). Langsames Internet, ein Firmen-Proxy, ein VPN, Virenscanner oder eine fast volle Platte machen es langsamer oder brechen es ab.

Was zu tun ist:

  1. Halten Sie mindestens 15 GB freien Speicherplatz bereit (Modelle etwa 5 GB, dazu Ollama, die App und die Engine).
  2. Das Fenster zeigt den Fortschritt jedes Downloads. TLS- oder Verbindungsfehler deuten auf ein blockiertes Netz; probieren Sie ein anderes.
  3. Klicken Sie nach der Behebung auf „Erneut versuchen“; bereits geladene Modelle werden nicht noch einmal geladen.
7. Das Fenster zeigt „StarkLLM konnte nicht gestartet werden“

Wahrscheinliche Ursache: Die App startet Ollama und ihre Engine selbst und zeigt diese Seite, wenn ein Schritt scheitert.

Was zu tun ist:

  1. Lesen Sie die rote Zeile: Sie nennt den fehlenden Teil (Ollama, ein belegter Port, eine von Windows blockierte Programmdatei oder ein Engine-Fehler mit den letzten Protokollzeilen).
  2. Beheben Sie diesen Teil und klicken Sie auf „Erneut versuchen“. Die Protokolle liegen in %APPDATA%\StarkLLM: engine.log (die App) und engine-native.log (die Engine).
  3. Der erste Start nach einer Installation oder einem Update kann auf einem ausgelasteten PC einige Minuten dauern; das Fenster sagt das, während es wartet.
8. Das Fenster bleibt nach dem Start leer oder zeigt eine Fehlerseite

Wahrscheinliche Ursache: Die Engine startet noch oder wurde beendet.

Was zu tun ist:

  1. Warten Sie ein bis zwei Minuten und wählen Sie dann im Menü des Infobereichs „Anwendung neu laden“.
  2. Bleibt es leer, beenden Sie StarkLLM im Menü des Infobereichs und starten Sie es neu.
  3. Der Fehler steht meist in den letzten 20 Zeilen des Engine-Protokolls (in PowerShell öffnen):
  4. notepad "$env:APPDATA\StarkLLM\engine-native.log"
9. Ich nutze Docker Desktop für die Engine (für Fortgeschrittene), und sie startet nicht

Wahrscheinliche Ursache: Mit „Docker Desktop für die Engine verwenden (für Fortgeschrittene)“ im Menü des Infobereichs braucht StarkLLM Docker Desktop mit WSL2, wie die Versionen vor 2.2. Meldungen wie „error during connect ... dockerDesktopLinuxEngine“ oder „WSL 2 installation is incomplete“ kommen von Docker Desktop.

Was zu tun ist:

  1. Starten Sie Docker Desktop und warten Sie, bis seine Engine läuft; docker info muss einen Abschnitt „Server:“ zeigen.
  2. Fehlt WSL2, führen Sie wsl --install in einem Administrator-Terminal aus und starten neu; die Virtualisierung muss im BIOS/UEFI eingeschaltet sein.
  3. Oder wechseln Sie zurück zur eingebauten Engine: Entfernen Sie im Menü des Infobereichs den Haken bei „Docker Desktop für die Engine verwenden (für Fortgeschrittene)“. Chats, Dokumente und Einstellungen sind in beiden dieselben.
  4. docker info
wsl --status

Chat und Modelle

10. „Model ... not found in Ollama. Please ensure it is pulled“

Wahrscheinliche Ursache: Der Chat verlangt ein Modell, das nicht installiert ist (Standard ist qwen2.5:7b). In v2.0.1 verlangte der Chat bei jeder neuen Installation llama3.2:3b („Model 'llama3.2:3b' not found“); v2.0.2 nutzt das Modell, das die App lädt.

Was zu tun ist:

  1. Aktualisieren Sie auf die neueste Version (Einstellungen → Über StarkLLM → Nach Updates suchen) oder wählen Sie in der Modellauswahl (KI-Modell unten links) ein installiertes Modell.
  2. Listen Sie die installierten Modelle auf und laden Sie das fehlende.
  3. ollama list
ollama pull qwen2.5:7b
11. „Not enough free memory to run model ...“, „Error generating response: 500 Server Error ...“ oder die Antwort kommt nie

Wahrscheinliche Ursache: Das Modell passte nicht in den freien Speicher und Ollama hat es gestoppt. Ein 7B-Modell braucht etwa 5 bis 6 GB freien RAM; bei zu wenig Speicher wird auch Windows sehr langsam. Seit v2.0.1 sagt der Chat das in klaren Worten; v2.0.0 zeigte den rohen „500 Server Error“.

Was zu tun ist:

  1. Schließen Sie Browser, Spiele und andere große Programme und versuchen Sie es erneut.
  2. Wählen Sie ein kleineres Modell, zum Beispiel qwen2.5:3b (etwa 2 GB), und wählen Sie es im Chat aus.
  3. Prüfen Sie, was Ollama geladen hat.
  4. ollama pull qwen2.5:3b
ollama ps
12. „Cannot connect to Ollama“ oder der Chat antwortet gar nicht

Wahrscheinliche Ursache: Ollama läuft nicht, oder eine Sicherheitssoftware blockiert die Verbindung dorthin. StarkLLM erreicht Ollama unter 127.0.0.1:11434 (mit der Docker-Desktop-Engine: host.docker.internal:11434).

Was zu tun ist:

  1. Starten Sie Ollama und prüfen Sie es vom PC aus:
  2. curl http://localhost:11434/api/tags
  3. Erlauben Sie Ollama in Firewall und Sicherheitssoftware.
  4. Wählen Sie danach im Menü des Infobereichs „Anwendung neu laden“, oder beenden Sie StarkLLM und starten Sie es neu.
13. Die Antworten sind sehr langsam

Wahrscheinliche Ursache: Ohne passende GPU rechnet Ollama auf der CPU. Die erste Antwort muss außerdem das Modell laden (in unserem Test etwa 20 Sekunden). Auf einem 16-Kern-Desktop dauerte eine kurze Antwort ungefähr 10 bis 40 Sekunden; Laptops sind langsamer.

Was zu tun ist:

  1. Nehmen Sie auf schwachen PCs ein kleineres Modell (qwen2.5:3b).
  2. Stellen Sie kurze, konkrete Fragen; lange Antworten kosten am meisten Zeit.
  3. Eine dedizierte NVIDIA-GPU mit 8 GB oder mehr VRAM macht es deutlich schneller. Seit v2.3 lässt StarkLLM Ollama auch integrierte Grafik nutzen (AMD Radeon, Intel Arc/Iris); „Integrierte Grafik für KI verwenden“ im Menü des Infobereichs schaltet das ab.
  4. Auch das Indexieren ist langsam: Jedes Textstück eines Dokuments geht an das Embedding-Modell.
14. Die Antwort bleibt leer oder die „Denk“-Punkte hören nicht auf (qwen3, deepseek-r1 und andere Denkmodelle)

Wahrscheinliche Ursache: Denkmodelle denken zuerst in verborgenem Text. Bis v2.0.2 konnten sie dafür das ganze Token-Limit verbrauchen und gaben keine Antwort. v2.0.3 fordert die Antwort bei Ollama ohne den Denkschritt an, und eine leere Antwort wird als Fehler angezeigt.

Was zu tun ist:

  1. Auf die neueste Version aktualisieren (Einstellungen → Über StarkLLM → Nach Updates suchen).
  2. Wenn das Modell zuerst denken soll: die Windows-Umgebungsvariable OLLAMA_THINK=true setzen, „Maximale Tokens“ in den Einstellungen erhöhen und StarkLLM neu starten.

Dokumente und Antwortqualität

15. Der Assistent ignoriert meine Dokumente und antwortet aus Allgemeinwissen (oder erfindet etwas)

Wahrscheinliche Ursache: In v2.0.0 startete die Dokumentsuche nur, wenn die Nachricht ein englisches Auslösewort wie document oder file enthielt. Seit v2.0.1 werden die Dokumente des Workspaces bei jeder Frage durchsucht. Passiert es trotzdem, verwenden Frage und Dokument meist andere Wörter oder Sprachen.

Was zu tun ist:

  1. Aktualisieren Sie auf die neueste Version (Einstellungen → Über StarkLLM → Nach Updates suchen).
  2. Fragen Sie in der Sprache des Dokuments und mit den Wörtern des Dokuments.
  3. Prüfen Sie immer, ob die Antwort eine Quelldatei nennt. Keine Quelldatei heißt, dass Ihre Dokumente nicht genutzt wurden.
16. Eine Datei lässt sich nicht hochladen oder endet mit dem Status „Fehlgeschlagen“

Wahrscheinliche Ursache: Der Dateityp wird nicht unterstützt, die Datei ist leer oder beschädigt, oder sie ist größer als 100 MB (bei einer Aufnahme 500 MB).

Was zu tun ist:

  1. Unterstützt: Dokumente PDF, DOCX, XLSX, PPTX, EPUB, TXT, MD, CSV, JSON, XML, HTML, Logs und Bilder (PNG, JPG, WEBP, TIFF) bis 100 MB; Aufnahmen MP3, M4A, WAV, OGG, FLAC, der Ton von MP4-, MOV- und MKV-Videos und mehr bis 500 MB.
  2. Öffnen Sie die Datei zuerst auf Ihrem PC; eine beschädigte PDF scheitert auch hier.
  3. Gescannte PDFs und Bilder brauchen Texterkennung (OCR) und sind langsamer; nehmen Sie lieber die Originaltextdatei, wenn Sie sie haben.
  4. Das bloße Umbenennen (zum Beispiel .exe in .txt) hilft nicht.
17. Eine CSV-, Excel- oder JSON-Datei steht auf „Indexiert“, aber nichts darin wird je gefunden (auch Tabellen in Word-Dateien)

Wahrscheinliche Ursache: Das war ein Problem von v2.0.0: Diese Dateien galten als indexiert, obwohl nichts im Index lag. Seit v2.0.1 werden CSV, XLSX, JSON, XML, Logs, Markdown und Tabellen in Word-Dateien indexiert (mit je einer Testdatei geprüft).

Was zu tun ist:

  1. Aktualisieren Sie auf die neueste Version (Einstellungen → Über StarkLLM → Nach Updates suchen) und laden Sie die Datei erneut hoch.
  2. Testen Sie jede neue Datei mit einer Frage, deren Antwort Sie kennen, bevor Sie sich darauf verlassen.
18. Die Antwort sagt „nicht in den Dokumenten gefunden“, obwohl die Angabe im Dokument steht

Wahrscheinliche Ursache: Die Suche liefert nur wenige Textstellen. Sie kann eine Angabe verpassen, wenn die Frage andere Wörter benutzt, wenn die Frage in einer anderen Sprache als das Dokument gestellt ist (eine englische Frage zu einem deutschen Vertrag wird oft nicht gefunden) oder wenn eine lange Datei ohne Sätze und Satzzeichen (etwa ein Maschinenlog) indexiert wurde.

Was zu tun ist:

  1. Fragen Sie in der Sprache des Dokuments und mit dem genauen Begriff, der Zahl oder der ID, die darin vorkommt.
  2. Formulieren Sie konkreter (Datei, Abschnitt oder Modellnummer nennen).
  3. Teilen Sie lange Logs oder Tabellen in kleinere Dateien nach Zeitraum oder Thema.
  4. Die Antwort nennt ihre Quelldatei; öffnen Sie sie und prüfen Sie nach.
19. Die Antwort vermischt eine alte und eine neue Version eines Dokuments

Wahrscheinliche Ursache: Alle hochgeladenen Dokumente eines Workspaces werden gemeinsam durchsucht. Ohne Datum oder „ersetzt“-Hinweis kann das Modell nicht wissen, welche Version gilt.

Was zu tun ist:

  1. Löschen Sie veraltete Dokumente aus dem Workspace oder halten Sie alte Versionen in einem eigenen Workspace.
  2. Schreiben Sie die Gültigkeit in den Text („gültig ab ...“, „ersetzt durch ...“).
  3. Fragen Sie ausdrücklich: „Laut Vertrag 2026 ...“.
20. Namen, Zahlen oder ähnliche Teilenummern werden verwechselt

Wahrscheinliche Ursache: Ein lokal laufendes 7B-Modell kann ähnliche Werte verwechseln (etwa FT-48 und FT-480) oder falsch rechnen. In unseren eigenen Tests wurde dieselbe Frage in manchen Läufen richtig und in anderen falsch beantwortet.

Was zu tun ist:

  1. Öffnen Sie bei wichtigen Dingen die genannte Quelle und prüfen Sie die Zahl selbst.
  2. Stellen Sie eine Frage nach der anderen und nennen Sie das genaue Modell oder die Teilenummer.
  3. Ein größeres Modell (qwen2.5:14b, braucht etwa 10 GB RAM) ist zuverlässiger, wenn Ihr PC es verträgt.
21. Zusammenfassungen lassen Wichtiges weg, oder Antworten in anderen Sprachen als Englisch und Deutsch lesen sich schlecht

Wahrscheinliche Ursache: Kleine Modelle fassen ungenau zusammen und sind außerhalb von Englisch und Deutsch schwächer.

Was zu tun ist:

  1. Nennen Sie die gewünschten Punkte: „Fasse in drei Punkten zusammen: Laufzeit, Preis, Kündigungsfrist“.
  2. Nehmen Sie für solche Aufgaben ein größeres Modell.
  3. Schreiben Sie die Frage in der Sprache des Dokuments; die Antwort folgt der Sprache Ihrer Frage.
22. Ein Dokument enthält Anweisungen („ignoriere alle bisherigen Anweisungen ...“)

Wahrscheinliche Ursache: Text in Dokumenten kann versuchen, das Modell zu lenken (Prompt-Injection). In unserem Test ignorierte das Modell einen solchen Satz und beantwortete die eigentliche Frage, eine Garantie gibt es aber nicht.

Was zu tun ist:

  1. Indexieren Sie nur Dokumente, denen Sie vertrauen.
  2. Gehen Sie mit Antworten aus Dokumenten unbekannter Herkunft vorsichtig um.

Konto, Daten und Entfernen

23. Ich habe mein Passwort vergessen

Wahrscheinliche Ursache: Auf Ihrem eigenen PC meldet StarkLLM Sie seit v2.0.7 ohne Passwort als Benutzer dieses PCs an; dieses Problem betrifft nur Konten mit Passwort. StarkLLM hat noch keine Passwort-Zurücksetzung (nur „Passwort ändern“ im angemeldeten Zustand).

Was zu tun ist:

  1. Probieren Sie Ihre üblichen Passwörter.
  2. Als letzten Ausweg registrieren Sie ein neues Konto. Dessen Workspaces sind getrennt: Das alte Konto behält seine Daten im selben Datenordner, Sie können es aber nicht öffnen.
24. Wo liegen meine Daten? Wie sichere ich sie?

Wahrscheinliche Ursache: Alles bleibt auf Ihrem PC.

Was zu tun ist:

  1. Desktop-App: Datenbank, Suchindex und hochgeladene Dateien liegen in %APPDATA%\StarkLLM\data; Ihr Ordner für die Wissensdatenbank ist Dokumente\StarkLLM Knowledge Base. Aus dem Quellcode: data\ und knowledge_base_data\ im Projektordner.
  2. In den Einstellungen gibt es „Sicherung und Wiederherstellung“. Seit v2.0.1 kann nur das erste Konto (der Administrator) sie nutzen; ein Backup enthält die Daten aller Konten, bewahren Sie es sicher auf.
  3. Beenden Sie StarkLLM, bevor Sie die Ordner von Hand kopieren.
25. Wie stoppe oder deinstalliere ich StarkLLM?

Wahrscheinliche Ursache: StarkLLM und Ollama sind getrennte Programme, die jeweils für sich entfernt werden.

Was zu tun ist:

  1. Stoppen: Wählen Sie im Menü des Infobereichs „StarkLLM beenden“; die Engine stoppt mit. Ollama läuft mit seinem eigenen Symbol im Infobereich weiter, bis Sie es dort beenden.
  2. Programm entfernen: Windows-Einstellungen > Apps > StarkLLM. Ihre Daten in %APPDATA%\StarkLLM\data bleiben, bis Sie diesen Ordner selbst löschen.
  3. Speicher freigeben: ollama rm <Name> entfernt ein Modell. Haben Sie vor 2.2 die Docker-Desktop-Engine genutzt, entfernt docker image prune -a deren alte Images.
  4. ollama list
ollama rm qwen2.5:7b

Web-Aufgaben, Terminal und Handy

26. Das Handy lässt sich nicht koppeln oder verbindet sich nicht mit dem PC

Wahrscheinliche Ursache: Die Telefon-Verbindung ist aus, das Handy ist nicht im selben Heimnetz, oder die Windows-Firewall blockiert StarkLLM. Das Handy erreicht den PC nur im Heimnetz (Vorschau); die Nutzung außerhalb des Heimnetzes gehört nicht zu dieser Version.

Was zu tun ist:

  1. Öffnen Sie am PC Einstellungen › Telefon, schalten Sie die Verbindung ein und lassen Sie den QR-Code anzeigen; scannen Sie ihn innerhalb von 5 Minuten mit der StarkLLM-App (ein Code gilt nur einmal).
  2. Handy und PC müssen im selben Heimnetz (WLAN) sein; über mobile Daten erreicht das Handy den PC nicht.
  3. Fragt Windows, ob StarkLLM in Netzwerken erreichbar sein darf, erlauben Sie nur private Netzwerke. StarkLLM ändert die Firewall nie selbst.
  4. „Vollständig offline“ schließt die Verbindung; schalten Sie es aus, um das Handy zu nutzen.
  5. Jeder Verbindungsversuch steht in Einstellungen › Datenschutz & Netzwerk.
27. Eine Web-Aufgabe oder eine Terminal-Aufgabe hält früh an oder schafft wenig

Wahrscheinliche Ursache: Web-Aufgaben und das Terminal brauchen ein Modell, das mehrere Schritte planen kann. Kleine 7B-Modelle halten sicher an, schaffen aber nur wenige Aufgaben.

Was zu tun ist:

  1. Wählen Sie für diese Aufgaben ein lokales Modell ab 14B, zum Beispiel qwen3:14b, wenn Ihr PC genug Speicher hat.
  2. Beschreiben Sie die Aufgabe in ein oder zwei klaren Sätzen und nennen Sie die Website oder die Datei.
  3. Anmeldungen, Zahlungen und „Sind Sie ein Roboter?“-Prüfungen bleiben immer bei Ihnen: Erledigen Sie sie im StarkLLM-Fenster und drücken Sie dann auf Weiter.
  4. ollama list
ollama pull qwen3:14b

Kommen Sie nicht weiter? Schicken Sie uns das

Führen Sie diese Befehle in PowerShell aus und senden Sie die Ausgabe mit einer kurzen Beschreibung, was Sie getan und gesehen haben. Der letzte Befehl zeigt das Ende des Engine-Protokolls. Entfernen Sie vorher alles Private.

winver
ollama --version
ollama list
ollama ps
Get-Content "$env:APPDATA\StarkLLM\engine-native.log" -Tail 100

Schreiben Sie an info@starkllm.com oder eröffnen Sie ein Issue auf GitHub. Nennen Sie bitte Ihre Windows-Version, die RAM-Größe und ob Sie eine NVIDIA-GPU haben.

Bekannte Grenzen von v2.5.0

Das sagen wir lieber offen:

  • Der erste Start dauert lange: Etwa 5 GB KI-Modelle werden geladen (Internet nötig); die Engine kommt mit dem Installer. Ollama wird einmal installiert, von StarkLLM oder von Ihnen.
  • Antworten können falsch sein: Das 7B-Standardmodell kann ähnliche Werte verwechseln, falsch rechnen oder eine Angabe übersehen. Prüfen Sie bei wichtigen Entscheidungen immer die genannte Quelle.
  • Fragen in einer anderen Sprache als das Dokument: Eine englische Frage zu einem deutschen Dokument wird oft nicht beantwortet, weil das Embedding-Modell auf Englisch am stärksten ist. Fragen Sie in der Dokumentsprache.
  • Das erste Bild lädt das Bildmodell: Beim ersten PNG oder JPG (oder einer gescannten PDF-Seite) lädt StarkLLM einmalig das Bildmodell llava herunter (etwa 4,4 GB). Bis dahin zeigt das Dokument „Wird indexiert“.
  • Lange Dateien ohne Satzzeichen: Logs und ähnliche Dateien können als sehr große Stücke indexiert werden, sodass einzelne Werte darin schwer zu finden sind.
  • Alte und neue Versionen: Der Assistent weiß nicht, welche Dokumentversion gilt, solange der Text es nicht sagt.
  • Nicht auf jedem Windows-PC getestet: Wir konnten nicht jeden Windows-PC testen; schreiben Sie uns an info@starkllm.com, wenn ein Schritt auf Ihrem PC scheitert.
  • Dienste im Hintergrund: Wenn Sie StarkLLM beenden, stoppt auch seine Engine. Ollama läuft mit seinem eigenen Symbol im Infobereich weiter, bis Sie es beenden. Mit der Docker-Desktop-Engine (für Fortgeschrittene) läuft die Engine nach dem Schließen des Fensters in Docker weiter.
  • Code im Chat ausführen: „Ausführen“ bei Python-Codeblöcken ist in der eingebauten Engine aus, bis StarkLLM eine eigene Sandbox hat; mit der Docker-Desktop-Engine (für Fortgeschrittene) funktioniert es wie bisher.
  • Ein Administrator pro Installation: Das erste Konto kann die ganze Datenbank sichern, auch die Dokumente anderer Konten. Teilen Sie eine Installation nur mit Personen, denen Sie vertrauen.
  • Keine Passwort-Zurücksetzung: Siehe Problem 23.
  • Geschwindigkeit: PCs ohne GPU sind langsam; siehe Problem 13.
  • Web-Aufgaben und Terminal brauchen ein größeres Modell: Sie funktionieren am besten mit einem lokalen Modell ab 14B (zum Beispiel qwen3:14b); kleine 7B-Modelle halten sicher an, schaffen aber nur wenige Aufgaben. Siehe Problem 27.
  • Die Handy-App ist eine Vorschau: Die Android-App funktioniert nur in Ihrem Heimnetz und ist im geschlossenen Test bei Google Play. Die Nutzung außerhalb des Heimnetzes gehört nicht zu dieser Version. Siehe Problem 26.
  • Die erste Aufnahme lädt ein Sprachmodell: Die erste Aufnahme, die Sie hinzufügen, lädt einmalig Whisper large-v3-turbo (etwa 1,6 GB). Vollständig offline wird das kleinere Diktiermodell verwendet.
  • Terminal-Befehle stehen nicht in der Netzwerkliste: Ein Befehl, den Sie im Terminal erlauben (zum Beispiel npm install oder git push), und ein Werkzeug-Server, den Sie hinzufügen, laufen als Ihre eigenen Programme. Ihre Verbindungen stehen nicht in Einstellungen › Datenschutz & Netzwerk; solange StarkLLM vollständig offline ist, werden Befehle abgelehnt, die das Internet nutzen.

Hilfe

Hilfe & Problemlösung

Wenn StarkLLM nicht startet oder eine Antwort falsch aussieht, beginnen Sie hier. Jeder Schritt hat einen Test, damit Sie sehen, welcher Teil fehlt.

Springe zu: Checkliste · Probleme · Hilfe holen · Grenzen

Wie die Teile zusammenspielen

StarkLLM ist nicht ein einzelnes Programm. Vier Teile arbeiten zusammen, und das Desktop-Fenster ist nur der letzte:

Docker Desktop

Führt die StarkLLM-Dienste (Backend und Weboberfläche) im Hintergrund aus.

Ollama

Führt das Sprachmodell und das Embedding-Modell auf Ihrem eigenen PC aus. Nichts wird ins Internet gesendet.

Der StarkLLM-Projektordner

Enthält docker-compose.yml und die Starter (start.exe, start.cmd). Sein Start fährt die Dienste hoch.

Das Desktop-Fenster (StarkLLM.exe)

Zeigt nur die Weboberfläche unter http://localhost:5173 an. Es startet weder Docker noch Ollama noch die Dienste. Dieselbe Adresse können Sie auch in jedem Browser öffnen.

Der Desktop-Installer allein reicht also nicht. Wenn Sie nur StarkLLM-Setup.exe installiert haben, bleibt das Fenster bei „Connecting to local engine...“, bis die anderen drei Teile laufen.

Ehrlicher Hinweis: Die Schritte stammen aus den Start-Skripten und aus echten Testläufen unter Linux mit Docker und Ollama. Wir konnten nicht jeden Windows-PC testen. Weicht etwas von dem ab, was Sie sehen, schreiben Sie uns an info@starkllm.com, dann korrigieren wir diese Seite.

Installations-Checkliste mit Test pro Schritt

Gehen Sie die Schritte der Reihe nach durch. Machen Sie erst weiter, wenn der Test eines Schritts besteht. Öffnen Sie für die Befehle ein Terminal (Windows-Terminal oder Eingabeaufforderung).

  1. 1. Virtualisierung und WSL2Docker Desktop braucht unter Windows 10/11 Hardware-Virtualisierung und WSL2.
    wsl --status
    Test: Die Ausgabe zeigt „Default Version: 2“. Fehlt WSL, führen Sie wsl --install aus und starten neu. Im Task-Manager unter Leistung > CPU muss bei „Virtualisierung“ Aktiviert stehen; sonst schalten Sie sie im BIOS/UEFI ein (oft Intel VT-x, SVM oder AMD-V).
  2. 2. Docker DesktopInstallieren und starten Sie Docker Desktop und warten Sie, bis die Engine läuft (ruhiges Wal-Symbol im Infobereich). Verwenden Sie Linux-Container, keine Windows-Container.
    docker info
    Test: Die Ausgabe enthält einen Abschnitt „Server:“. Sehen Sie nur „error during connect ... dockerDesktopLinuxEngine“, läuft Docker Desktop noch nicht.
  3. 3. OllamaInstallieren Sie Ollama von ollama.com und stellen Sie sicher, dass es läuft (Symbol im Infobereich).
    ollama --version
curl http://localhost:11434/api/tags
    Test: Der zweite Befehl gibt JSON aus (eine Modellliste, möglicherweise leer).
  4. 4. Die zwei ModelleDie Standardeinrichtung nutzt ein 7B-Chatmodell und ein kleines Embedding-Modell. Zusammen etwa 5 GB Download.
    ollama pull qwen2.5:7b
ollama pull nomic-embed-text
ollama list
    Test: ollama list zeigt beide. Wenig Speicher (PC mit 8 GB)? Nehmen Sie stattdessen qwen2.5:3b und wählen es im Chat aus. Alte Kopien der Anleitung nennen qwen3-Modelle; ignorieren Sie diese (siehe Problem 5).
  5. 5. Projekt herunterladen und Dienste startenWählen Sie auf der GitHub-Seite des Projekts Code > Download ZIP und entpacken Sie es vollständig, zum Beispiel nach C:\StarkLLM. Öffnen Sie in diesem Ordner ein Terminal (cmd in die Adressleiste des Explorers tippen) und starten Sie:
    start.exe
:: oder, wenn SmartScreen start.exe blockiert
start.cmd
:: oder von Hand
docker compose up --build -d
    Test: docker compose ps zeigt zwei laufende Container (starkllm-backend, starkllm-frontend), und http://localhost:8000/health antwortet {"status":"ok",...}. Der erste Start baut die Images und kann 5 bis 15 Minuten dauern.
  6. 6. StarkLLM öffnenÖffnen Sie http://localhost:5173 im Browser oder starten Sie das Desktop-Fenster (StarkLLM.exe). Registrieren Sie ein Konto.Test: Sie sehen die Anmeldeseite, können einen Workspace anlegen und eine kleine Textdatei hochladen; ihr Status wechselt auf „indexed“. Stellen Sie danach eine Frage dazu.

Probleme und was zu tun ist

Klicken Sie auf ein Problem, um die wahrscheinliche Ursache und die Lösung zu sehen. Die Reihenfolge entspricht dem, was Nutzern meist als Erstes begegnet.

Installieren und Starten

1. Windows meldet „Der Computer wurde durch Windows geschützt“ (SmartScreen)

Wahrscheinliche Ursache: Installer, portable App und start.exe sind nicht code-signiert, und Dateien aus dem Internet tragen die Markierung „Mark of the Web“.

Was zu tun ist:

  1. Klicken Sie auf Weitere Informationen und dann auf Trotzdem ausführen.
  2. Optional: Vergleichen Sie vorher den SHA-256-Hash mit dem auf der Download-Seite.
  3. Blockiert Windows Skripte, führen Sie im Projektordner das Unblock-Skript aus (siehe unten).
  4. powershell -ExecutionPolicy Bypass -File unblock.ps1
2. „error during connect ... dockerDesktopLinuxEngine: The system cannot find the file specified“

Wahrscheinliche Ursache: Docker Desktop ist installiert, läuft aber noch nicht (oder startet gerade).

Was zu tun ist:

  1. Starten Sie Docker Desktop über das Startmenü und warten Sie, bis die Engine läuft.
  2. Führen Sie docker info erneut aus; es muss einen Abschnitt „Server:“ zeigen.
  3. Startet es nie: PC neu starten, WSL aktualisieren (wsl --update) und Problem 3 prüfen.
  4. docker info
3. „WSL 2 installation is incomplete“ oder „Hardware assisted virtualization ... must be enabled in the BIOS“

Wahrscheinliche Ursache: WSL2 oder die Plattform für virtuelle Maschinen fehlt, oder die Virtualisierung ist im BIOS/UEFI ausgeschaltet. In einer virtuellen Maschine muss zusätzlich verschachtelte Virtualisierung aktiv sein.

Was zu tun ist:

  1. Führen Sie wsl --install in einem Administrator-Terminal aus und starten Sie neu.
  2. Schalten Sie Intel VT-x / AMD SVM im BIOS/UEFI ein, wenn der Task-Manager „Virtualisierung: Deaktiviert“ zeigt.
  3. Windows 10/11 Home funktioniert mit dem WSL2-Backend; Hyper-V ist nicht nötig.
  4. wsl --install
wsl --update
4. docker compose scheitert mit: could not select device driver "nvidia" with capabilities: [[gpu]]

Wahrscheinliche Ursache: Ältere Kopien des Projekts (ein ZIP von vor der Korrektur in Pull Request #1 auf GitHub) enthalten in docker-compose.yml eine GPU-Reservierung. Das Backend nutzt die GPU nicht (Ollama tut es), daher ist sie unnötig und scheitert auf PCs ohne NVIDIA-Container-Toolkit.

Was zu tun ist:

  1. Öffnen Sie docker-compose.yml und löschen den ganzen Block „deploy:“ (die Zeilen mit resources, reservations, devices, driver: nvidia) und starten erneut. Neuere Kopien des Projekts enthalten ihn nicht mehr.
  2. docker compose up --build -d
5. „pull model manifest: file does not exist“, „model not found“ oder der PC friert ein, weil das Modell viel zu groß ist

Wahrscheinliche Ursache: Alte Kopien von start-here.txt, start.cmd und .env.example nannten qwen3.8:27b und qwen3-embedding:0.6b. Ein 27B-Modell braucht etwa 17 GB freien Speicher, und das Embedding-Modell passt nicht zum Standard, den die App erwartet.

Was zu tun ist:

  1. Nehmen Sie die Modelle der Standardeinrichtung:
  2. ollama pull qwen2.5:7b
ollama pull nomic-embed-text
docker compose up -d --force-recreate
  3. Haben Sie DEFAULT_TEXT_MODEL oder DEFAULT_EMBEDDING_MODEL in .env geändert, setzen Sie sie auf qwen2.5:7b und nomic-embed-text zurück und erzeugen die Container neu.
  4. Mit einem anderen Embedding-Modell indexierte Dokumente müssen erneut hochgeladen werden (die Vektoren haben eine andere Größe).
6. „Bind for 127.0.0.1:8000 failed: port is already allocated“ (oder 5173)

Wahrscheinliche Ursache: Ein anderes Programm belegt schon Port 8000 (Backend) oder 5173 (Weboberfläche).

Was zu tun ist:

  1. Finden Sie das Programm und beenden Sie es:
  2. netstat -ano | findstr :8000
tasklist /FI "PID eq <Zahl aus der letzten Spalte>"
  3. Oder verlegen Sie StarkLLM auf andere Ports: Ändern Sie in docker-compose.yml die linke Zahl der Zeilen unter ports (zum Beispiel "127.0.0.1:8001:8000" und "127.0.0.1:5174:80").
  4. Haben Sie die Weboberfläche verlegt, sagen Sie es dem Desktop-Fenster: setx STARKLLM_URL http://localhost:5174 und starten Sie das Fenster neu.
  5. Hinweis: BACKEND_PORT und FRONTEND_PORT in .env.example liest docker-compose.yml in v2.0.0 nicht; eine Änderung dort bewirkt nichts.
7. Der erste Start dauert sehr lange oder endet beim Bauen mit einem Fehler

Wahrscheinliche Ursache: Das Backend-Image ist groß (etwa 4,4 GB) und wird auf Ihrem PC gebaut. Langsames Internet, ein Firmen-Proxy, ein VPN, Virenscanner oder eine fast volle Platte machen es langsamer oder brechen es ab.

Was zu tun ist:

  1. Halten Sie mindestens 15 GB freien Speicherplatz bereit (Images 4,5 GB, Modelle 5 GB, Docker-Overhead).
  2. Beobachten Sie den Fortschritt, statt blind zu warten:
  3. docker compose logs -f backend
  4. Hinter einem Proxy: in Docker Desktop > Settings > Resources > Proxies eintragen. Meldungen wie „failed to resolve source metadata“ oder TLS-Fehler deuten auf ein blockiertes Netz; probieren Sie ein anderes.
  5. Starten Sie nach der Behebung erneut; fertige Schichten werden wiederverwendet.
8. Das Desktop-Fenster bleibt bei „Connecting to local engine...“ stehen und wird dann leer

Wahrscheinliche Ursache: Das Fenster zeigt nur http://localhost:5173 an. Die Dienste laufen nicht (es startet sie nicht) oder starten noch.

Was zu tun ist:

  1. Führen Sie im Projektordner docker compose ps aus; beide Container müssen „running“ sein.
  2. Starten Sie sie mit start.exe, start.cmd oder docker compose up -d, warten Sie 1 bis 2 Minuten und versuchen Sie es erneut.
  3. Öffnen Sie http://localhost:5173 im Browser. Funktioniert der Browser, das Fenster aber nicht, schließen Sie das Fenster (auch im Infobereich) und starten es neu.
  4. docker compose ps
curl http://localhost:8000/health
9. Der Browser zeigt „502 Bad Gateway“ oder eine leere Seite unter localhost:5173

Wahrscheinliche Ursache: Die Weboberfläche läuft, aber das Backend startet noch oder ist abgestürzt.

Was zu tun ist:

  1. Warten Sie nach dem Start ein bis zwei Minuten und laden Sie neu.
  2. Lesen Sie die letzten Zeilen des Backend-Logs; der Fehler steht meist in den letzten 20 Zeilen.
  3. Starten Sie nur das Backend neu.
  4. docker compose logs --tail 50 backend
docker compose restart backend

Chat und Modelle

10. „Model ... not found in Ollama. Please ensure it is pulled“

Wahrscheinliche Ursache: Der Chat verlangt ein Modell, das nicht installiert ist (Standard ist qwen2.5:7b).

Was zu tun ist:

  1. Listen Sie die installierten Modelle auf und laden Sie das fehlende, oder wählen Sie in der Modellauswahl des Chats ein installiertes Modell.
  2. ollama list
ollama pull qwen2.5:7b
11. „Error generating response: 500 Server Error ...“ oder die Antwort kommt nie

Wahrscheinliche Ursache: In v2.0.0 bedeutet das fast immer, dass das Modell nicht in den freien Speicher passte und Ollama es gestoppt hat. Ein 7B-Modell braucht etwa 5 bis 6 GB freien RAM; bei zu wenig Speicher wird auch Windows sehr langsam.

Was zu tun ist:

  1. Schließen Sie Browser, Spiele und andere große Programme und versuchen Sie es erneut.
  2. Wählen Sie ein kleineres Modell, zum Beispiel qwen2.5:3b (etwa 2 GB), und wählen Sie es im Chat aus.
  3. Prüfen Sie, was Ollama geladen hat.
  4. Der rohe Text „500 Server Error“ hilft wenig, aber fehlender Speicher ist mit Abstand der häufigste Grund dafür.
  5. ollama pull qwen2.5:3b
ollama ps
12. „Cannot connect to Ollama“ oder der Chat antwortet gar nicht

Wahrscheinliche Ursache: Ollama läuft nicht, oder eine Firewall blockiert die Verbindung vom Docker-Container zum PC. Das Backend erreicht Ollama unter host.docker.internal:11434.

Was zu tun ist:

  1. Starten Sie Ollama und prüfen Sie es vom PC aus:
  2. curl http://localhost:11434/api/tags
docker compose restart backend
  3. Erlauben Sie Docker Desktop und Ollama in Firewall und Sicherheitssoftware.
  4. Starten Sie danach die Container neu.
13. Die Antworten sind sehr langsam

Wahrscheinliche Ursache: Ohne passende GPU rechnet Ollama auf der CPU. Die erste Antwort muss außerdem das Modell laden (in unserem Test etwa 20 Sekunden). Auf einem 16-Kern-Desktop dauerte eine kurze Antwort ungefähr 10 bis 40 Sekunden; Laptops sind langsamer.

Was zu tun ist:

  1. Nehmen Sie auf schwachen PCs ein kleineres Modell (qwen2.5:3b).
  2. Stellen Sie kurze, konkrete Fragen; lange Antworten kosten am meisten Zeit.
  3. Eine dedizierte NVIDIA-GPU mit 8 GB oder mehr VRAM macht es deutlich schneller.
  4. Auch das Indexieren ist langsam: Jedes Textstück eines Dokuments geht an das Embedding-Modell.

Dokumente und Antwortqualität

14. Der Assistent ignoriert meine Dokumente und antwortet aus Allgemeinwissen (oder erfindet etwas)

Wahrscheinliche Ursache: In v2.0.0 startet die Dokumentsuche nur, wenn Ihre Nachricht eines von einer Liste englischer Auslösewörter enthält (zum Beispiel document, file, pdf, uploaded, report, summary, according to). Eine Frage wie „Wie hoch ist die Nennlast?“ enthält keines davon, daher antwortet das Modell allein. In unserem Test erfand es dann Antworten (es nannte das Förderband FT-480 einen Bootsmotor), und die Antwort zeigt keine Quelldatei.

Was zu tun ist:

  1. Fügen Sie der Frage ein englisches Auslösewort hinzu; der Rest der Frage kann in jeder Sprache sein: „According to the document: Wie hoch ist die Nennlast des FT-480?“ oder „... (see the file)“. Deutsche Wörter wie „Dokument“ stehen nicht auf der Liste und wirken nicht.
  2. Prüfen Sie immer, ob die Antwort eine Quelldatei nennt. Keine Quelldatei heißt: Ihre Dokumente wurden nicht genutzt.
  3. Eine Korrektur, die Ihre Dokumente bei jeder Frage durchsucht, sobald Dokumente indexiert sind, ist in Vorbereitung. Bis sie veröffentlicht ist, nutzen Sie das Auslösewort.
15. Eine Datei lässt sich nicht hochladen oder endet mit dem Status „failed“

Wahrscheinliche Ursache: Der Dateityp wird nicht unterstützt, die Datei ist leer oder beschädigt, oder sie ist größer als 100 MB.

Was zu tun ist:

  1. Unterstützt: PDF, DOCX, XLSX, TXT, MD, CSV, JSON, HTML, PNG, JPG.
  2. Öffnen Sie die Datei zuerst auf Ihrem PC; eine beschädigte PDF scheitert auch hier.
  3. Gescannte PDFs und Bilder brauchen Texterkennung (OCR) und sind langsamer; nehmen Sie lieber die Originaltextdatei, wenn Sie sie haben.
  4. Das bloße Umbenennen (zum Beispiel .exe in .txt) hilft nicht.
16. Eine CSV-, Excel- oder JSON-Datei steht auf „indexed“, aber nichts darin wird je gefunden (auch Tabellen in Word-Dateien)

Wahrscheinliche Ursache: In v2.0.0 werden diese Dateitypen angenommen, liefern aber keinen durchsuchbaren Text: Die Datei gilt als indexiert, obwohl nichts im Index liegt, und Tabellen in DOCX-Dateien werden übersprungen. In unserem Test wurden die Preise einer CSV-Preisliste nie gefunden.

Was zu tun ist:

  1. Kopieren Sie die Zeilen in eine Textdatei (.txt oder .md) oder exportieren Sie die Tabelle als PDF und laden Sie das hoch.
  2. Übernehmen Sie den Inhalt von Word-Tabellen in normale Absätze.
  3. Testen Sie jede neue Datei mit einer Frage, deren Antwort Sie kennen, bevor Sie sich darauf verlassen.
  4. Eine Korrektur, die CSV, XLSX, JSON und Word-Tabellen indexiert, ist in Vorbereitung.
17. Die Antwort sagt „nicht in den Dokumenten gefunden“, obwohl die Angabe im Dokument steht

Wahrscheinliche Ursache: Die Suche liefert nur wenige Textstellen. Sie kann eine Angabe verpassen, wenn die Frage andere Wörter benutzt, wenn die Frage in einer anderen Sprache als das Dokument gestellt ist (eine englische Frage zu einem deutschen Vertrag wird oft nicht gefunden) oder wenn eine lange Datei ohne Sätze und Satzzeichen (etwa ein Maschinenlog) indexiert wurde.

Was zu tun ist:

  1. Fragen Sie in der Sprache des Dokuments und mit dem genauen Begriff, der Zahl oder der ID, die darin vorkommt.
  2. Formulieren Sie konkreter (Datei, Abschnitt oder Modellnummer nennen).
  3. Teilen Sie lange Logs oder Tabellen in kleinere Dateien nach Zeitraum oder Thema.
  4. Die Antwort nennt ihre Quelldatei; öffnen Sie sie und prüfen Sie nach.
18. Die Antwort vermischt eine alte und eine neue Version eines Dokuments

Wahrscheinliche Ursache: Alle hochgeladenen Dokumente eines Workspaces werden gemeinsam durchsucht. Ohne Datum oder „ersetzt“-Hinweis kann das Modell nicht wissen, welche Version gilt.

Was zu tun ist:

  1. Löschen Sie veraltete Dokumente aus dem Workspace oder halten Sie alte Versionen in einem eigenen Workspace.
  2. Schreiben Sie die Gültigkeit in den Text („gültig ab ...“, „ersetzt durch ...“).
  3. Fragen Sie ausdrücklich: „Laut Vertrag 2026 ...“.
19. Namen, Zahlen oder ähnliche Teilenummern werden verwechselt

Wahrscheinliche Ursache: Ein lokal laufendes 7B-Modell kann ähnliche Werte verwechseln (etwa FT-48 und FT-480) oder falsch rechnen. In unseren eigenen Tests wurde dieselbe Frage in manchen Läufen richtig und in anderen falsch beantwortet.

Was zu tun ist:

  1. Öffnen Sie bei wichtigen Dingen die genannte Quelle und prüfen Sie die Zahl selbst.
  2. Stellen Sie eine Frage nach der anderen und nennen Sie das genaue Modell oder die Teilenummer.
  3. Ein größeres Modell (qwen2.5:14b, braucht etwa 10 GB RAM) ist zuverlässiger, wenn Ihr PC es verträgt.
20. Zusammenfassungen lassen Wichtiges weg, oder Antworten auf Persisch und in anderen Sprachen außer Englisch lesen sich schlecht

Wahrscheinliche Ursache: Kleine Modelle fassen ungenau zusammen und sind außerhalb von Englisch und Deutsch schwächer.

Was zu tun ist:

  1. Nennen Sie die gewünschten Punkte: „Fasse in drei Punkten zusammen: Laufzeit, Preis, Kündigungsfrist“.
  2. Nehmen Sie für solche Aufgaben ein größeres Modell.
  3. Schreiben Sie die Frage in der Sprache des Dokuments; die Antwort folgt der Sprache Ihrer Frage.
21. Ein Dokument enthält Anweisungen („ignoriere alle bisherigen Anweisungen ...“)

Wahrscheinliche Ursache: Text in Dokumenten kann versuchen, das Modell zu lenken (Prompt-Injection). In unserem Test ignorierte das Modell einen solchen Satz und beantwortete die eigentliche Frage, eine Garantie gibt es aber nicht.

Was zu tun ist:

  1. Indexieren Sie nur Dokumente, denen Sie vertrauen.
  2. Gehen Sie mit Antworten aus Dokumenten unbekannter Herkunft vorsichtig um.

Konto, Daten und Entfernen

22. Ich habe mein Passwort vergessen

Wahrscheinliche Ursache: Version 2.0.0 hat keine Passwort-Zurücksetzung (nur „Passwort ändern“ im angemeldeten Zustand).

Was zu tun ist:

  1. Probieren Sie Ihre üblichen Passwörter.
  2. Als letzten Ausweg registrieren Sie ein neues Konto. Dessen Workspaces sind getrennt: Das alte Konto behält seine Daten im selben Datenordner, Sie können es aber nicht öffnen.
23. Wo liegen meine Daten? Wie sichere ich sie?

Wahrscheinliche Ursache: Alles bleibt auf Ihrem PC.

Was zu tun ist:

  1. Der Ordner data\ im Projektordner enthält Datenbank, Suchindex und hochgeladene Dateien; knowledge_base_data\ enthält Ihre Dateien der Wissensdatenbank.
  2. In den Einstellungen gibt es Backup und Wiederherstellung. In v2.0.0 kann jedes Konto der Installation sie nutzen, und ein Backup enthält die Daten aller Konten. Nutzen Sie eine Installation für eine Person und bewahren Sie Backups sicher auf.
  3. Stoppen Sie die Dienste, bevor Sie die Ordner von Hand kopieren: docker compose down.
  4. docker compose down
24. Wie stoppe oder deinstalliere ich StarkLLM?

Wahrscheinliche Ursache: Es gibt mehrere getrennte Teile, die jeweils für sich entfernt werden.

Was zu tun ist:

  1. Stoppen: docker compose down (Ihre Daten in data\ bleiben).
  2. Programm entfernen: Windows-Einstellungen > Apps > StarkLLM. Löschen Sie den Projektordner erst, wenn Sie Ihre Daten nicht mehr brauchen.
  3. Speicher freigeben: docker image prune -a entfernt ungenutzte Images; ollama rm <Name> entfernt ein Modell.
  4. docker compose down
docker image prune -a
ollama rm qwen2.5:7b

winver

Bekannte Grenzen von v2.0.0

Das sagen wir lieber offen:

  • Die Desktop-App startet die Dienste nicht: Docker, Ollama und das Projekt starten Sie selbst (siehe Checkliste).
  • Antworten können falsch sein: Das 7B-Standardmodell kann ähnliche Werte verwechseln, falsch rechnen oder eine Angabe übersehen. Prüfen Sie bei wichtigen Entscheidungen immer die genannte Quelle.
  • Fragen in einer anderen Sprache als das Dokument: Eine englische Frage zu einem deutschen Dokument wird oft nicht beantwortet, weil das Embedding-Modell auf Englisch am stärksten ist. Fragen Sie in der Dokumentsprache.
  • Lange Dateien ohne Satzzeichen: Logs und ähnliche Dateien können als sehr große Stücke indexiert werden, sodass einzelne Werte darin schwer zu finden sind.
  • Alte und neue Versionen: Der Assistent weiß nicht, welche Dokumentversion gilt, solange der Text es nicht sagt.
  • Dokumente werden nur mit Auslösewort durchsucht: Bis die Korrektur veröffentlicht ist, fügen Sie Ihrer Frage ein englisches Wort wie „document“ oder „file“ hinzu (siehe Problem 14).
  • CSV, Excel, JSON und Word-Tabellen sind nicht durchsuchbar: Bis die Korrektur veröffentlicht ist, wandeln Sie sie in Text oder PDF um (siehe Problem 16).
  • Eine Person pro Installation: Jedes Konto kann ein Backup der ganzen Datenbank erstellen; teilen Sie eine Installation daher nicht mit Personen, die die Dokumente der anderen nicht sehen dürfen.
  • Keine Passwort-Zurücksetzung, nicht signierte Programme: Siehe Probleme 1 und 22.
  • Geschwindigkeit: PCs ohne GPU sind langsam; siehe Problem 13.

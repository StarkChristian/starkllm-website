Einrichtung

Sind Docker, Ollama und die Modelle bereits installiert, dauert die Einrichtung etwa 5 Minuten. Der erste Download von Modellen und Docker-Images hängt von Ihrer Bandbreite ab.

  1. Docker Desktop startenStellen Sie sicher, dass Docker Desktop im Infobereich läuft.
  2. Ollama installieren und Modelle ladenFühren Sie im Terminal aus:
    ollama pull qwen2.5:7b
ollama pull nomic-embed-text
    Für Laptops mit 8 GB RAM: ollama pull qwen2.5:3b. Für leistungsstarke Workstations: ollama pull qwen2.5:14b.
  3. StarkLLM-Projekt holen und Dienste startenDie Desktop-App zeigt StarkLLM nur an; sie startet die Dienste nicht selbst. Laden Sie das Projekt von GitHub herunter (Code, dann Download ZIP, oder git clone), entpacken Sie es, öffnen Sie in diesem Ordner ein Terminal und führen Sie start.cmd aus und wählen Sie 1 (Start StarkLLM), oder führen Sie aus:
    docker compose up --build -d
    Beim ersten Start werden die Container gebaut, das kann einige Minuten dauern.
  4. StarkLLM-Installer ausführenLaden Sie StarkLLM-v2.0.0-Setup.exe herunter und starten Sie sie, oder nutzen Sie die portable Programmdatei ohne Installation. Der Installer legt Desktop-Verknüpfungen an.
  5. Desktop-App startenKlicken Sie auf die StarkLLM-Verknüpfung. Laufen die Dienste aus dem früheren Schritt, öffnet sich StarkLLM in einem eigenen Anwendungsfenster, ohne Browser-Tabs und Adressleiste. Laufen die Dienste nicht, bleibt das Fenster auf „Connecting to local engine…“.

Checkliste der Voraussetzungen

Bevor Sie StarkLLM starten, prüfen Sie, ob alles Folgende vorhanden ist:

  • Betriebssystem: Windows 10 oder 11 mit aktiviertem WSL2.
  • Docker Desktop: Installiert und gestartet (im Infobereich sichtbar). Ohne Docker können keine Container starten.
  • Ollama: Nativ unter Windows installiert und gestartet. Download auf ollama.com.
  • Empfohlene Modelle: Im Terminal: ollama pull qwen2.5:7b und ollama pull nomic-embed-text.
  • Hardware: Mindestens 8 GB RAM (3B-Modelle), empfohlen 16 GB (7B-Modelle). Eine NVIDIA-GPU mit 8 GB+ VRAM wird dringend empfohlen. Das Handbuch enthält Hinweise zu Hardwarestufen.
  • Unterstützte Formate: PDF, DOCX, TXT, Markdown (.md), CSV, JSON, HTML und Bilder (PNG, JPG mit OCR).

Windows SmartScreen und Ausführungshinweis

Aus dem Web geladene Dateien tragen die Markierung „Mark of the Web“ (MOTW), und der StarkLLM-Installer sowie die portable App sind nicht code-signiert, daher kann Windows SmartScreen beim Start warnen. Klicken Sie auf „Weitere Informationen“ und dann auf „Trotzdem ausführen“. Bei den Start-Skripten können Sie zusätzlich unblock.ps1 in PowerShell ausführen, um die Markierung lokal zu entfernen.

Alternative Startmöglichkeiten

Diese gelten für den portablen Ordner oder das ZIP mit den Start-Skripten.

Variante A: start.exe im Terminal ausführen

start.exe ist ein eigenständiger Starter. Er prüft Docker Desktop und Ollama, baut Container und öffnet Ihren Browser.

  1. Klicken Sie im Explorer im entpackten Ordner in die Adressleiste, tippen Sie cmd und drücken Sie Enter.
  2. Tippen Sie start.exe und drücken Sie Enter. Warnt SmartScreen, klicken Sie auf „Weitere Informationen“ und dann auf „Trotzdem ausführen“.

Variante B: start.cmd ausführen

Um ein Befehlsskript direkt zu starten, öffnen Sie ein Terminal im entpackten Ordner und führen start.cmd aus (in PowerShell: .\start.cmd).

Variante C: Docker Compose direkt

Mit der Standard-Docker-CLI:

docker compose up --build -d

Variante D: unblock.ps1 ausführen

Blockieren Ausführungsrichtlinien Skripte, öffnen Sie PowerShell im entpackten Ordner und führen aus:

powershell -ExecutionPolicy Bypass -File unblock.ps1

Das entfernt SmartScreen-Markierungen nur von Dateien im aktuellen StarkLLM-Ordner. Ihre globalen Windows-Sicherheitseinstellungen bleiben unverändert. Danach führen Sie start.exe oder start.cmd aus.

Häufige Fragen

Verlassen meine Daten meinen Computer?

StarkLLM ist darauf ausgelegt, Ihre Daten auf Ihrem Rechner zu halten. Dokumente liegen in einem lokalen ChromaDB-Container, die KI-Inferenz läuft über Ollama auf Ihrem Host. Im normalen lokalen Betrieb werden keine Daten nach außen übertragen.

Ist StarkLLM kostenlos?

Ja. Es ist kostenlos und quelloffen unter Apache 2.0 für private, wissenschaftliche und kommerzielle Nutzung. Keine Abos, keine Telemetrie, keine versteckten Stufen. Bereitgestellt „wie besehen“ ohne Gewährleistung.

Warum können Antworten langsam sein?

Das Tempo hängt von Ihrer Hardware ab. Ohne dedizierte GPU nutzt Ollama die CPU, was deutlich langsamer ist. Eine dedizierte NVIDIA-GPU mit 8 GB+ VRAM erzeugt Text deutlich schneller.

Warum warnt Windows SmartScreen vor heruntergeladenen Startern?

Windows versieht aus dem Internet geladene Dateien mit der Markierung „Mark of the Web“. Beim Start von start.exe klicken Sie auf „Weitere Informationen“ und dann auf „Trotzdem ausführen“. Alternativ führen Sie start.cmd im Terminal aus oder unblock.ps1, um die Markierung lokal zu entfernen.

Welche Hardware brauche ich?

Mindestens 8 GB RAM für 3B-Modelle, 16 GB RAM für 7B-Modelle. Für große Modelle (14B bis 32B) werden 24 GB VRAM oder 64 GB Arbeitsspeicher empfohlen.

Was ist der Unterschied zwischen normalem Chat und Dokument-Chat?

Der normale Chat nutzt nur das vortrainierte Wissen des Modells. Der Dokument-Chat nutzt RAG: Er durchsucht zuerst Ihre hochgeladenen Dokumente, gibt die relevanten Chunks an das Modell und antwortet mit überprüfbaren Quellenangaben.

Was ist der Unterschied zwischen Workspace-Dokumenten und Wissensdatenbank?

Workspace-Dokumente sind auf ein Projekt beschränkt. Die Wissensdatenbank ist ein dauerhafter, globaler Ordner auf Ihrem Rechner, auf den jeder Chat zugreifen kann.

Das Desktop-Fenster bleibt auf „Connecting to local engine…“. Was tun?

Die Desktop-App zeigt StarkLLM nur an; die Dienste müssen bereits laufen. Prüfen Sie, ob Docker Desktop läuft, starten Sie StarkLLM im Projektordner mit start.cmd (oder docker compose up --build -d) und stellen Sie sicher, dass Ollama läuft. Das Fenster lädt von selbst, sobald die Dienste antworten.

Was, wenn die App startet, aber der Chat keine Verbindung hat?

Stellen Sie sicher, dass Docker Desktop und Ollama laufen und dass Sie die Standardmodelle geladen haben (ollama pull qwen2.5:7b und ollama pull nomic-embed-text). Der Backend-Container erreicht Ollama auf Ihrem Host über host.docker.internal:11434. Bei Bedarf starten Sie die Container mit docker compose down und anschließend docker compose up --build -d neu.

Help & Troubleshooting

If StarkLLM does not start or an answer looks wrong, start here. Every step has a test, so you can see which part is missing.

ChecklistProblemsGet helpLimits

How the pieces fit together

StarkLLM is not one program. Two parts work together, and the desktop app starts the other one for you:

The StarkLLM app (StarkLLM.exe)

Contains the engine (database, search index, backend and web interface) and, since v2.2, runs it directly on Windows: no Docker Desktop, no WSL2. On every start it checks Ollama, downloads missing models, starts the engine and then shows StarkLLM. If a part is missing it says which one and how to fix it. When you quit StarkLLM, the engine stops too.

Ollama

Runs the language model and the embedding model on your own PC. Your documents and questions stay on your PC; Ollama itself only goes online for model downloads and its own update check. If Ollama is missing, StarkLLM offers "Install Ollama for me" and installs the official, signed version; then it starts Ollama and downloads the models.

Docker Desktop (optional, advanced)

Not needed since v2.2. If you prefer it, choose "Use Docker Desktop for the engine (advanced)" in the tray menu; StarkLLM then runs its engine in Docker Desktop, with the same data.

From source (optional)

Developers can build and run the engine from the source code on GitHub with docker compose up --build -d.

Versions before 2.2 needed Docker Desktop and WSL2, and v2.0.0 (before 24 October 2026) started nothing at all. Please install v2.6.0.

Honest note: the steps were assembled from the checks the app runs on every start and from real test runs. We could not test every Windows PC. If something here does not match what you see, tell us at info@starkllm.com and we will fix this page.

Install checklist with a test for every step

Do the steps in this order. Do not continue until the test of a step passes. Open a terminal (Windows Terminal or PowerShell) for the commands.

  1. 1. Windows and disk spaceStarkLLM runs on Windows 10 or 11 (64-bit). Docker Desktop and WSL2 are not needed. Keep at least 15 GB of free disk space for the app, the engine and the AI models.
    winver
    Test: winver shows Windows 10 or Windows 11. In File Explorer, the drive with your user folder (usually C:) has at least 15 GB free.
  2. 2. Install and start StarkLLMDownload StarkLLM-v2.6.0-Setup.exe from the download page, install it and start StarkLLM. The engine is part of the installer.Test: the StarkLLM window opens and shows the progress of the start. If it says "StarkLLM could not start", it lists what is missing and has a Retry button.
  3. 3. OllamaIf Ollama is missing, the window offers "Install Ollama for me": StarkLLM downloads the official installer from ollama.com (about 2 GB), checks its signature and installs it; no administrator rights are needed. You can also install Ollama yourself from ollama.com.
    ollama --version
curl http://localhost:11434/api/tags
    Test: the second command prints JSON (a list of models, possibly empty).
  4. 4. The two modelsOn the first start StarkLLM downloads a chat model and a small embedding model (by default qwen2.5:7b and nomic-embed-text, about 5 GB together) and shows the progress. Suitable models you already have in Ollama are used instead.
    ollama list
    Test: ollama list shows a chat model and an embedding model. If a download failed, the window names the model: run ollama pull with that name and press Retry. Short on memory (8 GB PC)? Use qwen2.5:3b and select it in the chat.
  5. 5. First testStarkLLM signs you in as the user of this PC; there is no account to create.Test: you can create a workspace and upload a small text file; its status changes to "indexed". Then ask a question about it and check that the answer names the file.

Problems and what to do

Click a problem to see the likely cause and the fix. They are ordered the way people usually meet them.

Installing and starting

1. Windows says "Windows protected your PC" (SmartScreen) or Smart App Control blocks the installer

Likely cause: Since v2.1.2 the installer, StarkLLM.exe and the uninstaller are signed by "Open Source Developer Christian Stark", so Windows can verify the publisher. Windows can still warn about a file it has not seen often. Versions before v2.1.2 were not signed.

What to do:

  1. Check the publisher: right-click the installer, choose Properties and open the Digital Signatures tab. The signer must be "Open Source Developer Christian Stark", and Details must say "This digital signature is OK".
  2. Compare the SHA-256 hash with the one on the download page.
  3. If both match, continue (in SmartScreen: More info, then Run anyway). If not, do not run the file: download it again and tell us at info@starkllm.com.
  4. Do not turn off Smart App Control, SmartScreen or other security settings. If Smart App Control blocks a correctly signed installer, tell us at info@starkllm.com.
2. Smart App Control or security software blocks a program file of the engine

Likely cause: Since v2.2.1 every program file of the engine (Python packages, Tesseract) is signed by "Open Source Developer Christian Stark", so Smart App Control lets them run. Another application control rule or security software can still block a file; then the engine does not start.

What to do:

  1. The start page names the blocked file and the engine log (%APPDATA%\StarkLLM\engine-native.log).
  2. Do not turn off Smart App Control or your security software. Report the file name on the StarkLLM page on GitHub or at info@starkllm.com.
  3. Until it is fixed you can choose "Use Docker Desktop for the engine (advanced)" in the tray menu (needs Docker Desktop with WSL2).
3. "Ollama is not installed" or "Ollama is not running"

Likely cause: StarkLLM runs its AI models with Ollama (free) and expects it at 127.0.0.1:11434.

What to do:

  1. Press "Install Ollama for me" on the start page, or install Ollama yourself from ollama.com.
  2. If Ollama is installed: start it from the Start menu, wait for its icon in the tray and press Retry.
  3. Check it from the PC:
  4. curl http://localhost:11434/api/tags
4. "pull model manifest: file does not exist", "model not found", or the PC freezes because the model is far too big

Likely cause: The model name does not exist in Ollama, or the chosen model needs far more memory than the PC has (a 27B model needs about 17 GB of free memory). Old copies of start-here.txt and .env.example named qwen3.8:27b and qwen3-embedding:0.6b.

What to do:

  1. Use the models of the default setup:
  2. ollama pull qwen2.5:7b
ollama pull nomic-embed-text
  3. Or pick an installed model in the model selector (AI MODEL at the bottom left).
  4. Documents indexed with a different embedding model must be uploaded again (the vectors have a different size).
5. "Another StarkLLM engine already uses port 5173", or the engine does not start because the port is busy

Likely cause: The engine serves the app on port 5173 of your PC (127.0.0.1). Another program, or the StarkLLM containers of an earlier install with Docker Desktop, already use it. StarkLLM stops its own old containers by itself; other programs it cannot stop.

What to do:

  1. Find the program, then close it:
  2. netstat -ano | findstr :5173
tasklist /FI "PID eq <number from the last column>"
  3. Or move StarkLLM to another port: run setx STARKLLM_UI_PORT 5174, then quit StarkLLM in the tray menu and start it again.
6. The first start takes very long or a download fails

Likely cause: The first start downloads the AI models (about 5 GB) and, if you let it, Ollama (about 2 GB). Slow internet, a company proxy, a VPN, antivirus scanning or a nearly full disk make it slower or stop it.

What to do:

  1. Keep at least 15 GB of free disk space (models about 5 GB, plus Ollama, the app and the engine).
  2. The window shows the progress of each download. TLS or connection errors point to a blocked network; try another network.
  3. After fixing the cause, press Retry; models that are already downloaded are not downloaded again.
7. The window says "StarkLLM could not start"

Likely cause: The app starts Ollama and its engine itself and shows this page when a step fails.

What to do:

  1. Read the red line on the page: it names the missing part (Ollama, a busy port, a program file Windows blocked, or an engine error with its last log lines).
  2. Fix that part and press Retry. The logs are in %APPDATA%\StarkLLM: engine.log (the app) and engine-native.log (the engine).
  3. The first start after an install or update can take a few minutes on a busy PC; the window says so while it waits.
8. The window stays empty or shows an error page after the start

Likely cause: The engine is still starting or has stopped.

What to do:

  1. Wait one or two minutes, then choose "Reload Application" in the tray menu.
  2. If it stays empty, quit StarkLLM in the tray menu and start it again.
  3. The error is usually in the last 20 lines of the engine log (open it in PowerShell):
  4. notepad "$env:APPDATA\StarkLLM\engine-native.log"
9. I use Docker Desktop for the engine (advanced) and it does not start

Likely cause: With "Use Docker Desktop for the engine (advanced)" in the tray menu, StarkLLM needs Docker Desktop with WSL2, as versions before 2.2 did. Errors such as "error during connect ... dockerDesktopLinuxEngine" or "WSL 2 installation is incomplete" come from Docker Desktop.

What to do:

  1. Start Docker Desktop and wait until its engine is running; docker info must show a Server: section.
  2. If WSL2 is missing, run wsl --install in an administrator terminal and restart; virtualization must be enabled in the BIOS/UEFI.
  3. Or go back to the built-in engine: untick "Use Docker Desktop for the engine (advanced)" in the tray menu. Chats, documents and settings are the same in both.
  4. docker info
wsl --status

Using chat and models

10. "Model ... not found in Ollama. Please ensure it is pulled"

Likely cause: The chat asks for a model that is not installed (the default is qwen2.5:7b). In v2.0.1 the chat asked for llama3.2:3b on every new installation ("Model 'llama3.2:3b' not found"); v2.0.2 uses the model the app downloads.

What to do:

  1. Update to the latest version (Settings → About StarkLLM → Check for updates), or pick an installed model in the model selector (AI MODEL at the bottom left).
  2. List the installed models and pull the missing one.
  3. ollama list
ollama pull qwen2.5:7b
11. "Not enough free memory to run model ...", "Error generating response: 500 Server Error ..." or the answer never comes

Likely cause: The model did not fit into the free memory and Ollama stopped it. A 7B model needs about 5 to 6 GB of free RAM; with too little memory Windows also gets very slow. Since v2.0.1 the chat says this in plain words; v2.0.0 showed the raw "500 Server Error".

What to do:

  1. Close browsers, games and other large programs and try again.
  2. Choose a smaller model, for example qwen2.5:3b (about 2 GB), and select it in the chat.
  3. Check what Ollama has loaded.
  4. ollama pull qwen2.5:3b
ollama ps
12. "Ollama is offline." or chat does not answer at all

Likely cause: Ollama is not running, or security software blocks the connection to it. StarkLLM reaches Ollama at 127.0.0.1:11434 (with the Docker Desktop engine: host.docker.internal:11434).

What to do:

  1. Start Ollama and check it from the PC:
  2. curl http://localhost:11434/api/tags
  3. Allow Ollama in your firewall or security software.
  4. Then choose "Reload Application" in the tray menu, or quit StarkLLM and start it again.
13. Answers are very slow

Likely cause: Without a suitable GPU Ollama computes on the CPU. The first answer also has to load the model (in our test about 20 seconds). On a 16-core desktop a short answer took roughly 10 to 40 seconds; laptops are slower.

What to do:

  1. Use a smaller model (qwen2.5:3b) on weak PCs.
  2. Ask short, specific questions; long answers cost the most time.
  3. A dedicated NVIDIA GPU with 8 GB or more VRAM makes it much faster. Since v2.3 StarkLLM also lets Ollama use integrated graphics (AMD Radeon, Intel Arc/Iris); "Use the integrated graphics for AI" in the tray menu turns this off.
  4. Indexing is slow too: every text piece of a document is sent to the embedding model.
14. The answer stays empty or the "thinking" dots never end (qwen3, deepseek-r1 and other thinking models)

Likely cause: Thinking models first think in hidden text. Up to v2.0.2 they could use the whole token limit for it and return no answer. v2.0.3 asks Ollama for the answer without the thinking step, and an empty answer is shown as an error.

What to do:

  1. Update to the latest version (Settings → About StarkLLM → Check for updates).
  2. If you want the model to think first: set the Windows environment variable OLLAMA_THINK=true, raise Max Tokens in Settings and restart StarkLLM.

Documents and answer quality

15. The assistant ignores my documents and answers from general knowledge (or invents something)

Likely cause: In v2.0.0 the document search started only when the message contained an English trigger word such as document or file. Since v2.0.1 the documents of the workspace are searched for every question. If it still happens, the question and the document usually use different words or languages.

What to do:

  1. Update to the latest version (Settings → About StarkLLM → Check for updates).
  2. Ask in the language of the document and use the words the document uses.
  3. Always check that the answer names a source file. No source file means your documents were not used.
16. A file will not upload or ends with the status "failed"

Likely cause: The file type is not supported, the file is empty or damaged, or it is larger than 100 MB (500 MB for a recording).

What to do:

  1. Supported: documents PDF, DOCX, XLSX, PPTX, EPUB, TXT, MD, CSV, JSON, XML, HTML, logs and images (PNG, JPG, WEBP, TIFF), up to 100 MB; recordings MP3, M4A, WAV, OGG, FLAC, the sound of MP4, MOV and MKV videos and more, up to 500 MB.
  2. Open the file on your PC first; a damaged PDF also fails here.
  3. Scanned PDFs and images need text recognition (OCR) and are slower; prefer the original text file when you have it.
  4. Rename-only tricks (for example .exe to .txt) do not help.
17. A CSV, Excel or JSON file shows "indexed", but nothing in it is ever found (also tables inside Word files)

Likely cause: This was a v2.0.0 problem: these files were marked as indexed with nothing in the index. Since v2.0.1 CSV, XLSX, JSON, XML, logs, Markdown and tables inside Word files are indexed (checked with a test file of each type).

What to do:

  1. Update to the latest version (Settings → About StarkLLM → Check for updates) and upload the file again.
  2. Test every new file with a question whose answer you know before you rely on it.
18. The answer says "not found in the documents", but the fact is in the document

Likely cause: Retrieval picks only a few passages. It can miss a fact when the question uses other words, when the question is in another language than the document (a question in English about a German contract is often not found), or when a long file without sentences or punctuation (for example a machine log) was indexed.

What to do:

  1. Ask in the language of the document and use the exact term, number or ID that appears in it.
  2. Make the question more specific (name the file, the section or the model number).
  3. For long logs or tables, split the file into smaller files by period or topic.
  4. The answer cites its source file; open it and check.
19. The answer mixes an old and a new version of a document

Likely cause: All uploaded documents of a workspace are searched together. Without a date or a "replaced" note, the model cannot know which version is valid.

What to do:

  1. Delete outdated documents from the workspace, or keep old versions in a separate workspace.
  2. Put the validity in the text ("valid from ...", "replaced by ...").
  3. Ask explicitly: "According to the 2026 contract ...".
20. Names, numbers or similar part numbers are mixed up

Likely cause: A 7B model running locally can confuse look-alike values (for example FT-48 and FT-480) or calculate wrongly. In our own tests the same question was answered correctly in some runs and wrongly in others.

What to do:

  1. For anything important, open the cited source and check the number yourself.
  2. Ask one question at a time and name the exact model or part number.
  3. A larger model (qwen2.5:14b, needs about 10 GB of RAM) is more reliable if your PC can run it.
21. Summaries leave out important points, or answers in languages other than English and German read poorly

Likely cause: Small models summarise loosely and are weaker outside English and German.

What to do:

  1. Name the points you need: "Summarise in three points: duration, price, notice period".
  2. Use a larger model for these tasks.
  3. Write the question in the language of the document; the answer follows the language of your question.
22. A document contains instructions ("ignore all previous instructions ...")

Likely cause: Text inside documents can try to steer the model (prompt injection). In our test the model ignored such a sentence and answered the real question, but there is no guarantee.

What to do:

  1. Only index documents you trust.
  2. Treat answers that come from documents of unknown origin with care.

Account, data and removal

23. I forgot my password

Likely cause: On your own PC, StarkLLM signs you in as the user of this PC without a password (since v2.0.7); this problem only concerns accounts that have a password. StarkLLM has no password reset yet (only "Change Password" while logged in).

What to do:

  1. Try the passwords you normally use.
  2. As a last resort register a new account. Its workspaces are separate: the old account keeps its data in the same data folder but you cannot open it.
24. Where is my data? How do I back it up?

Likely cause: Everything stays on your PC.

What to do:

  1. Desktop app: the database, search index and uploaded files are in %APPDATA%\StarkLLM\data; your Knowledge Base folder is Documents\StarkLLM Knowledge Base. From source: data\ and knowledge_base_data\ inside the project folder.
  2. Settings has a backup and restore function. Since v2.0.1 only the first account (the administrator) can use it; a backup contains the data of all accounts, so store it safely.
  3. Quit StarkLLM before you copy the folders by hand.
25. How do I stop or uninstall StarkLLM?

Likely cause: StarkLLM and Ollama are separate programs, and each one is removed on its own.

What to do:

  1. Stop: choose "Quit StarkLLM" in the tray menu; the engine stops with it. Ollama keeps running in its own tray icon until you quit it there.
  2. Remove the program: Windows Settings > Apps > StarkLLM. Your data in %APPDATA%\StarkLLM\data stays until you delete that folder yourself.
  3. Free disk space: ollama rm <name> removes a model. If you used the Docker Desktop engine before 2.2, docker image prune -a removes its old images.
  4. ollama list
ollama rm qwen2.5:7b

Web tasks, Terminal and phone

26. The phone cannot pair or connect with the PC

Likely cause: The phone link is off, the phone is not on the same home network and is not allowed away from home, or Windows Firewall blocks StarkLLM. Without "Also away from home (through the relay)" the phone reaches the PC on the home network only.

What to do:

  1. On the PC, open Settings › Phone, turn the link on and show the QR code; scan it with the StarkLLM app within 5 minutes (a code works once).
  2. Pairing works at home only: phone and PC must be on the same home network (Wi-Fi).
  3. Over mobile data or another Wi-Fi, the phone reaches the PC only if "Also away from home (through the relay)" is on for it in Settings › Phone, the PC is on and StarkLLM runs. The phone then shows "Connected · away from home".
  4. If Windows asks whether StarkLLM may be reached on networks, allow private networks only. StarkLLM never changes the firewall itself.
  5. "Fully offline" closes the link; turn it off to use the phone.
  6. Every connection attempt is listed in Settings › Privacy & network.
27. A web task or a Terminal task stops early or gets little done

Likely cause: Web tasks and Terminal need a model that can plan several steps. Small 7B models stop safely but finish few tasks.

What to do:

  1. Choose a local model of 14B or more for these tasks, for example qwen3:14b, if your PC has enough memory.
  2. Describe the task in one or two clear sentences and name the website or the file.
  3. Sign-ins, payments and "are you a robot" checks are always yours: do them in the StarkLLM window, then press Continue.
  4. ollama list
ollama pull qwen3:14b

Still stuck? Send us this

Run these commands in PowerShell and send the output with a short description of what you did and what you saw. The last command prints the end of the engine log. Remove anything private first.

winver
ollama --version
ollama list
ollama ps
Get-Content "$env:APPDATA\StarkLLM\engine-native.log" -Tail 100

Write to info@starkllm.com or open an issue on GitHub. Please tell us your Windows version, the amount of RAM and whether you have an NVIDIA GPU.

Known limits of v2.6.0

We prefer to say this openly:

The first start takes long
About 5 GB of AI models are downloaded (internet needed); the engine comes with the installer. Ollama is installed once, by StarkLLM or by you.
Answers can be wrong
The default 7B model can confuse similar values, miscalculate or miss a fact. Always check the cited source for important decisions.
Questions in another language than the document
A question in English about a German document is often not answered, because the embedding model is strongest in English. Ask in the document language.
The first image downloads the image model
When you add the first PNG or JPG (or a scanned PDF page), StarkLLM downloads the image model llava (about 4.4 GB) once. The document shows "Embedding" until it is done.
Long files without punctuation
Logs and similar files can be indexed as very large pieces, so single values inside are hard to find.
Old and new versions
The assistant does not know which document version is valid unless the text says so.
Not tested on every Windows PC
We could not test every Windows PC; tell us at info@starkllm.com if a step fails on your PC.
Background services
When you quit StarkLLM, its engine stops too. Ollama keeps running in its own tray icon until you quit it. With the Docker Desktop engine (advanced), the engine keeps running in Docker after you close the window.
Running code in the chat
"Run" on Python code blocks is off in the built-in engine until StarkLLM has its own sandbox; with the Docker Desktop engine (advanced) it works as before.
One administrator per installation
The first account can back up the whole database, including the documents of other accounts. Share an installation only with people you trust.
No password reset
See problem 23.
Speed
CPU-only PCs are slow; see problem 13.
Web tasks and Terminal need a larger model
They work best with a local model of 14B or more (for example qwen3:14b); small 7B models stop safely but finish few tasks. See problem 27.
The phone app is a preview
The Android app is on Google Play in a test phase. If you would like it from Google Play, send your e-mail address to info@starkllm.com, and you will receive the link to Google Play. It works on your home network and, only for a phone you allow, away from home through the StarkLLM relay (encrypted from the phone to the PC). See problem 26.
The first recording downloads a speech model
The first recording you add downloads Whisper large-v3-turbo once (about 1.6 GB). Fully offline, the smaller dictation model is used.
Terminal commands are not in the network list
A command you allow in Terminal (for example npm install or git push) and a tool server you add run as your own programs. Their connections are not listed in Settings › Privacy & network; while StarkLLM is fully offline, commands that use the internet are refused.

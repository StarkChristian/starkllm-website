Help & Troubleshooting

If StarkLLM does not start or an answer looks wrong, start here. Every step has a test, so you can see which part is missing.

Jump to: Checklist · Problems · Get help · Limits

How the pieces fit together

StarkLLM is not one program. Four parts work together, and the desktop window is only the last one:

Docker Desktop

Runs the StarkLLM services (backend and web interface) in the background.

Ollama

Runs the language model and the embedding model on your own PC. Nothing is sent to the internet.

The StarkLLM project folder

Contains docker-compose.yml and the launchers (start.exe, start.cmd). Starting it brings the services up.

The desktop window (StarkLLM.exe)

Only displays the web interface at http://localhost:5173. It does not start Docker, Ollama or the services. You can also open that address in any browser.

So the desktop installer on its own is not enough. If you installed only StarkLLM-Setup.exe, the window will stay on "Connecting to local engine..." until the other three parts are running.

Honest note: the steps were assembled from the launcher scripts and from real test runs on Linux with Docker and Ollama. We could not test every Windows PC. If something here does not match what you see, tell us at info@starkllm.com and we will fix this page.

Install checklist with a test for every step

Do the steps in this order. Do not continue until the test of a step passes. Open a terminal (Windows Terminal or Command Prompt) for the commands.

  1. 1. Virtualization and WSL2Docker Desktop needs hardware virtualization and WSL2 on Windows 10/11.
    wsl --status
    Test: the output shows "Default Version: 2". If WSL is missing run wsl --install and restart. In Task Manager > Performance > CPU, "Virtualization" must say Enabled; if not, enable it in the BIOS/UEFI (often called Intel VT-x, SVM or AMD-V).
  2. 2. Docker DesktopInstall Docker Desktop, start it and wait until it reports that the engine is running (steady whale icon in the tray). Use Linux containers, not Windows containers.
    docker info
    Test: the output contains a "Server:" section. If you only see "error during connect ... dockerDesktopLinuxEngine", Docker Desktop is not running yet.
  3. 3. OllamaInstall Ollama from ollama.com and make sure it is running (icon in the tray).
    ollama --version
curl http://localhost:11434/api/tags
    Test: the second command prints JSON (a list of models, possibly empty).
  4. 4. The two modelsThe default setup uses a 7B chat model and a small embedding model. Together about 5 GB of download.
    ollama pull qwen2.5:7b
ollama pull nomic-embed-text
ollama list
    Test: ollama list shows both. Short on memory (8 GB PC)? Use qwen2.5:3b instead and select it in the chat. Old copies of the instructions mention qwen3 models; ignore them (see problem 5 below).
  5. 5. Download the project and start the servicesOn the GitHub page of the project choose Code > Download ZIP and extract it completely, for example to C:\StarkLLM. Open a terminal in that folder (type cmd in the address bar of File Explorer) and start:
    start.exe
:: or, if SmartScreen blocks start.exe
start.cmd
:: or by hand
docker compose up --build -d
    Test: docker compose ps lists two containers (starkllm-backend, starkllm-frontend) as running, and http://localhost:8000/health answers {"status":"ok",...}. The first start builds the images and can take 5 to 15 minutes.
  6. 6. Open StarkLLMOpen http://localhost:5173 in a browser, or start the desktop window (StarkLLM.exe). Register an account.Test: you see the login page, can create a workspace and upload a small text file; its status changes to "indexed". Then ask a question about it.

Problems and what to do

Click a problem to see the likely cause and the fix. They are ordered the way people usually meet them.

Installing and starting

1. Windows says "Windows protected your PC" (SmartScreen)

Likely cause: The installer, the portable app and start.exe are not code-signed, and files from the internet carry a Mark of the Web.

What to do:

  1. Click More info, then Run anyway.
  2. Optional: compare the SHA-256 hash with the one on the download page first.
  3. If scripts are blocked, run the unblock script from the project folder (see below).
  4. powershell -ExecutionPolicy Bypass -File unblock.ps1
2. "error during connect ... dockerDesktopLinuxEngine: The system cannot find the file specified"

Likely cause: Docker Desktop is installed but not running yet (or still starting).

What to do:

  1. Start Docker Desktop from the Start menu and wait until the engine is running.
  2. Run docker info again; it must show a Server: section.
  3. If it never starts: restart the PC, update WSL (wsl --update) and check problem 3.
  4. docker info
3. "WSL 2 installation is incomplete" or "Hardware assisted virtualization ... must be enabled in the BIOS"

Likely cause: WSL2 or the virtual machine platform is not installed, or virtualization is switched off in the BIOS/UEFI. In a virtual machine, nested virtualization must be enabled too.

What to do:

  1. Run wsl --install in an administrator terminal and restart.
  2. Enable Intel VT-x / AMD SVM in the BIOS/UEFI if Task Manager shows Virtualization: Disabled.
  3. Windows 10/11 Home works with the WSL2 backend; Hyper-V is not required.
  4. wsl --install
wsl --update
4. docker compose fails with: could not select device driver "nvidia" with capabilities: [[gpu]]

Likely cause: Older copies of the project (a ZIP from before the fix in pull request #1 on GitHub) contain a GPU reservation in docker-compose.yml. The backend does not use the GPU (Ollama does), so it is not needed and fails on PCs without the NVIDIA container toolkit.

What to do:

  1. Open docker-compose.yml and delete the whole "deploy:" block (the lines with resources, reservations, devices, driver: nvidia), then start again. Newer copies of the project no longer contain it.
  2. docker compose up --build -d
5. "pull model manifest: file does not exist", "model not found", or the PC freezes because the model is far too big

Likely cause: Old copies of start-here.txt, start.cmd and .env.example told you to pull qwen3.8:27b and qwen3-embedding:0.6b. A 27B model needs about 17 GB of free memory, and the embedding model does not match the default one the app expects.

What to do:

  1. Use the models of the default setup:
  2. ollama pull qwen2.5:7b
ollama pull nomic-embed-text
docker compose up -d --force-recreate
  3. If you changed DEFAULT_TEXT_MODEL or DEFAULT_EMBEDDING_MODEL in .env, set them back to qwen2.5:7b and nomic-embed-text, then recreate the containers.
  4. Documents indexed with a different embedding model must be uploaded again (the vectors have a different size).
6. "Bind for 127.0.0.1:8000 failed: port is already allocated" (or 5173)

Likely cause: Another program already uses port 8000 (backend) or 5173 (web interface).

What to do:

  1. Find the program, then close it:
  2. netstat -ano | findstr :8000
tasklist /FI "PID eq <number from the last column>"
  3. Or move StarkLLM to other ports: in docker-compose.yml change the left number of the ports lines (for example "127.0.0.1:8001:8000" and "127.0.0.1:5174:80").
  4. If you moved the web interface, tell the desktop window: setx STARKLLM_URL http://localhost:5174 and start the window again.
  5. Note: BACKEND_PORT and FRONTEND_PORT in .env.example are not read by docker-compose.yml in v2.0.0; editing them has no effect.
7. The first start takes very long or ends with an error while building

Likely cause: The backend image is large (about 4.4 GB) and is built on your PC. Slow internet, a company proxy, a VPN, antivirus scanning or a nearly full disk make it slower or stop it.

What to do:

  1. Keep at least 15 GB of free disk space (images 4.5 GB, models 5 GB, Docker overhead).
  2. Watch the progress instead of waiting blindly:
  3. docker compose logs -f backend
  4. Behind a proxy: set it in Docker Desktop > Settings > Resources > Proxies. Errors such as "failed to resolve source metadata" or TLS errors point to a blocked network; try another network.
  5. After fixing the cause, run the start command again; finished layers are reused.
8. The desktop window stays on "Connecting to local engine..." and then goes blank

Likely cause: The window only displays http://localhost:5173. The services are not running (it does not start them), or they are still starting.

What to do:

  1. Run docker compose ps in the project folder; both containers must be "running".
  2. Start them with start.exe, start.cmd or docker compose up -d, wait 1 to 2 minutes and try again.
  3. Open http://localhost:5173 in a browser. If the browser works but the window does not, close the window (also in the tray) and start it again.
  4. docker compose ps
curl http://localhost:8000/health
9. The browser shows "502 Bad Gateway" or an empty page at localhost:5173

Likely cause: The web interface is up, but the backend is still starting or has crashed.

What to do:

  1. Wait one or two minutes after a start, then reload.
  2. Read the last lines of the backend log; the error is usually in the last 20 lines.
  3. Restart only the backend.
  4. docker compose logs --tail 50 backend
docker compose restart backend

Using chat and models

10. "Model ... not found in Ollama. Please ensure it is pulled"

Likely cause: The chat asks for a model that is not installed (the default is qwen2.5:7b).

What to do:

  1. List the installed models and pull the missing one, or pick an installed model in the model selector of the chat.
  2. ollama list
ollama pull qwen2.5:7b
11. "Error generating response: 500 Server Error ..." or the answer never comes

Likely cause: In v2.0.0 this almost always means that the model did not fit into the free memory and Ollama stopped it. A 7B model needs about 5 to 6 GB of free RAM; with too little memory Windows also gets very slow.

What to do:

  1. Close browsers, games and other large programs and try again.
  2. Choose a smaller model, for example qwen2.5:3b (about 2 GB), and select it in the chat.
  3. Check what Ollama has loaded.
  4. The raw "500 Server Error" text is not very helpful, but out of memory is by far the most common reason for it.
  5. ollama pull qwen2.5:3b
ollama ps
12. "Cannot connect to Ollama" or chat does not answer at all

Likely cause: Ollama is not running, or a firewall blocks the connection from the Docker container to the PC. The backend reaches Ollama at host.docker.internal:11434.

What to do:

  1. Start Ollama and check it from the PC:
  2. curl http://localhost:11434/api/tags
docker compose restart backend
  3. Allow Docker Desktop and Ollama in your firewall or security software.
  4. Restart the containers afterwards.
13. Answers are very slow

Likely cause: Without a suitable GPU Ollama computes on the CPU. The first answer also has to load the model (in our test about 20 seconds). On a 16-core desktop a short answer took roughly 10 to 40 seconds; laptops are slower.

What to do:

  1. Use a smaller model (qwen2.5:3b) on weak PCs.
  2. Ask short, specific questions; long answers cost the most time.
  3. A dedicated NVIDIA GPU with 8 GB or more VRAM makes it much faster.
  4. Indexing is slow too: every text piece of a document is sent to the embedding model.

Documents and answer quality

14. The assistant ignores my documents and answers from general knowledge (or invents something)

Likely cause: In v2.0.0 the document search starts only when your message contains one of a list of English trigger words (for example document, file, pdf, uploaded, report, summary, according to). A question such as "Wie hoch ist die Nennlast?" has none of them, so the model answers on its own. In our test it then made answers up (it called the FT-480 conveyor a boat engine), and the answer shows no source file.

What to do:

  1. Add an English trigger word to the question; the rest of the question can be in any language: "According to the document: Wie hoch ist die Nennlast des FT-480?" or "... (see the file)". German words such as "Dokument" are not on the list and do not work.
  2. Always check that the answer names a source file. No source file means your documents were not used.
  3. A fix that searches your documents for every question as soon as documents are indexed is in preparation. Until it is released, use the trigger word.
15. A file will not upload or ends with the status "failed"

Likely cause: The file type is not supported, the file is empty or damaged, or it is larger than 100 MB.

What to do:

  1. Supported: PDF, DOCX, XLSX, TXT, MD, CSV, JSON, HTML, PNG, JPG.
  2. Open the file on your PC first; a damaged PDF also fails here.
  3. Scanned PDFs and images need text recognition (OCR) and are slower; prefer the original text file when you have it.
  4. Rename-only tricks (for example .exe to .txt) do not help.
16. A CSV, Excel or JSON file shows "indexed", but nothing in it is ever found (also tables inside Word files)

Likely cause: In v2.0.0 these file types are accepted but produce no searchable text: the file is marked as indexed with nothing in the index, and tables inside DOCX files are skipped. In our test the prices of a CSV price list were never found.

What to do:

  1. Copy the rows into a text file (.txt or .md) or export the sheet to PDF, and upload that instead.
  2. Move the content of Word tables into normal paragraphs.
  3. Test every new file with a question whose answer you know before you rely on it.
  4. A fix that indexes CSV, XLSX, JSON and Word tables is in preparation.
17. The answer says "not found in the documents", but the fact is in the document

Likely cause: Retrieval picks only a few passages. It can miss a fact when the question uses other words, when the question is in another language than the document (a question in English about a German contract is often not found), or when a long file without sentences or punctuation (for example a machine log) was indexed.

What to do:

  1. Ask in the language of the document and use the exact term, number or ID that appears in it.
  2. Make the question more specific (name the file, the section or the model number).
  3. For long logs or tables, split the file into smaller files by period or topic.
  4. The answer cites its source file; open it and check.
18. The answer mixes an old and a new version of a document

Likely cause: All uploaded documents of a workspace are searched together. Without a date or a "replaced" note, the model cannot know which version is valid.

What to do:

  1. Delete outdated documents from the workspace, or keep old versions in a separate workspace.
  2. Put the validity in the text ("valid from ...", "replaced by ...").
  3. Ask explicitly: "According to the 2026 contract ...".
19. Names, numbers or similar part numbers are mixed up

Likely cause: A 7B model running locally can confuse look-alike values (for example FT-48 and FT-480) or calculate wrongly. In our own tests the same question was answered correctly in some runs and wrongly in others.

What to do:

  1. For anything important, open the cited source and check the number yourself.
  2. Ask one question at a time and name the exact model or part number.
  3. A larger model (qwen2.5:14b, needs about 10 GB of RAM) is more reliable if your PC can run it.
20. Summaries leave out important points, or answers in Persian or other non-English languages read poorly

Likely cause: Small models summarise loosely and are weaker outside English and German.

What to do:

  1. Name the points you need: "Summarise in three points: duration, price, notice period".
  2. Use a larger model for these tasks.
  3. Write the question in the language of the document; the answer follows the language of your question.
21. A document contains instructions ("ignore all previous instructions ...")

Likely cause: Text inside documents can try to steer the model (prompt injection). In our test the model ignored such a sentence and answered the real question, but there is no guarantee.

What to do:

  1. Only index documents you trust.
  2. Treat answers that come from documents of unknown origin with care.

Account, data and removal

22. I forgot my password

Likely cause: Version 2.0.0 has no password reset (only "change password" while logged in).

What to do:

  1. Try the passwords you normally use.
  2. As a last resort register a new account. Its workspaces are separate: the old account keeps its data in the same data folder but you cannot open it.
23. Where is my data? How do I back it up?

Likely cause: Everything stays on your PC.

What to do:

  1. The folder data\ inside the project folder holds the database, the search index and the uploaded files; knowledge_base_data\ holds your Knowledge Base files.
  2. Settings has a backup and restore function. In v2.0.0 every account on the installation can use it, and a backup contains the data of all accounts. Keep one installation for one person and store backups safely.
  3. Stop the services before you copy the folders by hand: docker compose down.
  4. docker compose down
24. How do I stop or uninstall StarkLLM?

Likely cause: There are several separate parts, and each one is removed on its own.

What to do:

  1. Stop: docker compose down (your data in data\ stays).
  2. Remove the program: Windows Settings > Apps > StarkLLM. Delete the project folder only when you no longer need your data.
  3. Free disk space: docker image prune -a removes unused images; ollama rm <name> removes a model.
  4. docker compose down
docker image prune -a
ollama rm qwen2.5:7b

Still stuck? Send us this

Run these commands in the project folder and send the output with a short description of what you did and what you saw. Remove anything private first.

winver
wsl --status
docker version
docker compose ps
docker compose logs --tail 100 backend
ollama list
ollama ps

Write to info@starkllm.com or open an issue on GitHub. Please tell us your Windows version, the amount of RAM and whether you have an NVIDIA GPU.

Known limits of v2.0.0

We prefer to say this openly:

  • The desktop app does not start the services: You start Docker, Ollama and the project yourself (see the checklist).
  • Answers can be wrong: The default 7B model can confuse similar values, miscalculate or miss a fact. Always check the cited source for important decisions.
  • Questions in another language than the document: A question in English about a German document is often not answered, because the embedding model is strongest in English. Ask in the document language.
  • Long files without punctuation: Logs and similar files can be indexed as very large pieces, so single values inside are hard to find.
  • Old and new versions: The assistant does not know which document version is valid unless the text says so.
  • Documents are searched only with a trigger word: Until the fix is released, add an English word such as "document" or "file" to your question (see problem 14).
  • CSV, Excel, JSON and Word tables are not searchable: Until the fix is released, convert them to text or PDF (see problem 16).
  • One person per installation: Every account can create a backup of the whole database, so do not share one installation between people who must not see each other's documents.
  • No password reset, unsigned programs: See problems 1 and 22.
  • Speed: CPU-only PCs are slow; see problem 13.

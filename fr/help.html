Aide et dépannage

Si StarkLLM ne démarre pas ou si une réponse vous paraît fausse, commencez ici. Chaque étape comporte un test, ce qui vous permet de voir quel élément manque.

Comment les éléments s’articulent

StarkLLM n’est pas un seul programme. Deux éléments travaillent ensemble, et l’application de bureau démarre l’autre à votre place :

L’application StarkLLM (StarkLLM.exe)

Contient le moteur (base de données, index de recherche, backend et interface web) et, depuis la v2.2, l’exécute directement sous Windows : ni Docker Desktop, ni WSL2. À chaque démarrage, elle vérifie Ollama, télécharge les modèles manquants, démarre le moteur, puis affiche StarkLLM. Si un élément manque, elle dit lequel et comment y remédier. Quand vous quittez StarkLLM, le moteur s’arrête aussi.

Ollama

Fait tourner le modèle de langage et le modèle d’embedding sur votre propre PC. Vos documents et vos questions restent sur votre PC ; Ollama lui-même ne se connecte à internet que pour télécharger des modèles et pour sa propre vérification des mises à jour. Si Ollama manque, StarkLLM propose « Installer Ollama pour moi » et installe la version officielle et signée ; il démarre ensuite Ollama et télécharge les modèles.

Docker Desktop (facultatif, avancé)

Plus nécessaire depuis la v2.2. Si vous le préférez, choisissez « Utiliser Docker Desktop pour le moteur (avancé) » dans le menu de la zone de notification ; StarkLLM fait alors tourner son moteur dans Docker Desktop, avec les mêmes données.

À partir des sources (facultatif)

Les développeurs peuvent construire et lancer le moteur à partir du code source sur GitHub avec docker compose up --build -d.

Les versions antérieures à la 2.2 avaient besoin de Docker Desktop et de WSL2, et la v2.0.0 (avant le 24 octobre 2026) ne démarrait rien du tout. Veuillez installer la v2.6.0.

Remarque honnête : ces étapes ont été établies à partir des vérifications que l’application effectue à chaque démarrage et de vrais essais. Nous n’avons pas pu tester tous les PC Windows. Si quelque chose ici ne correspond pas à ce que vous voyez, dites-le-nous à info@starkllm.com et nous corrigerons cette page.

Liste de contrôle d’installation, avec un test pour chaque étape

Suivez les étapes dans cet ordre. Ne passez pas à la suivante tant que le test d’une étape n’est pas réussi. Ouvrez un terminal (Windows Terminal ou PowerShell) pour les commandes.

  1. 1. Windows et espace disqueStarkLLM fonctionne sous Windows 10 ou 11 (64 bits). Docker Desktop et WSL2 ne sont pas nécessaires. Gardez au moins 15 Go d’espace disque libre pour l’application, le moteur et les modèles d’IA.
    winver
    Test : winver affiche Windows 10 ou Windows 11. Dans l’Explorateur de fichiers, le lecteur qui contient votre dossier utilisateur (en général C:) dispose d’au moins 15 Go libres.
  2. 2. Installer et lancer StarkLLMTéléchargez StarkLLM-v2.6.0-Setup.exe depuis la page de téléchargement, installez-le et lancez StarkLLM. Le moteur fait partie de l’installeur.Test : la fenêtre de StarkLLM s’ouvre et affiche la progression du démarrage. Si elle indique « StarkLLM n’a pas pu démarrer », elle liste ce qui manque et propose un bouton « Réessayer ».
  3. 3. OllamaSi Ollama manque, la fenêtre propose « Installer Ollama pour moi » : StarkLLM télécharge l’installeur officiel depuis ollama.com (environ 2 Go), vérifie sa signature et l’installe ; aucun droit d’administrateur n’est nécessaire. Vous pouvez aussi installer Ollama vous-même depuis ollama.com.
    ollama --version
curl http://localhost:11434/api/tags
    Test : la deuxième commande affiche du JSON (une liste de modèles, éventuellement vide).
  4. 4. Les deux modèlesAu premier démarrage, StarkLLM télécharge un modèle de discussion et un petit modèle d’embedding (par défaut qwen2.5:7b et nomic-embed-text, environ 5 Go en tout) et affiche la progression. Les modèles adaptés que vous avez déjà dans Ollama sont utilisés à la place.
    ollama list
    Test : ollama list affiche un modèle de discussion et un modèle d’embedding. Si un téléchargement a échoué, la fenêtre nomme le modèle : exécutez ollama pull avec ce nom et cliquez sur « Réessayer ». Peu de mémoire (PC de 8 Go) ? Utilisez qwen2.5:3b et sélectionnez-le dans la discussion.
  5. 5. Premier testStarkLLM vous connecte en tant qu’utilisateur de ce PC ; aucun compte n’est à créer.Test : vous pouvez créer un espace de travail et ajouter un petit fichier texte ; son statut passe à « indexed ». Posez ensuite une question à son sujet et vérifiez que la réponse nomme le fichier.

Problèmes et que faire

Cliquez sur un problème pour voir la cause probable et la solution. Ils sont classés dans l’ordre où on les rencontre le plus souvent.

Installation et démarrage

1. Windows affiche « Windows a protégé votre ordinateur » (SmartScreen) ou Smart App Control bloque l’installeur

Cause probable: Depuis la v2.1.2, l’installeur, StarkLLM.exe et le programme de désinstallation sont signés par « Open Source Developer Christian Stark », afin que Windows puisse vérifier l’éditeur. Windows peut quand même afficher un avertissement pour un fichier qu’il a rarement vu. Les versions antérieures à la v2.1.2 n’étaient pas signées.

Que faire:

  1. Vérifiez l’éditeur : clic droit sur l’installeur, « Propriétés » (Properties), onglet « Signatures numériques » (Digital Signatures). Le signataire doit être « Open Source Developer Christian Stark », et « Détails » (Details) doit indiquer « Cette signature numérique est valide » (This digital signature is OK).
  2. Comparez le hachage SHA-256 avec celui de la page de téléchargement.
  3. Si les deux correspondent, continuez (dans SmartScreen : « Informations complémentaires » (More info), puis « Exécuter quand même » (Run anyway)). Sinon, n’exécutez pas le fichier : téléchargez-le de nouveau et écrivez-nous à info@starkllm.com.
  4. Ne désactivez pas Smart App Control, SmartScreen ni les autres réglages de sécurité. Si Smart App Control bloque un installeur correctement signé, écrivez-nous à info@starkllm.com.
2. Smart App Control ou un logiciel de sécurité bloque un fichier de programme du moteur

Cause probable: Depuis la v2.2.1, chaque fichier de programme du moteur (paquets Python, Tesseract) est signé par « Open Source Developer Christian Stark », afin que Smart App Control les laisse s’exécuter. Une autre règle de contrôle des applications ou un logiciel de sécurité peut quand même bloquer un fichier ; le moteur ne démarre alors pas.

Que faire:

  1. La page de démarrage nomme le fichier bloqué et le journal du moteur (%APPDATA%\StarkLLM\engine-native.log).
  2. Ne désactivez pas Smart App Control ni votre logiciel de sécurité. Signalez le nom du fichier sur la page de StarkLLM sur GitHub ou à info@starkllm.com.
  3. En attendant une correction, vous pouvez choisir « Utiliser Docker Desktop pour le moteur (avancé) » dans le menu de la zone de notification (nécessite Docker Desktop avec WSL2).
3. « Ollama n’est pas installé » ou « Ollama n’est pas en cours d’exécution »

Cause probable: StarkLLM exécute ses modèles d’IA avec Ollama (gratuit) et s’attend à le trouver à l’adresse 127.0.0.1:11434.

Que faire:

  1. Cliquez sur « Installer Ollama pour moi » sur la page de démarrage, ou installez vous-même Ollama depuis ollama.com.
  2. Si Ollama est installé : lancez-le depuis le menu Démarrer, attendez son icône dans la zone de notification et cliquez sur « Réessayer ».
  3. Vérifiez-le depuis le PC :
  4. curl http://localhost:11434/api/tags
4. « pull model manifest: file does not exist », « model not found », ou le PC se fige parce que le modèle est beaucoup trop gros

Cause probable: Le nom du modèle n’existe pas dans Ollama, ou le modèle choisi demande bien plus de mémoire que le PC n’en a (un modèle 27B a besoin d’environ 17 Go de mémoire libre). D’anciennes copies de start-here.txt et de .env.example indiquaient qwen3.8:27b et qwen3-embedding:0.6b.

Que faire:

  1. Utilisez les modèles de la configuration par défaut :
  2. ollama pull qwen2.5:7b
ollama pull nomic-embed-text
  3. Ou choisissez un modèle installé dans le sélecteur de modèle (AI MODEL, en bas à gauche).
  4. Les documents indexés avec un autre modèle d’embedding doivent être ajoutés de nouveau (les vecteurs n’ont pas la même taille).
5. « Un autre moteur StarkLLM utilise déjà le port 5173 », ou le moteur ne démarre pas parce que le port est occupé

Cause probable: Le moteur sert l’application sur le port 5173 de votre PC (127.0.0.1). Un autre programme, ou les conteneurs StarkLLM d’une installation antérieure avec Docker Desktop, l’utilisent déjà. StarkLLM arrête lui-même ses propres anciens conteneurs ; il ne peut pas arrêter les autres programmes.

Que faire:

  1. Repérez le programme, puis fermez-le :
  2. netstat -ano | findstr :5173
tasklist /FI "PID eq <number from the last column>"
  3. Ou déplacez StarkLLM sur un autre port : exécutez setx STARKLLM_UI_PORT 5174, puis quittez StarkLLM dans le menu de la zone de notification et relancez-le.
6. Le premier démarrage est très long ou un téléchargement échoue

Cause probable: Le premier démarrage télécharge les modèles d’IA (environ 5 Go) et, si vous l’acceptez, Ollama (environ 2 Go). Une connexion internet lente, un proxy d’entreprise, un VPN, l’analyse de l’antivirus ou un disque presque plein le ralentissent ou l’arrêtent.

Que faire:

  1. Gardez au moins 15 Go d’espace disque libre (modèles environ 5 Go, plus Ollama, l’application et le moteur).
  2. La fenêtre affiche la progression de chaque téléchargement. Des erreurs TLS ou de connexion indiquent un réseau bloqué ; essayez un autre réseau.
  3. Une fois la cause corrigée, cliquez sur « Réessayer » ; les modèles déjà téléchargés ne sont pas téléchargés de nouveau.
7. La fenêtre indique « StarkLLM n’a pas pu démarrer »

Cause probable: L’application démarre elle-même Ollama et son moteur, et affiche cette page quand une étape échoue.

Que faire:

  1. Lisez la ligne rouge de la page : elle nomme l’élément manquant (Ollama, un port occupé, un fichier de programme bloqué par Windows, ou une erreur du moteur avec les dernières lignes de son journal).
  2. Corrigez cet élément et cliquez sur « Réessayer ». Les journaux se trouvent dans %APPDATA%\StarkLLM : engine.log (l’application) et engine-native.log (le moteur).
  3. Le premier démarrage après une installation ou une mise à jour peut prendre quelques minutes sur un PC très sollicité ; la fenêtre l’indique pendant l’attente.
8. La fenêtre reste vide ou affiche une page d’erreur après le démarrage

Cause probable: Le moteur est encore en cours de démarrage ou s’est arrêté.

Que faire:

  1. Attendez une ou deux minutes, puis choisissez « Recharger l’application » dans le menu de la zone de notification.
  2. Si elle reste vide, quittez StarkLLM dans le menu de la zone de notification et relancez-le.
  3. L’erreur se trouve en général dans les 20 dernières lignes du journal du moteur (ouvrez-le dans PowerShell) :
  4. notepad "$env:APPDATA\StarkLLM\engine-native.log"
9. J’utilise Docker Desktop pour le moteur (avancé) et il ne démarre pas

Cause probable: Avec « Utiliser Docker Desktop pour le moteur (avancé) » dans le menu de la zone de notification, StarkLLM a besoin de Docker Desktop avec WSL2, comme les versions antérieures à la 2.2. Les erreurs comme « error during connect ... dockerDesktopLinuxEngine » ou « WSL 2 installation is incomplete » viennent de Docker Desktop.

Que faire:

  1. Lancez Docker Desktop et attendez que son moteur fonctionne ; docker info doit afficher une section Server:.
  2. Si WSL2 manque, exécutez wsl --install dans un terminal administrateur et redémarrez ; la virtualisation doit être activée dans le BIOS/UEFI.
  3. Ou revenez au moteur intégré : décochez « Utiliser Docker Desktop pour le moteur (avancé) » dans le menu de la zone de notification. Les discussions, les documents et les paramètres sont les mêmes dans les deux cas.
  4. docker info
wsl --status

Discussion et modèles

10. « Model ... not found in Ollama. Please ensure it is pulled »

Cause probable: La discussion demande un modèle qui n’est pas installé (par défaut : qwen2.5:7b). Dans la v2.0.1, la discussion demandait llama3.2:3b à chaque nouvelle installation (« Model 'llama3.2:3b' not found ») ; la v2.0.2 utilise le modèle que l’application télécharge.

Que faire:

  1. Passez à la dernière version (Paramètres → À propos de StarkLLM → Rechercher des mises à jour), ou choisissez un modèle installé dans le sélecteur de modèle (AI MODEL, en bas à gauche).
  2. Listez les modèles installés et récupérez celui qui manque.
  3. ollama list
ollama pull qwen2.5:7b
11. « Not enough free memory to run model ... », « Error generating response: 500 Server Error ... » ou la réponse n’arrive jamais

Cause probable: Le modèle ne tenait pas dans la mémoire libre et Ollama l’a arrêté. Un modèle 7B demande environ 5 à 6 Go de RAM libre ; avec trop peu de mémoire, Windows devient aussi très lent. Depuis la v2.0.1, la discussion le dit en clair ; la v2.0.0 affichait l’erreur brute « 500 Server Error ».

Que faire:

  1. Fermez les navigateurs, les jeux et les autres gros programmes, puis réessayez.
  2. Choisissez un modèle plus petit, par exemple qwen2.5:3b (environ 2 Go), et sélectionnez-le dans la discussion.
  3. Vérifiez ce qu’Ollama a chargé.
  4. ollama pull qwen2.5:3b
ollama ps
12. « Ollama est hors ligne. » ou la discussion ne répond pas du tout

Cause probable: Ollama ne fonctionne pas, ou un logiciel de sécurité bloque la connexion vers lui. StarkLLM joint Ollama à l’adresse 127.0.0.1:11434 (avec le moteur Docker Desktop : host.docker.internal:11434).

Que faire:

  1. Démarrez Ollama et vérifiez-le depuis le PC :
  2. curl http://localhost:11434/api/tags
  3. Autorisez Ollama dans votre pare-feu ou votre logiciel de sécurité.
  4. Choisissez ensuite « Recharger l’application » dans le menu de la zone de notification, ou quittez StarkLLM et relancez-le.
13. Les réponses sont très lentes

Cause probable: Sans GPU adapté, Ollama calcule sur le processeur. La première réponse doit aussi charger le modèle (environ 20 secondes lors de notre test). Sur un PC de bureau à 16 cœurs, une réponse courte a pris environ 10 à 40 secondes ; les portables sont plus lents.

Que faire:

  1. Utilisez un modèle plus petit (qwen2.5:3b) sur les PC peu puissants.
  2. Posez des questions courtes et précises ; les longues réponses coûtent le plus de temps.
  3. Un GPU NVIDIA dédié avec 8 Go ou plus de VRAM accélère nettement les choses. Depuis la v2.3, StarkLLM permet aussi à Ollama d’utiliser la carte graphique intégrée (AMD Radeon, Intel Arc/Iris) ; « Utiliser la carte graphique intégrée pour l’IA » dans le menu de la zone de notification désactive cette option.
  4. L’indexation est lente aussi : chaque morceau de texte d’un document est envoyé au modèle d’embedding.
14. La réponse reste vide ou les points de « réflexion » ne s’arrêtent jamais (qwen3, deepseek-r1 et autres modèles à réflexion)

Cause probable: Les modèles à réflexion commencent par réfléchir dans un texte masqué. Jusqu’à la v2.0.2, ils pouvaient y consacrer toute la limite de jetons et ne renvoyer aucune réponse. La v2.0.3 demande à Ollama la réponse sans l’étape de réflexion, et une réponse vide s’affiche comme une erreur.

Que faire:

  1. Passez à la dernière version (Paramètres → À propos de StarkLLM → Rechercher des mises à jour).
  2. Si vous voulez que le modèle réfléchisse d’abord : définissez la variable d’environnement Windows OLLAMA_THINK=true, augmentez Tokens max. dans les Paramètres et redémarrez StarkLLM.

Documents et qualité des réponses

15. L’assistant ignore mes documents et répond à partir de connaissances générales (ou invente quelque chose)

Cause probable: Dans la v2.0.0, la recherche dans les documents ne se lançait que si le message contenait un mot déclencheur anglais comme document ou file. Depuis la v2.0.1, les documents de l’espace de travail sont consultés pour chaque question. Si cela arrive encore, la question et le document emploient en général des mots ou des langues différents.

Que faire:

  1. Passez à la dernière version (Paramètres → À propos de StarkLLM → Rechercher des mises à jour).
  2. Posez votre question dans la langue du document et employez les mots qu’il utilise.
  3. Vérifiez toujours que la réponse nomme un fichier source. Pas de fichier source : vos documents n’ont pas été utilisés.
16. Un fichier ne s’ajoute pas, ou se termine avec le statut « failed »

Cause probable: Le type de fichier n’est pas pris en charge, le fichier est vide ou endommagé, ou il dépasse 100 Mo (500 Mo pour un enregistrement).

Que faire:

  1. Pris en charge : documents PDF, DOCX, XLSX, PPTX, EPUB, TXT, MD, CSV, JSON, XML, HTML, journaux et images (PNG, JPG, WEBP, TIFF), jusqu’à 100 Mo ; enregistrements MP3, M4A, WAV, OGG, FLAC, le son des vidéos MP4, MOV et MKV et d’autres, jusqu’à 500 Mo.
  2. Ouvrez d’abord le fichier sur votre PC ; un PDF endommagé échoue aussi ici.
  3. Les PDF numérisés et les images nécessitent une reconnaissance de texte (OCR) et sont plus lents ; préférez le fichier texte d’origine si vous l’avez.
  4. Les simples changements de nom (par exemple .exe en .txt) n’y changent rien.
17. Un fichier CSV, Excel ou JSON affiche « indexed », mais rien de ce qu’il contient n’est jamais trouvé (y compris les tableaux dans les fichiers Word)

Cause probable: C’était un problème de la v2.0.0 : ces fichiers étaient marqués comme indexés alors que rien n’était entré dans l’index. Depuis la v2.0.1, les CSV, XLSX, JSON, XML, journaux, Markdown et tableaux des fichiers Word sont indexés (vérifié avec un fichier d’essai de chaque type).

Que faire:

  1. Passez à la dernière version (Paramètres → À propos de StarkLLM → Rechercher des mises à jour) et ajoutez de nouveau le fichier.
  2. Testez chaque nouveau fichier avec une question dont vous connaissez la réponse avant de vous y fier.
18. La réponse dit « not found in the documents », alors que l’information figure dans le document

Cause probable: La recherche ne retient que quelques passages. Elle peut manquer une information quand la question emploie d’autres mots, quand elle est posée dans une autre langue que le document (une question en anglais sur un contrat allemand ne trouve souvent rien), ou quand un long fichier sans phrases ni ponctuation (par exemple un journal machine) a été indexé.

Que faire:

  1. Posez la question dans la langue du document et employez le terme, le nombre ou l’identifiant exact qui y figure.
  2. Rendez la question plus précise (nommez le fichier, la section ou le numéro de modèle).
  3. Pour les longs journaux ou tableaux, découpez le fichier en fichiers plus petits par période ou par sujet.
  4. La réponse cite son fichier source ; ouvrez-le et vérifiez.
19. La réponse mélange une ancienne et une nouvelle version d’un document

Cause probable: Tous les documents ajoutés à un espace de travail sont consultés ensemble. Sans date ni mention « remplacé », le modèle ne peut pas savoir quelle version est valable.

Que faire:

  1. Supprimez les documents périmés de l’espace de travail, ou gardez les anciennes versions dans un espace de travail distinct.
  2. Indiquez la validité dans le texte (« valable à partir de ... », « remplacé par ... »).
  3. Demandez explicitement : « D’après le contrat de 2026 ... ».
20. Des noms, des nombres ou des références de pièces proches sont confondus

Cause probable: Un modèle 7B exécuté en local peut confondre des valeurs qui se ressemblent (par exemple FT-48 et FT-480) ou mal calculer. Lors de nos propres tests, la même question a reçu une bonne réponse dans certains essais et une mauvaise dans d’autres.

Que faire:

  1. Pour tout ce qui est important, ouvrez la source citée et vérifiez vous-même le nombre.
  2. Posez une question à la fois et nommez le modèle ou la référence exacte.
  3. Un modèle plus grand (qwen2.5:14b, environ 10 Go de RAM) est plus fiable si votre PC peut l’exécuter.
21. Les résumés omettent des points importants, ou les réponses dans des langues autres que l’anglais et l’allemand se lisent mal

Cause probable: Les petits modèles résument de façon approximative et sont plus faibles en dehors de l’anglais et de l’allemand.

Que faire:

  1. Nommez les points dont vous avez besoin : « Résume en trois points : durée, prix, délai de préavis ».
  2. Utilisez un modèle plus grand pour ces tâches.
  3. Rédigez la question dans la langue du document ; la réponse suit la langue de votre question.
22. Un document contient des instructions (« ignore all previous instructions ... »)

Cause probable: Le texte d’un document peut tenter d’orienter le modèle (injection d’instructions, ou prompt injection). Lors de notre test, le modèle a ignoré cette phrase et répondu à la vraie question, mais il n’y a aucune garantie.

Que faire:

  1. N’indexez que des documents en lesquels vous avez confiance.
  2. Traitez avec prudence les réponses issues de documents d’origine inconnue.

Compte, données et désinstallation

23. J’ai oublié mon mot de passe

Cause probable: Sur votre propre PC, StarkLLM vous connecte sans mot de passe en tant qu’utilisateur de ce PC (depuis la v2.0.7) ; ce problème ne concerne que les comptes qui ont un mot de passe. StarkLLM n’a pas encore de réinitialisation du mot de passe (seulement « Changer le mot de passe » quand on est connecté).

Que faire:

  1. Essayez les mots de passe que vous utilisez d’habitude.
  2. En dernier recours, créez un nouveau compte. Ses espaces de travail sont distincts : l’ancien compte garde ses données dans le même dossier de données, mais vous ne pouvez pas l’ouvrir.
24. Où sont mes données ? Comment les sauvegarder ?

Cause probable: Tout reste sur votre PC.

Que faire:

  1. Application de bureau : la base de données, l’index de recherche et les fichiers ajoutés se trouvent dans %APPDATA%\StarkLLM\data ; votre dossier de base de connaissances est Documents\StarkLLM Knowledge Base. À partir des sources : data\ et knowledge_base_data\ dans le dossier du projet.
  2. Les Paramètres comportent une fonction de sauvegarde et de restauration. Depuis la v2.0.1, seul le premier compte (l’administrateur) peut l’utiliser ; une sauvegarde contient les données de tous les comptes : conservez-la en lieu sûr.
  3. Quittez StarkLLM avant de copier les dossiers à la main.
25. Comment arrêter ou désinstaller StarkLLM ?

Cause probable: StarkLLM et Ollama sont des programmes distincts, et chacun se supprime séparément.

Que faire:

  1. Arrêter : choisissez « Quitter StarkLLM » dans le menu de la zone de notification ; le moteur s’arrête avec lui. Ollama continue de tourner avec sa propre icône dans la zone de notification, jusqu’à ce que vous le quittiez à cet endroit.
  2. Supprimer le programme : Paramètres Windows > Applications > StarkLLM. Vos données dans %APPDATA%\StarkLLM\data restent jusqu’à ce que vous supprimiez vous-même ce dossier.
  3. Libérer de l’espace disque : ollama rm <nom> supprime un modèle. Si vous utilisiez le moteur Docker Desktop avant la 2.2, docker image prune -a supprime ses anciennes images.
  4. ollama list
ollama rm qwen2.5:7b

Tâches web, Terminal et téléphone

26. Le téléphone ne s’associe pas ou ne se connecte pas au PC

Cause probable: La liaison avec le téléphone est désactivée, le téléphone n’est pas sur le même réseau domestique et n’est pas autorisé hors de chez vous, ou le pare-feu Windows bloque StarkLLM. Sans « Aussi hors de chez vous (via le relais) », le téléphone n’atteint le PC que sur le réseau domestique.

Que faire:

  1. Sur le PC, ouvrez Paramètres › Téléphone, activez la liaison et affichez le code QR ; scannez-le avec l’application StarkLLM dans les 5 minutes (un code ne sert qu’une fois).
  2. L’association se fait uniquement à la maison : le téléphone et le PC doivent être sur le même réseau domestique (Wi-Fi).
  3. Par les données mobiles ou un autre Wi-Fi, le téléphone n’atteint le PC que si « Aussi hors de chez vous (via le relais) » est activé pour lui dans Paramètres › Téléphone, que le PC est allumé et que StarkLLM tourne. Le téléphone affiche alors « Connecté · hors de chez vous ».
  4. Si Windows demande si StarkLLM peut être joint sur les réseaux, autorisez uniquement les réseaux privés. StarkLLM ne modifie jamais le pare-feu lui-même.
  5. « Entièrement hors ligne » ferme la liaison ; désactivez-le pour utiliser le téléphone.
  6. Chaque tentative de connexion figure dans Paramètres › Confidentialité et réseau.
27. Une tâche web ou une tâche du Terminal s’arrête tôt ou aboutit à peu de chose

Cause probable: Les tâches web et le Terminal ont besoin d’un modèle capable de planifier plusieurs étapes. Les petits modèles 7B s’arrêtent sans risque, mais terminent peu de tâches.

Que faire:

  1. Choisissez pour ces tâches un modèle local de 14B ou plus, par exemple qwen3:14b, si votre PC a assez de mémoire.
  2. Décrivez la tâche en une ou deux phrases claires et nommez le site web ou le fichier.
  3. Les connexions, les paiements et les vérifications « êtes-vous un robot ? » restent toujours entre vos mains : faites-les dans la fenêtre de StarkLLM, puis appuyez sur Continuer.
  4. ollama list
ollama pull qwen3:14b

Toujours bloqué ? Envoyez-nous ceci

Exécutez ces commandes dans PowerShell et envoyez-nous leur sortie, avec une courte description de ce que vous avez fait et de ce que vous avez vu. La dernière commande affiche la fin du journal du moteur. Retirez d’abord tout ce qui est privé.

winver
ollama --version
ollama list
ollama ps
Get-Content "$env:APPDATA\StarkLLM\engine-native.log" -Tail 100

Écrivez à info@starkllm.com ou ouvrez un ticket (issue) sur GitHub. Indiquez-nous votre version de Windows, la quantité de RAM et si vous avez un GPU NVIDIA.

Limites connues de la v2.6.0

Nous préférons le dire ouvertement :

Le premier démarrage est long
Environ 5 Go de modèles d’IA sont téléchargés (connexion internet nécessaire) ; le moteur est fourni avec l’installeur. Ollama s’installe une fois, par StarkLLM ou par vos soins.
Les réponses peuvent être fausses
Le modèle 7B par défaut peut confondre des valeurs proches, mal calculer ou manquer une information. Vérifiez toujours la source citée pour les décisions importantes.
Questions dans une autre langue que le document
Une question en anglais sur un document allemand reste souvent sans réponse, car le modèle d’embedding est le plus performant en anglais. Posez votre question dans la langue du document.
La première image télécharge le modèle d’image
Quand vous ajoutez le premier PNG ou JPG (ou une page de PDF numérisé), StarkLLM télécharge une fois le modèle d’image llava (environ 4,4 Go). Le document affiche « Embedding » jusqu’à la fin.
Longs fichiers sans ponctuation
Les journaux et fichiers similaires peuvent être indexés en très gros morceaux : les valeurs isolées qu’ils contiennent sont alors difficiles à retrouver.
Anciennes et nouvelles versions
L’assistant ne sait pas quelle version d’un document est valable, sauf si le texte le précise.
Pas testé sur tous les PC Windows
Nous n’avons pas pu tester tous les PC Windows ; dites-nous à info@starkllm.com si une étape échoue sur votre PC.
Services en arrière-plan
Quand vous quittez StarkLLM, son moteur s’arrête aussi. Ollama continue de tourner avec sa propre icône dans la zone de notification jusqu’à ce que vous le quittiez. Avec le moteur Docker Desktop (avancé), le moteur continue de tourner dans Docker après la fermeture de la fenêtre.
Exécuter du code dans la discussion
« Exécuter » (Run) sur les blocs de code Python est désactivé dans le moteur intégré tant que StarkLLM n’a pas son propre bac à sable ; avec le moteur Docker Desktop (avancé), cela fonctionne comme avant.
Un administrateur par installation
Le premier compte peut sauvegarder toute la base de données, y compris les documents des autres comptes. Ne partagez une installation qu’avec des personnes en qui vous avez confiance.
Pas de réinitialisation du mot de passe
Voir le problème 23.
Vitesse
Les PC sans GPU sont lents ; voir le problème 13.
Les tâches web et le Terminal ont besoin d’un modèle plus grand
Ils fonctionnent le mieux avec un modèle local de 14B ou plus (par exemple qwen3:14b) ; les petits modèles 7B s’arrêtent sans risque, mais terminent peu de tâches. Voir le problème 27.
L’application pour téléphone est un aperçu
L’application Android est sur Google Play en phase de test. Si vous souhaitez l’obtenir sur Google Play, envoyez votre adresse e-mail à info@starkllm.com : vous recevrez le lien vers Google Play. Elle fonctionne sur votre réseau domestique et, seulement pour un téléphone que vous autorisez, hors de chez vous via le relais StarkLLM (chiffré du téléphone jusqu’au PC). Voir le problème 26.
Le premier enregistrement télécharge un modèle vocal
Le premier enregistrement que vous ajoutez télécharge une seule fois Whisper large-v3-turbo (environ 1,6 Go). Entièrement hors ligne, le modèle de dictée plus petit est utilisé.
Les commandes du Terminal ne figurent pas dans la liste du réseau
Une commande que vous autorisez dans le Terminal (par exemple npm install ou git push) et un serveur d’outils que vous ajoutez s’exécutent comme vos propres programmes. Leurs connexions ne figurent pas dans Paramètres › Confidentialité et réseau ; tant que StarkLLM est entièrement hors ligne, les commandes qui utilisent internet sont refusées.

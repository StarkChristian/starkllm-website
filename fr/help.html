Aide

Aide et dépannage

Si StarkLLM ne démarre pas ou si une réponse vous paraît fausse, commencez ici. Chaque étape comporte un test, ce qui vous permet de voir quel élément manque.

Aller à: Liste de contrôle · Problèmes · Obtenir de l’aide · Limites

Comment les éléments s’articulent

StarkLLM n’est pas un seul programme. Trois éléments travaillent ensemble ; depuis la v2.0.1, l’application de bureau démarre les deux autres à votre place :

Docker Desktop

Fait tourner le moteur de StarkLLM (backend et interface web) en arrière-plan. Vous l’installez une fois ; StarkLLM le démarre quand c’est nécessaire.

Ollama

Fait tourner le modèle de langage et le modèle d’embedding sur votre propre PC. Rien n’est envoyé sur internet. Vous l’installez une fois ; StarkLLM le démarre et télécharge les modèles.

L’application StarkLLM (StarkLLM.exe)

Contient le moteur. À chaque démarrage, elle vérifie Docker et Ollama, télécharge les modèles manquants, construit et démarre le moteur, puis affiche StarkLLM. Si un élément manque, elle dit lequel et comment y remédier.

À partir des sources (facultatif)

Les développeurs peuvent construire et lancer le moteur à partir du code source sur GitHub avec docker compose up --build -d. L’application de bureau utilise un moteur déjà en cours d’exécution.

La v2.0.0 (avant le 24 octobre 2026) affichait seulement l’interface web et ne démarrait rien : sur un nouveau PC, sa fenêtre se terminait donc toujours par une erreur. Veuillez installer la v2.1.2 ou une version plus récente.

Remarque honnête : ces étapes ont été établies à partir des scripts de lancement et de vrais essais sous Linux avec Docker et Ollama. Nous n’avons pas pu tester tous les PC Windows. Si quelque chose ici ne correspond pas à ce que vous voyez, dites-le-nous à info@starkllm.com et nous corrigerons cette page.

Liste de contrôle d’installation, avec un test pour chaque étape

Suivez les étapes dans cet ordre. Ne passez pas à la suivante tant que le test d’une étape n’est pas réussi. Ouvrez un terminal (Windows Terminal ou Invite de commandes) pour les commandes.

  1. 1. Virtualisation et WSL2Docker Desktop a besoin de la virtualisation matérielle et de WSL2 sous Windows 10/11.
    wsl --status
    Test : la sortie affiche « Default Version: 2 » (« Version par défaut : 2 » sur un Windows en français). Si WSL est absent, exécutez wsl --install et redémarrez. Dans le Gestionnaire des tâches > Performances > UC, « Virtualisation » doit indiquer « Activé » ; sinon, activez-la dans le BIOS/UEFI (souvent appelée Intel VT-x, SVM ou AMD-V).
  2. 2. Docker DesktopInstallez Docker Desktop, lancez-le et attendez qu’il indique que le moteur fonctionne (icône de baleine fixe dans la zone de notification). Utilisez des conteneurs Linux, pas des conteneurs Windows.
    docker info
    Test : la sortie contient une section « Server: ». Si vous ne voyez que « error during connect ... dockerDesktopLinuxEngine », Docker Desktop n’est pas encore démarré.
  3. 3. OllamaInstallez Ollama depuis ollama.com et vérifiez qu’il fonctionne (icône dans la zone de notification).
    ollama --version
curl http://localhost:11434/api/tags
    Test : la deuxième commande affiche du JSON (une liste de modèles, éventuellement vide).
  4. 4. Les deux modèlesLa configuration par défaut utilise un modèle de discussion 7B et un petit modèle d’embedding. Environ 5 Go à télécharger en tout.
    ollama pull qwen2.5:7b
ollama pull nomic-embed-text
ollama list
    Test : ollama list affiche les deux. Peu de mémoire (PC de 8 Go) ? Utilisez plutôt qwen2.5:3b et sélectionnez-le dans la discussion. D’anciennes copies des instructions mentionnent des modèles qwen3 ; ignorez-les (voir le problème 5 ci-dessous).
  5. 5. Installer et lancer StarkLLMTéléchargez StarkLLM-v2.1.2-Setup.exe depuis la page de téléchargement, installez-le et lancez StarkLLM. Le premier démarrage télécharge les deux modèles (environ 5 Go) et construit le moteur ; cela prend 10 à 20 minutes et la fenêtre affiche la progression. Les étapes 3 et 4 sont faites pour vous si Ollama est installé.Test : la page de connexion de StarkLLM s’affiche. Si la fenêtre indique « StarkLLM could not start », elle liste ce qui manque ; le journal complet se trouve dans %APPDATA%\StarkLLM\engine.log.
  6. 6. Premier testCréez un compte (le premier compte est l’administrateur de cette installation).Test : vous pouvez créer un Workspace (espace de travail) et ajouter un petit fichier texte ; son statut passe à « indexed ». Posez ensuite une question à son sujet et vérifiez que la réponse nomme le fichier.

Problèmes et que faire

Cliquez sur un problème pour voir la cause probable et la solution. Ils sont classés dans l’ordre où on les rencontre le plus souvent.

Installation et démarrage

1. Windows affiche « Windows a protégé votre ordinateur » (SmartScreen) ou Smart App Control bloque l’installeur

Cause probable: Depuis la v2.1.2, l’installeur, StarkLLM.exe et le programme de désinstallation sont signés par « Open Source Developer Christian Stark », afin que Windows puisse vérifier l’éditeur. Windows peut quand même afficher un avertissement pour un fichier qu’il a rarement vu. Les versions antérieures à la v2.1.2 n’étaient pas signées.

Que faire:

  1. Vérifiez l’éditeur : clic droit sur l’installeur, « Propriétés » (Properties), onglet « Signatures numériques » (Digital Signatures). Le signataire doit être « Open Source Developer Christian Stark », et « Détails » (Details) doit indiquer « Cette signature numérique est valide » (This digital signature is OK).
  2. Comparez le hachage SHA-256 avec celui de la page de téléchargement.
  3. Si les deux correspondent, continuez (dans SmartScreen : « Informations complémentaires » (More info), puis « Exécuter quand même » (Run anyway)). Sinon, n’exécutez pas le fichier : téléchargez-le de nouveau et écrivez-nous à info@starkllm.com.
  4. Ne désactivez pas Smart App Control, SmartScreen ni les autres réglages de sécurité. Si Smart App Control bloque un installeur correctement signé, écrivez-nous à info@starkllm.com.
2. « error during connect ... dockerDesktopLinuxEngine: The system cannot find the file specified »

Cause probable: Docker Desktop est installé mais pas encore démarré (ou en cours de démarrage).

Que faire:

  1. Lancez Docker Desktop depuis le menu Démarrer et attendez que le moteur fonctionne.
  2. Exécutez de nouveau docker info ; il doit afficher une section Server:.
  3. S’il ne démarre jamais : redémarrez le PC, mettez WSL à jour (wsl --update) et consultez le problème 3.
  4. docker info
3. « WSL 2 installation is incomplete » ou « Hardware assisted virtualization ... must be enabled in the BIOS »

Cause probable: WSL2 ou la plateforme de machine virtuelle n’est pas installé, ou la virtualisation est désactivée dans le BIOS/UEFI. Dans une machine virtuelle, la virtualisation imbriquée doit aussi être activée.

Que faire:

  1. Exécutez wsl --install dans un terminal administrateur, puis redémarrez.
  2. Activez Intel VT-x / AMD SVM dans le BIOS/UEFI si le Gestionnaire des tâches affiche Virtualisation : Désactivé.
  3. Windows 10/11 Famille fonctionne avec le backend WSL2 ; Hyper-V n’est pas nécessaire.
  4. wsl --install
wsl --update
4. docker compose échoue avec : could not select device driver "nvidia" with capabilities: [[gpu]]

Cause probable: D’anciennes copies du projet (antérieures à la correction de la pull request n° 1 sur GitHub) contiennent une réservation de GPU dans docker-compose.yml. Le backend n’utilise pas le GPU (c’est Ollama qui le fait) : elle est donc inutile et échoue sur les PC sans le NVIDIA Container Toolkit.

Que faire:

  1. Ouvrez docker-compose.yml et supprimez tout le bloc « deploy: » (les lignes avec resources, reservations, devices, driver: nvidia), puis redémarrez. Les copies récentes du projet ne le contiennent plus.
  2. docker compose up --build -d
5. « pull model manifest: file does not exist », « model not found », ou le PC se fige parce que le modèle est beaucoup trop gros

Cause probable: D’anciennes copies de start-here.txt et de .env.example demandaient de récupérer qwen3.8:27b et qwen3-embedding:0.6b. Un modèle 27B a besoin d’environ 17 Go de mémoire libre, et le modèle d’embedding ne correspond pas à celui que l’application attend par défaut.

Que faire:

  1. Utilisez les modèles de la configuration par défaut :
  2. ollama pull qwen2.5:7b
ollama pull nomic-embed-text
docker compose up -d --force-recreate
  3. Si vous avez modifié DEFAULT_TEXT_MODEL ou DEFAULT_EMBEDDING_MODEL dans .env, remettez qwen2.5:7b et nomic-embed-text, puis recréez les conteneurs.
  4. Les documents indexés avec un autre modèle d’embedding doivent être ajoutés de nouveau (les vecteurs n’ont pas la même taille).
6. « Bind for 127.0.0.1:8000 failed: port is already allocated » (ou 5173)

Cause probable: Un autre programme utilise déjà le port 8000 (backend) ou 5173 (interface web).

Que faire:

  1. Repérez le programme, puis fermez-le :
  2. netstat -ano | findstr :8000
tasklist /FI "PID eq <number from the last column>"
  3. Ou déplacez StarkLLM sur d’autres ports (v2.0.1) : exécutez setx STARKLLM_UI_PORT 5174 et setx STARKLLM_API_PORT 8001, puis quittez StarkLLM (y compris dans la zone de notification) et relancez-le. À partir des sources, définissez les deux mêmes variables avant docker compose up.
  4. À noter : BACKEND_PORT et FRONTEND_PORT dans .env.example ne sont pas lus par docker-compose.yml ; les modifier n’a aucun effet.
7. Le premier démarrage est très long ou se termine par une erreur pendant la construction

Cause probable: L’image du backend est volumineuse (environ 4,4 Go) et se construit sur votre PC. Une connexion internet lente, un proxy d’entreprise, un VPN, l’analyse de l’antivirus ou un disque presque plein la ralentissent ou l’arrêtent.

Que faire:

  1. Gardez au moins 15 Go d’espace disque libre (images 4,5 Go, modèles 5 Go, surcoût de Docker).
  2. Suivez la progression au lieu d’attendre à l’aveugle :
  3. docker compose logs -f backend
  4. Derrière un proxy : configurez-le dans Docker Desktop > Settings > Resources > Proxies. Des erreurs comme « failed to resolve source metadata » ou des erreurs TLS indiquent un réseau bloqué ; essayez un autre réseau.
  5. Une fois la cause corrigée, relancez la commande de démarrage ; les couches déjà terminées sont réutilisées.
8. La fenêtre indique « StarkLLM could not start » (ou la v2.0.0 reste sur « Connecting to local engine... »)

Cause probable: Depuis la v2.0.1, l’application démarre elle-même Docker Desktop, Ollama et le moteur, et affiche cette page quand une étape échoue. La v2.0.0 ne démarrait rien et se contentait d’attendre.

Que faire:

  1. Lisez la ligne rouge de la page : elle nomme l’élément manquant (Docker Desktop non installé ou non démarré, Ollama, un port occupé, ou une erreur du moteur avec les dernières lignes de son journal).
  2. Corrigez cet élément et cliquez sur Retry (Réessayer). Le journal complet se trouve dans %APPDATA%\StarkLLM\engine.log.
  3. Vous êtes encore en v2.0.0 ? Installez la v2.0.1 depuis la page de téléchargement.
  4. docker info
curl http://localhost:5173
9. Le navigateur affiche « 502 Bad Gateway » ou une page vide sur localhost:5173

Cause probable: L’interface web fonctionne, mais le backend est encore en cours de démarrage ou a planté.

Que faire:

  1. Attendez une ou deux minutes après un démarrage, puis rechargez la page.
  2. Lisez les dernières lignes du journal du backend ; l’erreur se trouve en général dans les 20 dernières lignes.
  3. Redémarrez uniquement le backend.
  4. docker compose logs --tail 50 backend
docker compose restart backend

Discussion et modèles

10. « Model ... not found in Ollama. Please ensure it is pulled »

Cause probable: La discussion demande un modèle qui n’est pas installé (par défaut : qwen2.5:7b). Dans la v2.0.1, la discussion demandait llama3.2:3b à chaque nouvelle installation (« Model 'llama3.2:3b' not found ») ; la v2.0.2 utilise le modèle que l’application télécharge.

Que faire:

  1. Passez à la v2.0.2, ou choisissez un modèle installé dans le sélecteur de modèle (AI MODEL, en bas à gauche).
  2. Listez les modèles installés et récupérez celui qui manque.
  3. ollama list
ollama pull qwen2.5:7b
11. « Not enough free memory to run model ... », « Error generating response: 500 Server Error ... » ou la réponse n’arrive jamais

Cause probable: Le modèle ne tenait pas dans la mémoire libre et Ollama l’a arrêté. Un modèle 7B demande environ 5 à 6 Go de RAM libre ; avec trop peu de mémoire, Windows devient aussi très lent. Depuis la v2.0.1, la discussion le dit en clair ; la v2.0.0 affichait l’erreur brute « 500 Server Error ».

Que faire:

  1. Fermez les navigateurs, les jeux et les autres gros programmes, puis réessayez.
  2. Choisissez un modèle plus petit, par exemple qwen2.5:3b (environ 2 Go), et sélectionnez-le dans la discussion.
  3. Vérifiez ce qu’Ollama a chargé.
  4. ollama pull qwen2.5:3b
ollama ps
12. « Cannot connect to Ollama » ou la discussion ne répond pas du tout

Cause probable: Ollama ne fonctionne pas, ou un pare-feu bloque la connexion entre le conteneur Docker et le PC. Le backend joint Ollama à l’adresse host.docker.internal:11434.

Que faire:

  1. Démarrez Ollama et vérifiez-le depuis le PC :
  2. curl http://localhost:11434/api/tags
docker compose restart backend
  3. Autorisez Docker Desktop et Ollama dans votre pare-feu ou votre logiciel de sécurité.
  4. Redémarrez ensuite les conteneurs.
13. Les réponses sont très lentes

Cause probable: Sans GPU adapté, Ollama calcule sur le processeur. La première réponse doit aussi charger le modèle (environ 20 secondes lors de notre test). Sur un PC de bureau à 16 cœurs, une réponse courte a pris environ 10 à 40 secondes ; les portables sont plus lents.

Que faire:

  1. Utilisez un modèle plus petit (qwen2.5:3b) sur les PC peu puissants.
  2. Posez des questions courtes et précises ; les longues réponses coûtent le plus de temps.
  3. Un GPU NVIDIA dédié avec 8 Go ou plus de VRAM accélère nettement les choses.
  4. L’indexation est lente aussi : chaque morceau de texte d’un document est envoyé au modèle d’embedding.
14. La réponse reste vide ou les points de « réflexion » ne s’arrêtent jamais (qwen3, deepseek-r1 et autres modèles à réflexion)

Cause probable: Les modèles à réflexion commencent par réfléchir dans un texte masqué. Jusqu’à la v2.0.2, ils pouvaient y consacrer toute la limite de jetons et ne renvoyer aucune réponse. La v2.0.3 demande à Ollama la réponse sans l’étape de réflexion, et une réponse vide s’affiche comme une erreur.

Que faire:

  1. Passez à la v2.0.3.
  2. Si vous voulez que le modèle réfléchisse d’abord : définissez la variable d’environnement Windows OLLAMA_THINK=true, augmentez Max Tokens dans les paramètres (Settings) et redémarrez StarkLLM.

Documents et qualité des réponses

15. L’assistant ignore mes documents et répond à partir de connaissances générales (ou invente quelque chose)

Cause probable: Dans la v2.0.0, la recherche dans les documents ne se lançait que si le message contenait un mot déclencheur anglais comme document ou file. Depuis la v2.0.1, les documents du Workspace sont consultés pour chaque question. Si cela arrive encore, la question et le document emploient en général des mots ou des langues différents.

Que faire:

  1. Passez à la v2.0.1.
  2. Posez votre question dans la langue du document et employez les mots qu’il utilise.
  3. Vérifiez toujours que la réponse nomme un fichier source. Pas de fichier source : vos documents n’ont pas été utilisés.
16. Un fichier ne s’ajoute pas, ou se termine avec le statut « failed »

Cause probable: Le type de fichier n’est pas pris en charge, le fichier est vide ou endommagé, ou il dépasse 100 Mo.

Que faire:

  1. Pris en charge : PDF, DOCX, XLSX, TXT, MD, CSV, JSON, HTML, PNG, JPG.
  2. Ouvrez d’abord le fichier sur votre PC ; un PDF endommagé échoue aussi ici.
  3. Les PDF numérisés et les images nécessitent une reconnaissance de texte (OCR) et sont plus lents ; préférez le fichier texte d’origine si vous l’avez.
  4. Les simples changements de nom (par exemple .exe en .txt) n’y changent rien.
17. Un fichier CSV, Excel ou JSON affiche « indexed », mais rien de ce qu’il contient n’est jamais trouvé (y compris les tableaux dans les fichiers Word)

Cause probable: C’était un problème de la v2.0.0 : ces fichiers étaient marqués comme indexés alors que rien n’était entré dans l’index. Depuis la v2.0.1, les CSV, XLSX, JSON, XML, journaux, Markdown et tableaux des fichiers Word sont indexés (vérifié avec un fichier d’essai de chaque type).

Que faire:

  1. Passez à la v2.0.1 et ajoutez de nouveau le fichier.
  2. Testez chaque nouveau fichier avec une question dont vous connaissez la réponse avant de vous y fier.
18. La réponse dit « not found in the documents », alors que l’information figure dans le document

Cause probable: La recherche ne retient que quelques passages. Elle peut manquer une information quand la question emploie d’autres mots, quand elle est posée dans une autre langue que le document (une question en anglais sur un contrat allemand ne trouve souvent rien), ou quand un long fichier sans phrases ni ponctuation (par exemple un journal machine) a été indexé.

Que faire:

  1. Posez la question dans la langue du document et employez le terme, le nombre ou l’identifiant exact qui y figure.
  2. Rendez la question plus précise (nommez le fichier, la section ou le numéro de modèle).
  3. Pour les longs journaux ou tableaux, découpez le fichier en fichiers plus petits par période ou par sujet.
  4. La réponse cite son fichier source ; ouvrez-le et vérifiez.
19. La réponse mélange une ancienne et une nouvelle version d’un document

Cause probable: Tous les documents ajoutés à un Workspace sont consultés ensemble. Sans date ni mention « remplacé », le modèle ne peut pas savoir quelle version est valable.

Que faire:

  1. Supprimez les documents périmés du Workspace, ou gardez les anciennes versions dans un Workspace distinct.
  2. Indiquez la validité dans le texte (« valable à partir de ... », « remplacé par ... »).
  3. Demandez explicitement : « D’après le contrat de 2026 ... ».
20. Des noms, des nombres ou des références de pièces proches sont confondus

Cause probable: Un modèle 7B exécuté en local peut confondre des valeurs qui se ressemblent (par exemple FT-48 et FT-480) ou mal calculer. Lors de nos propres tests, la même question a reçu une bonne réponse dans certains essais et une mauvaise dans d’autres.

Que faire:

  1. Pour tout ce qui est important, ouvrez la source citée et vérifiez vous-même le nombre.
  2. Posez une question à la fois et nommez le modèle ou la référence exacte.
  3. Un modèle plus grand (qwen2.5:14b, environ 10 Go de RAM) est plus fiable si votre PC peut l’exécuter.
21. Les résumés omettent des points importants, ou les réponses dans des langues autres que l’anglais et l’allemand se lisent mal

Cause probable: Les petits modèles résument de façon approximative et sont plus faibles en dehors de l’anglais et de l’allemand.

Que faire:

  1. Nommez les points dont vous avez besoin : « Résume en trois points : durée, prix, délai de préavis ».
  2. Utilisez un modèle plus grand pour ces tâches.
  3. Rédigez la question dans la langue du document ; la réponse suit la langue de votre question.
22. Un document contient des instructions (« ignore all previous instructions ... »)

Cause probable: Le texte d’un document peut tenter d’orienter le modèle (injection d’instructions, ou prompt injection). Lors de notre test, le modèle a ignoré cette phrase et répondu à la vraie question, mais il n’y a aucune garantie.

Que faire:

  1. N’indexez que des documents en lesquels vous avez confiance.
  2. Traitez avec prudence les réponses issues de documents d’origine inconnue.

Compte, données et désinstallation

23. J’ai oublié mon mot de passe

Cause probable: StarkLLM n’a pas encore de réinitialisation du mot de passe (seulement « change password » quand on est connecté).

Que faire:

  1. Essayez les mots de passe que vous utilisez d’habitude.
  2. En dernier recours, créez un nouveau compte. Ses Workspaces sont distincts : l’ancien compte garde ses données dans le même dossier de données, mais vous ne pouvez pas l’ouvrir.
24. Où sont mes données ? Comment les sauvegarder ?

Cause probable: Tout reste sur votre PC.

Que faire:

  1. Application de bureau (v2.0.1) : la base de données, l’index de recherche et les fichiers ajoutés se trouvent dans %APPDATA%\StarkLLM\data ; votre dossier de Knowledge Base est Documents\StarkLLM Knowledge Base. À partir des sources : data\ et knowledge_base_data\ dans le dossier du projet.
  2. Les paramètres (Settings) comportent une fonction de sauvegarde et de restauration. Depuis la v2.0.1, seul le premier compte (l’administrateur) peut l’utiliser ; une sauvegarde contient les données de tous les comptes : conservez-la en lieu sûr.
  3. Quittez StarkLLM avant de copier les dossiers à la main.
25. Comment arrêter ou désinstaller StarkLLM ?

Cause probable: Il y a plusieurs éléments distincts, et chacun se supprime séparément.

Que faire:

  1. Arrêter : docker compose down (vos données dans data\ restent).
  2. Supprimer le programme : Paramètres Windows > Applications > StarkLLM. Ne supprimez le dossier du projet que si vous n’avez plus besoin de vos données.
  3. Libérer de l’espace disque : docker image prune -a supprime les images inutilisées ; ollama rm <nom> supprime un modèle.
  4. docker compose down
docker image prune -a
ollama rm qwen2.5:7b

Toujours bloqué ? Envoyez-nous ceci

Exécutez ces commandes dans le dossier du projet et envoyez-nous leur sortie, avec une courte description de ce que vous avez fait et de ce que vous avez vu. Retirez d’abord tout ce qui est privé.

winver
wsl --status
docker version
docker compose ps
docker compose logs --tail 100 backend
ollama list
ollama ps

Écrivez à info@starkllm.com ou ouvrez un ticket (issue) sur GitHub. Indiquez-nous votre version de Windows, la quantité de RAM et si vous avez un GPU NVIDIA.

Limites connues de la v2.1.2

Nous préférons le dire ouvertement :

  • Le premier démarrage est long: Environ 5 Go de modèles, plus le moteur, sont téléchargés et construits (10 à 20 minutes, connexion internet nécessaire). Docker Desktop et Ollama doivent être installés une fois par vos soins.
  • Les réponses peuvent être fausses: Le modèle 7B par défaut peut confondre des valeurs proches, mal calculer ou manquer une information. Vérifiez toujours la source citée pour les décisions importantes.
  • Questions dans une autre langue que le document: Une question en anglais sur un document allemand reste souvent sans réponse, car le modèle d’embedding est le plus performant en anglais. Posez votre question dans la langue du document.
  • La première image télécharge le modèle d’image: Quand vous ajoutez le premier PNG ou JPG (ou une page de PDF numérisé), StarkLLM télécharge une fois le modèle d’image llava (environ 4,4 Go). Le document affiche « Embedding » jusqu’à la fin.
  • Longs fichiers sans ponctuation: Les journaux et fichiers similaires peuvent être indexés en très gros morceaux : les valeurs isolées qu’ils contiennent sont alors difficiles à retrouver.
  • Anciennes et nouvelles versions: L’assistant ne sait pas quelle version d’un document est valable, sauf si le texte le précise.
  • Pas testé sur tous les PC Windows: L’application de bureau à démarrage automatique a été testée sous forme d’application empaquetée sous Linux et construite pour Windows ; dites-nous à info@starkllm.com si une étape échoue sur votre PC.
  • Services en arrière-plan: Le moteur continue de tourner dans Docker après la fermeture de la fenêtre, ce qui accélère le démarrage suivant. Arrêtez-le dans Docker Desktop si vous avez besoin de la mémoire.
  • Un administrateur par installation: Le premier compte peut sauvegarder toute la base de données, y compris les documents des autres comptes. Ne partagez une installation qu’avec des personnes en qui vous avez confiance.
  • Pas de réinitialisation du mot de passe: Voir le problème 23.
  • Vitesse: Les PC sans GPU sont lents ; voir le problème 13.

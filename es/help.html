Ayuda

Ayuda y solución de problemas

Si StarkLLM no arranca o una respuesta parece incorrecta, empieza aquí. Cada paso tiene una prueba, para que veas qué pieza falta.

Ir a: Lista de comprobación · Problemas · Obtener ayuda · Límites

Cómo encajan las piezas

StarkLLM no es un único programa. Dos partes trabajan juntas, y la aplicación de escritorio inicia la otra por ti:

La aplicación StarkLLM (StarkLLM.exe)

Contiene el motor (base de datos, índice de búsqueda, backend e interfaz web) y, desde la v2.2, lo ejecuta directamente en Windows: sin Docker Desktop ni WSL2. En cada arranque comprueba Ollama, descarga los modelos que falten, inicia el motor y después muestra StarkLLM. Si falta una pieza, dice cuál y cómo solucionarlo. Cuando sales de StarkLLM, el motor también se detiene.

Ollama

Ejecuta el modelo de lenguaje y el modelo de embeddings en tu propio PC. No se envía nada a internet. Si falta Ollama, StarkLLM ofrece «Instalar Ollama por mí» e instala la versión oficial y firmada; después inicia Ollama y descarga los modelos.

Docker Desktop (opcional, avanzado)

Ya no hace falta desde la v2.2. Si lo prefieres, elige «Usar Docker Desktop para el motor (avanzado)» en el menú de la bandeja; StarkLLM ejecuta entonces su motor en Docker Desktop, con los mismos datos.

Desde el código fuente (opcional)

Los desarrolladores pueden compilar y ejecutar el motor desde el código fuente de GitHub con docker compose up --build -d.

Las versiones anteriores a la 2.2 necesitaban Docker Desktop y WSL2, y la v2.0.0 (anterior al 24 de octubre de 2026) no iniciaba nada en absoluto. Instala la v2.3.0.

Una nota sincera: los pasos se han reunido a partir de las comprobaciones que la aplicación hace en cada arranque y de pruebas reales. No hemos podido probarlo en todos los PC con Windows. Si algo de lo que ves aquí no coincide con lo que te sale, escríbenos a info@starkllm.com y corregiremos esta página.

Lista de instalación con una prueba para cada paso

Haz los pasos en este orden. No sigas hasta que la prueba de un paso se supere. Abre un terminal (Windows Terminal o PowerShell) para los comandos.

  1. 1. Windows y espacio en discoStarkLLM funciona en Windows 10 u 11 (64 bits). No hacen falta Docker Desktop ni WSL2. Mantén al menos 15 GB de espacio libre en disco para la aplicación, el motor y los modelos de IA.
    winver
    Prueba: winver muestra Windows 10 o Windows 11. En el Explorador de archivos, la unidad de tu carpeta de usuario (normalmente C:) tiene al menos 15 GB libres.
  2. 2. Instala y abre StarkLLMDescarga StarkLLM-v2.3.0-Setup.exe desde la página de descarga, instálalo y abre StarkLLM. El motor forma parte del instalador.Prueba: se abre la ventana de StarkLLM y muestra el progreso del arranque. Si dice «StarkLLM no pudo iniciarse», enumera lo que falta y tiene un botón «Reintentar».
  3. 3. OllamaSi falta Ollama, la ventana ofrece «Instalar Ollama por mí»: StarkLLM descarga el instalador oficial desde ollama.com (unos 2 GB), comprueba su firma y lo instala; no hacen falta derechos de administrador. También puedes instalar Ollama tú mismo desde ollama.com.
    ollama --version
curl http://localhost:11434/api/tags
    Prueba: el segundo comando imprime JSON (una lista de modelos, que puede estar vacía).
  4. 4. Los dos modelosEn el primer arranque, StarkLLM descarga un modelo de chat y un modelo de embeddings pequeño (por defecto qwen2.5:7b y nomic-embed-text, unos 5 GB entre los dos) y muestra el progreso. Si ya tienes en Ollama modelos adecuados, se usan esos.
    ollama list
    Prueba: ollama list muestra un modelo de chat y un modelo de embeddings. Si una descarga ha fallado, la ventana nombra el modelo: ejecuta ollama pull con ese nombre y pulsa «Reintentar». ¿Vas justo de memoria (PC de 8 GB)? Usa qwen2.5:3b y selecciónalo en el chat.
  5. 5. Primera pruebaRegistra una cuenta (la primera cuenta es la administradora de esta instalación).Prueba: puedes crear un Workspace y subir un archivo de texto pequeño; su estado cambia a «indexed». Después hazle una pregunta y comprueba que la respuesta nombra el archivo.

Problemas y qué hacer

Haz clic en un problema para ver la causa probable y la solución. Están ordenados según el momento en que la gente suele encontrarlos.

Instalación y arranque

1. Windows dice «Windows protegió su PC» (SmartScreen) o Smart App Control bloquea el instalador

Causa probable: Desde la v2.1.2, el instalador, StarkLLM.exe y el desinstalador están firmados por «Open Source Developer Christian Stark», para que Windows pueda verificar el editor. Aun así, Windows puede avisar de un archivo que todavía ha visto pocas veces. Las versiones anteriores a la v2.1.2 no estaban firmadas.

Qué hacer:

  1. Comprueba el editor: clic derecho en el instalador, Propiedades (Properties), pestaña Firmas digitales (Digital Signatures). El firmante debe ser «Open Source Developer Christian Stark» y en Detalles (Details) Windows debe indicar que la firma es correcta (This digital signature is OK).
  2. Compara el hash SHA-256 con el de la página de descarga.
  3. Si ambos coinciden, continúa (en SmartScreen: More info (Más información) y después Run anyway (Ejecutar de todas formas)). Si no, no ejecutes el archivo: descárgalo de nuevo y escríbenos a info@starkllm.com.
  4. No desactives Smart App Control, SmartScreen ni otros ajustes de seguridad. Si Smart App Control bloquea un instalador correctamente firmado, escríbenos a info@starkllm.com.
2. Smart App Control o un software de seguridad bloquea un archivo de programa del motor

Causa probable: Desde la v2.2.1, todos los archivos de programa del motor (paquetes de Python, Tesseract) están firmados por «Open Source Developer Christian Stark», así que Smart App Control permite que se ejecuten. Aun así, otra regla de control de aplicaciones o un software de seguridad puede bloquear un archivo; entonces el motor no arranca.

Qué hacer:

  1. La página de inicio nombra el archivo bloqueado y el registro del motor (%APPDATA%\StarkLLM\engine-native.log).
  2. No desactives Smart App Control ni tu software de seguridad. Comunica el nombre del archivo en la página de StarkLLM en GitHub o en info@starkllm.com.
  3. Hasta que se solucione, puedes elegir «Usar Docker Desktop para el motor (avanzado)» en el menú de la bandeja (necesita Docker Desktop con WSL2).
3. «Ollama no está instalado» u «Ollama no se está ejecutando»

Causa probable: StarkLLM ejecuta sus modelos de IA con Ollama (gratuito) y espera encontrarlo en 127.0.0.1:11434.

Qué hacer:

  1. Pulsa «Instalar Ollama por mí» en la página de inicio, o instala Ollama tú mismo desde ollama.com.
  2. Si Ollama está instalado: ábrelo desde el menú Inicio, espera a que aparezca su icono en la bandeja y pulsa «Reintentar».
  3. Compruébalo desde el PC:
  4. curl http://localhost:11434/api/tags
4. «pull model manifest: file does not exist», «model not found», o el PC se congela porque el modelo es demasiado grande

Causa probable: El nombre del modelo no existe en Ollama, o el modelo elegido necesita mucha más memoria de la que tiene el PC (un modelo de 27B necesita unos 17 GB de memoria libre). Las copias antiguas de start-here.txt y .env.example nombraban qwen3.8:27b y qwen3-embedding:0.6b.

Qué hacer:

  1. Usa los modelos de la configuración por defecto:
  2. ollama pull qwen2.5:7b
ollama pull nomic-embed-text
  3. O elige un modelo instalado en el selector de modelos (AI MODEL, abajo a la izquierda).
  4. Los documentos indexados con otro modelo de embeddings hay que subirlos de nuevo (los vectores tienen otro tamaño).
5. «Another StarkLLM engine already uses port 5173», o el motor no arranca porque el puerto está ocupado

Causa probable: El motor sirve la aplicación en el puerto 5173 de tu PC (127.0.0.1). Otro programa, o los contenedores de StarkLLM de una instalación anterior con Docker Desktop, ya lo usan. StarkLLM detiene por sí solo sus propios contenedores antiguos; otros programas no puede detenerlos.

Qué hacer:

  1. Busca el programa y ciérralo:
  2. netstat -ano | findstr :5173
tasklist /FI "PID eq <number from the last column>"
  3. O cambia StarkLLM a otro puerto: ejecuta setx STARKLLM_UI_PORT 5174, después elige «Salir de StarkLLM» en el menú de la bandeja y vuelve a abrirlo.
6. El primer arranque tarda muchísimo o falla una descarga

Causa probable: El primer arranque descarga los modelos de IA (unos 5 GB) y, si lo permites, Ollama (unos 2 GB). Un internet lento, un proxy de empresa, una VPN, el análisis del antivirus o un disco casi lleno lo ralentizan o lo detienen.

Qué hacer:

  1. Mantén al menos 15 GB de espacio libre en disco (modelos, unos 5 GB, más Ollama, la aplicación y el motor).
  2. La ventana muestra el progreso de cada descarga. Los errores TLS o de conexión apuntan a una red bloqueada; prueba con otra red.
  3. Cuando hayas arreglado la causa, pulsa «Reintentar»; los modelos ya descargados no se vuelven a descargar.
7. La ventana dice «StarkLLM no pudo iniciarse»

Causa probable: La aplicación inicia por sí sola Ollama y su motor, y muestra esta página cuando un paso falla.

Qué hacer:

  1. Lee la línea roja de la página: nombra la pieza que falta (Ollama, un puerto ocupado, un archivo de programa que Windows ha bloqueado o un error del motor con sus últimas líneas de registro).
  2. Soluciona esa pieza y pulsa «Reintentar». Los registros están en %APPDATA%\StarkLLM: engine.log (la aplicación) y engine-native.log (el motor).
  3. El primer arranque después de una instalación o una actualización puede tardar unos minutos en un PC muy ocupado; la ventana lo indica mientras espera.
8. La ventana se queda vacía o muestra una página de error después del arranque

Causa probable: El motor todavía está arrancando o se ha detenido.

Qué hacer:

  1. Espera uno o dos minutos y después elige «Recargar la aplicación» en el menú de la bandeja.
  2. Si sigue vacía, elige «Salir de StarkLLM» en el menú de la bandeja y vuelve a abrirlo.
  3. El error suele estar en las últimas 20 líneas del registro del motor (ábrelo en PowerShell):
  4. notepad "$env:APPDATA\StarkLLM\engine-native.log"
9. Uso Docker Desktop para el motor (avanzado) y no arranca

Causa probable: Con «Usar Docker Desktop para el motor (avanzado)» en el menú de la bandeja, StarkLLM necesita Docker Desktop con WSL2, como las versiones anteriores a la 2.2. Los errores como «error during connect ... dockerDesktopLinuxEngine» o «WSL 2 installation is incomplete» proceden de Docker Desktop.

Qué hacer:

  1. Abre Docker Desktop y espera hasta que su motor esté en marcha; docker info debe mostrar una sección Server:.
  2. Si falta WSL2, ejecuta wsl --install en un terminal de administrador y reinicia; la virtualización debe estar activada en la BIOS/UEFI.
  3. O vuelve al motor integrado: desmarca «Usar Docker Desktop para el motor (avanzado)» en el menú de la bandeja. Los chats, los documentos y los ajustes son los mismos en ambos.
  4. docker info
wsl --status

Uso del chat y de los modelos

10. «Model ... not found in Ollama. Please ensure it is pulled»

Causa probable: El chat pide un modelo que no está instalado (el predeterminado es qwen2.5:7b). En la v2.0.1 el chat pedía llama3.2:3b en cada instalación nueva («Model 'llama3.2:3b' not found»); la v2.0.2 usa el modelo que descarga la aplicación.

Qué hacer:

  1. Actualiza a la última versión (Ajustes → Acerca de StarkLLM → Buscar actualizaciones), o elige un modelo instalado en el selector de modelos (AI MODEL, abajo a la izquierda).
  2. Lista los modelos instalados y descarga el que falte.
  3. ollama list
ollama pull qwen2.5:7b
11. «Not enough free memory to run model ...», «Error generating response: 500 Server Error ...» o la respuesta no llega nunca

Causa probable: El modelo no cabía en la memoria libre y Ollama lo detuvo. Un modelo de 7B necesita unos 5 a 6 GB de RAM libre; con muy poca memoria, Windows también se vuelve muy lento. Desde la v2.0.1 el chat lo dice con palabras claras; la v2.0.0 mostraba el «500 Server Error» en bruto.

Qué hacer:

  1. Cierra navegadores, juegos y otros programas grandes y vuelve a intentarlo.
  2. Elige un modelo más pequeño, por ejemplo qwen2.5:3b (unos 2 GB), y selecciónalo en el chat.
  3. Comprueba qué tiene cargado Ollama.
  4. ollama pull qwen2.5:3b
ollama ps
12. «Cannot connect to Ollama» o el chat no responde en absoluto

Causa probable: Ollama no está en ejecución, o un software de seguridad bloquea la conexión con él. StarkLLM llega a Ollama en 127.0.0.1:11434 (con el motor de Docker Desktop: host.docker.internal:11434).

Qué hacer:

  1. Inicia Ollama y compruébalo desde el PC:
  2. curl http://localhost:11434/api/tags
  3. Permite Ollama en tu cortafuegos o software de seguridad.
  4. Después elige «Recargar la aplicación» en el menú de la bandeja, o sal de StarkLLM y vuelve a abrirlo.
13. Las respuestas son muy lentas

Causa probable: Sin una GPU adecuada, Ollama calcula con la CPU. Además, la primera respuesta tiene que cargar el modelo (en nuestra prueba, unos 20 segundos). En un sobremesa de 16 núcleos, una respuesta corta tardó entre 10 y 40 segundos; los portátiles son más lentos.

Qué hacer:

  1. Usa un modelo más pequeño (qwen2.5:3b) en PC poco potentes.
  2. Haz preguntas cortas y concretas; las respuestas largas son las que más tiempo cuestan.
  3. Una GPU NVIDIA dedicada con 8 GB o más de VRAM lo acelera mucho. Desde la v2.3, StarkLLM también permite que Ollama use la gráfica integrada (AMD Radeon, Intel Arc/Iris); «Usar la gráfica integrada para la IA» en el menú de la bandeja lo desactiva.
  4. La indexación también es lenta: cada trozo de texto de un documento se envía al modelo de embeddings.
14. La respuesta queda vacía o los puntos de «pensando» no terminan nunca (qwen3, deepseek-r1 y otros modelos que piensan)

Causa probable: Los modelos que piensan primero razonan en un texto oculto. Hasta la v2.0.2 podían gastar en eso todo el límite de tokens y no devolver ninguna respuesta. La v2.0.3 le pide a Ollama la respuesta sin el paso de pensar, y una respuesta vacía se muestra como un error.

Qué hacer:

  1. Actualiza a la última versión (Ajustes → Acerca de StarkLLM → Buscar actualizaciones).
  2. Si quieres que el modelo piense primero: define la variable de entorno de Windows OLLAMA_THINK=true, sube Max Tokens en Settings y reinicia StarkLLM.

Documentos y calidad de las respuestas

15. El asistente ignora mis documentos y responde con conocimientos generales (o se inventa algo)

Causa probable: En la v2.0.0 la búsqueda en los documentos solo se iniciaba cuando el mensaje contenía una palabra desencadenante en inglés, como document o file. Desde la v2.0.1 se buscan los documentos del Workspace en cada pregunta. Si aun así ocurre, lo normal es que la pregunta y el documento usen palabras o idiomas distintos.

Qué hacer:

  1. Actualiza a la última versión (Ajustes → Acerca de StarkLLM → Buscar actualizaciones).
  2. Pregunta en el idioma del documento y usa las palabras que usa el documento.
  3. Comprueba siempre que la respuesta nombra un archivo de origen. Si no hay archivo de origen, tus documentos no se han usado.
16. Un archivo no se sube o termina con el estado «failed»

Causa probable: El tipo de archivo no es compatible, el archivo está vacío o dañado, o pesa más de 100 MB.

Qué hacer:

  1. Compatibles: PDF, DOCX, XLSX, TXT, MD, CSV, JSON, HTML, PNG, JPG.
  2. Abre primero el archivo en tu PC; un PDF dañado también falla aquí.
  3. Los PDF escaneados y las imágenes necesitan reconocimiento de texto (OCR) y son más lentos; si tienes el archivo de texto original, es preferible.
  4. Los trucos de cambiar solo el nombre (por ejemplo de .exe a .txt) no sirven.
17. Un archivo CSV, Excel o JSON aparece como «indexed», pero nunca se encuentra nada de lo que contiene (también las tablas dentro de archivos de Word)

Causa probable: Era un problema de la v2.0.0: estos archivos se marcaban como indexados sin nada en el índice. Desde la v2.0.1 se indexan CSV, XLSX, JSON, XML, registros, Markdown y las tablas dentro de archivos de Word (comprobado con un archivo de prueba de cada tipo).

Qué hacer:

  1. Actualiza a la última versión (Ajustes → Acerca de StarkLLM → Buscar actualizaciones) y vuelve a subir el archivo.
  2. Prueba cada archivo nuevo con una pregunta cuya respuesta conozcas antes de fiarte de él.
18. La respuesta dice «not found in the documents», pero el dato está en el documento

Causa probable: La recuperación elige solo unos pocos pasajes. Puede pasar por alto un dato cuando la pregunta usa otras palabras, cuando la pregunta está en un idioma distinto al del documento (una pregunta en inglés sobre un contrato en alemán a menudo no se encuentra) o cuando se indexó un archivo largo sin frases ni signos de puntuación (por ejemplo un registro de máquina).

Qué hacer:

  1. Pregunta en el idioma del documento y usa el término, el número o el ID exactos que aparecen en él.
  2. Haz la pregunta más específica (nombra el archivo, la sección o el número de modelo).
  3. Para registros o tablas largos, divide el archivo en archivos más pequeños por periodo o tema.
  4. La respuesta cita su archivo de origen; ábrelo y compruébalo.
19. La respuesta mezcla una versión antigua y una nueva de un documento

Causa probable: Se busca a la vez en todos los documentos subidos de un Workspace. Sin una fecha o una nota de «sustituido», el modelo no puede saber qué versión es la vigente.

Qué hacer:

  1. Borra del Workspace los documentos obsoletos, o guarda las versiones antiguas en otro Workspace.
  2. Indica la vigencia en el texto («válido desde ...», «sustituido por ...»).
  3. Pregunta de forma explícita: «Según el contrato de 2026 ...».
20. Se confunden nombres, números o números de pieza parecidos

Causa probable: Un modelo de 7B que se ejecuta en local puede confundir valores parecidos (por ejemplo FT-48 y FT-480) o calcular mal. En nuestras propias pruebas, la misma pregunta se respondió bien en unas ejecuciones y mal en otras.

Qué hacer:

  1. Para cualquier cosa importante, abre la fuente citada y comprueba tú mismo el número.
  2. Haz una pregunta cada vez y nombra el modelo o el número de pieza exactos.
  3. Un modelo más grande (qwen2.5:14b, necesita unos 10 GB de RAM) es más fiable si tu PC puede ejecutarlo.
21. Los resúmenes dejan fuera puntos importantes, o las respuestas en idiomas distintos del inglés y el alemán se leen mal

Causa probable: Los modelos pequeños resumen de forma imprecisa y son más débiles fuera del inglés y el alemán.

Qué hacer:

  1. Nombra los puntos que necesitas: «Resume en tres puntos: duración, precio, plazo de preaviso».
  2. Usa un modelo más grande para estas tareas.
  3. Escribe la pregunta en el idioma del documento; la respuesta sigue el idioma de tu pregunta.
22. Un documento contiene instrucciones («ignore all previous instructions ...»)

Causa probable: El texto dentro de los documentos puede intentar manipular al modelo (inyección de prompts). En nuestra prueba el modelo ignoró una frase así y respondió a la pregunta real, pero no hay ninguna garantía.

Qué hacer:

  1. Indexa solo documentos de confianza.
  2. Trata con cuidado las respuestas que proceden de documentos de origen desconocido.

Cuenta, datos y desinstalación

23. He olvidado mi contraseña

Causa probable: StarkLLM todavía no tiene restablecimiento de contraseña (solo «cambiar contraseña» con la sesión iniciada).

Qué hacer:

  1. Prueba las contraseñas que sueles usar.
  2. Como último recurso, registra una cuenta nueva. Sus Workspaces son independientes: la cuenta antigua conserva sus datos en la misma carpeta de datos, pero no puedes abrirla.
24. ¿Dónde están mis datos? ¿Cómo hago una copia de seguridad?

Causa probable: Todo se queda en tu PC.

Qué hacer:

  1. Aplicación de escritorio: la base de datos, el índice de búsqueda y los archivos subidos están en %APPDATA%\StarkLLM\data; la carpeta de tu Knowledge Base es Documents\StarkLLM Knowledge Base. Desde el código fuente: data\ y knowledge_base_data\ dentro de la carpeta del proyecto.
  2. Settings tiene una función de copia de seguridad y restauración. Desde la v2.0.1 solo puede usarla la primera cuenta (la administradora); una copia de seguridad contiene los datos de todas las cuentas, así que guárdala en un lugar seguro.
  3. Cierra StarkLLM antes de copiar las carpetas a mano.
25. ¿Cómo detengo o desinstalo StarkLLM?

Causa probable: StarkLLM y Ollama son programas independientes, y cada uno se elimina por separado.

Qué hacer:

  1. Detener: elige «Salir de StarkLLM» en el menú de la bandeja; el motor se detiene con él. Ollama sigue en marcha con su propio icono en la bandeja hasta que lo cierres allí.
  2. Quitar el programa: Configuración de Windows > Aplicaciones > StarkLLM. Tus datos en %APPDATA%\StarkLLM\data se conservan hasta que borres tú mismo esa carpeta.
  3. Liberar espacio en disco: ollama rm <name> elimina un modelo. Si usaste el motor de Docker Desktop antes de la 2.2, docker image prune -a elimina sus imágenes antiguas.
  4. ollama list
ollama rm qwen2.5:7b

¿Sigues atascado? Envíanos esto

Ejecuta estos comandos en PowerShell y envíanos la salida con una breve descripción de lo que hiciste y de lo que viste. El último comando muestra el final del registro del motor. Antes, elimina cualquier dato privado.

winver
ollama --version
ollama list
ollama ps
Get-Content "$env:APPDATA\StarkLLM\engine-native.log" -Tail 100

Escribe a info@starkllm.com o abre una incidencia (issue) en GitHub. Indícanos tu versión de Windows, la cantidad de RAM y si tienes una GPU NVIDIA.

Límites conocidos de la v2.3.0

Preferimos decirlo abiertamente:

  • El primer arranque tarda mucho: Se descargan unos 5 GB de modelos de IA (hace falta internet); el motor viene con el instalador. Ollama se instala una vez, lo haga StarkLLM o tú.
  • Las respuestas pueden ser incorrectas: El modelo de 7B por defecto puede confundir valores parecidos, calcular mal o pasar por alto un dato. Comprueba siempre la fuente citada en las decisiones importantes.
  • Preguntas en un idioma distinto al del documento: A menudo no se responde una pregunta en inglés sobre un documento en alemán, porque el modelo de embeddings es más fuerte en inglés. Pregunta en el idioma del documento.
  • La primera imagen descarga el modelo de imágenes: Cuando añades el primer PNG o JPG (o una página escaneada de un PDF), StarkLLM descarga una sola vez el modelo de imágenes llava (unos 4,4 GB). El documento muestra «Embedding» hasta que termina.
  • Archivos largos sin signos de puntuación: Los registros y archivos similares pueden indexarse como trozos muy grandes, así que resulta difícil encontrar los valores sueltos que contienen.
  • Versiones antiguas y nuevas: El asistente no sabe qué versión de un documento es la vigente a menos que lo diga el texto.
  • No probado en todos los PC con Windows: No hemos podido probarlo en todos los PC con Windows; si un paso falla en tu PC, avísanos en info@starkllm.com.
  • Servicios en segundo plano: Cuando sales de StarkLLM, su motor también se detiene. Ollama sigue en marcha con su propio icono en la bandeja hasta que lo cierres. Con el motor de Docker Desktop (avanzado), el motor sigue ejecutándose en Docker después de cerrar la ventana.
  • Ejecutar código en el chat: «Ejecutar» en los bloques de código Python está desactivado en el motor integrado hasta que StarkLLM tenga su propio sandbox; con el motor de Docker Desktop (avanzado) funciona como antes.
  • Un administrador por instalación: La primera cuenta puede hacer una copia de seguridad de toda la base de datos, incluidos los documentos de otras cuentas. Comparte una instalación solo con personas de confianza.
  • Sin restablecimiento de contraseña: Véase el problema 23.
  • Velocidad: Los PC que solo usan la CPU son lentos; véase el problema 13.

Ayuda

Ayuda y solución de problemas

Si StarkLLM no arranca o una respuesta parece incorrecta, empieza aquí. Cada paso tiene una prueba, para que veas qué pieza falta.

Ir a: Lista de comprobación · Problemas · Obtener ayuda · Límites

Cómo encajan las piezas

StarkLLM no es un único programa. Tres partes trabajan juntas; desde la v2.0.1 la aplicación de escritorio inicia las otras dos por ti:

Docker Desktop

Ejecuta el motor de StarkLLM (el backend y la interfaz web) en segundo plano. Lo instalas una vez; StarkLLM lo inicia cuando hace falta.

Ollama

Ejecuta el modelo de lenguaje y el modelo de embeddings en tu propio PC. No se envía nada a internet. Lo instalas una vez; StarkLLM lo inicia y descarga los modelos.

La aplicación StarkLLM (StarkLLM.exe)

Contiene el motor. En cada arranque comprueba Docker y Ollama, descarga los modelos que falten, construye e inicia el motor y después muestra StarkLLM. Si falta una pieza, dice cuál y cómo solucionarlo.

Desde el código fuente (opcional)

Los desarrolladores pueden compilar y ejecutar el motor desde el código fuente de GitHub con docker compose up --build -d. La aplicación de escritorio usa un motor que ya está en marcha.

La v2.0.0 (anterior al 24 de octubre de 2026) solo mostraba la interfaz web y no iniciaba nada, así que en un PC nuevo su ventana siempre terminaba en un error. Instala la v2.1.2 o una posterior.

Una nota sincera: los pasos se han reunido a partir de los scripts de arranque y de pruebas reales en Linux con Docker y Ollama. No hemos podido probarlo en todos los PC con Windows. Si algo de lo que ves aquí no coincide con lo que te sale, escríbenos a info@starkllm.com y corregiremos esta página.

Lista de instalación con una prueba para cada paso

Haz los pasos en este orden. No sigas hasta que la prueba de un paso se supere. Abre un terminal (Windows Terminal o Símbolo del sistema) para los comandos.

  1. 1. Virtualización y WSL2Docker Desktop necesita virtualización por hardware y WSL2 en Windows 10/11.
    wsl --status
    Prueba: la salida muestra «Default Version: 2». Si falta WSL, ejecuta wsl --install y reinicia. En el Administrador de tareas > Rendimiento > CPU, «Virtualización» debe indicar Habilitado; si no, actívala en la BIOS/UEFI (suele llamarse Intel VT-x, SVM o AMD-V).
  2. 2. Docker DesktopInstala Docker Desktop, ábrelo y espera hasta que indique que el motor está en marcha (el icono de la ballena queda fijo en la bandeja). Usa contenedores de Linux, no de Windows.
    docker info
    Prueba: la salida contiene una sección «Server:». Si solo ves «error during connect ... dockerDesktopLinuxEngine», Docker Desktop aún no está en marcha.
  3. 3. OllamaInstala Ollama desde ollama.com y comprueba que está en ejecución (icono en la bandeja).
    ollama --version
curl http://localhost:11434/api/tags
    Prueba: el segundo comando imprime JSON (una lista de modelos, que puede estar vacía).
  4. 4. Los dos modelosLa configuración por defecto usa un modelo de chat de 7B y un modelo de embeddings pequeño. Juntos suponen unos 5 GB de descarga.
    ollama pull qwen2.5:7b
ollama pull nomic-embed-text
ollama list
    Prueba: ollama list muestra los dos. ¿Vas justo de memoria (PC de 8 GB)? Usa qwen2.5:3b en su lugar y selecciónalo en el chat. Las copias antiguas de las instrucciones mencionan modelos qwen3; ignóralas (consulta el problema 5 más abajo).
  5. 5. Instala y abre StarkLLMDescarga StarkLLM-v2.1.2-Setup.exe desde la página de descarga, instálalo y abre StarkLLM. El primer arranque descarga los dos modelos (unos 5 GB) y construye el motor; tarda de 10 a 20 minutos y la ventana muestra el progreso. Si Ollama está instalado, los pasos 3 y 4 se hacen solos.Prueba: aparece la página de inicio de sesión de StarkLLM. Si la ventana dice «StarkLLM could not start», enumera lo que falta; el registro completo está en %APPDATA%\StarkLLM\engine.log.
  6. 6. Primera pruebaRegistra una cuenta (la primera cuenta es la administradora de esta instalación).Prueba: puedes crear un Workspace y subir un archivo de texto pequeño; su estado cambia a «indexed». Después hazle una pregunta y comprueba que la respuesta nombra el archivo.

Problemas y qué hacer

Haz clic en un problema para ver la causa probable y la solución. Están ordenados según el momento en que la gente suele encontrarlos.

Instalación y arranque

1. Windows dice «Windows protegió su PC» (SmartScreen) o Smart App Control bloquea el instalador

Causa probable: Desde la v2.1.2, el instalador, StarkLLM.exe y el desinstalador están firmados por «Open Source Developer Christian Stark», para que Windows pueda verificar el editor. Aun así, Windows puede avisar de un archivo que todavía ha visto pocas veces. Las versiones anteriores a la v2.1.2 no estaban firmadas.

Qué hacer:

  1. Comprueba el editor: clic derecho en el instalador, Propiedades (Properties), pestaña Firmas digitales (Digital Signatures). El firmante debe ser «Open Source Developer Christian Stark» y en Detalles (Details) Windows debe indicar que la firma es correcta (This digital signature is OK).
  2. Compara el hash SHA-256 con el de la página de descarga.
  3. Si ambos coinciden, continúa (en SmartScreen: More info (Más información) y después Run anyway (Ejecutar de todas formas)). Si no, no ejecutes el archivo: descárgalo de nuevo y escríbenos a info@starkllm.com.
  4. No desactives Smart App Control, SmartScreen ni otros ajustes de seguridad. Si Smart App Control bloquea un instalador correctamente firmado, escríbenos a info@starkllm.com.
2. «error during connect ... dockerDesktopLinuxEngine: The system cannot find the file specified»

Causa probable: Docker Desktop está instalado pero todavía no está en marcha (o aún está arrancando).

Qué hacer:

  1. Abre Docker Desktop desde el menú Inicio y espera hasta que el motor esté en marcha.
  2. Ejecuta docker info otra vez; debe mostrar una sección Server:.
  3. Si nunca arranca: reinicia el PC, actualiza WSL (wsl --update) y revisa el problema 3.
  4. docker info
3. «WSL 2 installation is incomplete» o «Hardware assisted virtualization ... must be enabled in the BIOS»

Causa probable: WSL2 o la plataforma de máquina virtual no están instalados, o la virtualización está desactivada en la BIOS/UEFI. En una máquina virtual, también hay que activar la virtualización anidada.

Qué hacer:

  1. Ejecuta wsl --install en un terminal de administrador y reinicia.
  2. Activa Intel VT-x / AMD SVM en la BIOS/UEFI si el Administrador de tareas muestra Virtualización: Deshabilitado.
  3. Windows 10/11 Home funciona con el backend de WSL2; no hace falta Hyper-V.
  4. wsl --install
wsl --update
4. docker compose falla con: could not select device driver "nvidia" with capabilities: [[gpu]]

Causa probable: Las copias antiguas del proyecto (anteriores a la corrección de la pull request #1 en GitHub) contienen una reserva de GPU en docker-compose.yml. El backend no usa la GPU (la usa Ollama), así que no hace falta y falla en los PC sin el NVIDIA container toolkit.

Qué hacer:

  1. Abre docker-compose.yml y borra todo el bloque «deploy:» (las líneas con resources, reservations, devices, driver: nvidia) y vuelve a iniciarlo. Las copias más recientes del proyecto ya no lo contienen.
  2. docker compose up --build -d
5. «pull model manifest: file does not exist», «model not found», o el PC se congela porque el modelo es demasiado grande

Causa probable: Las copias antiguas de start-here.txt y .env.example indicaban descargar qwen3.8:27b y qwen3-embedding:0.6b. Un modelo de 27B necesita unos 17 GB de memoria libre, y el modelo de embeddings no coincide con el que la aplicación espera por defecto.

Qué hacer:

  1. Usa los modelos de la configuración por defecto:
  2. ollama pull qwen2.5:7b
ollama pull nomic-embed-text
docker compose up -d --force-recreate
  3. Si cambiaste DEFAULT_TEXT_MODEL o DEFAULT_EMBEDDING_MODEL en .env, vuelve a ponerlos en qwen2.5:7b y nomic-embed-text y después vuelve a crear los contenedores.
  4. Los documentos indexados con otro modelo de embeddings hay que subirlos de nuevo (los vectores tienen otro tamaño).
6. «Bind for 127.0.0.1:8000 failed: port is already allocated» (o 5173)

Causa probable: Otro programa ya usa el puerto 8000 (backend) o el 5173 (interfaz web).

Qué hacer:

  1. Busca el programa y ciérralo:
  2. netstat -ano | findstr :8000
tasklist /FI "PID eq <number from the last column>"
  3. O cambia StarkLLM a otros puertos (v2.0.1): ejecuta setx STARKLLM_UI_PORT 5174 y setx STARKLLM_API_PORT 8001, después cierra StarkLLM (también en la bandeja) y vuelve a abrirlo. Desde el código fuente, define las mismas dos variables antes de docker compose up.
  4. Nota: BACKEND_PORT y FRONTEND_PORT de .env.example no los lee docker-compose.yml; editarlos no tiene ningún efecto.
7. El primer arranque tarda muchísimo o termina con un error durante la construcción

Causa probable: La imagen del backend es grande (unos 4,4 GB) y se construye en tu PC. Un internet lento, un proxy de empresa, una VPN, el análisis del antivirus o un disco casi lleno la ralentizan o la detienen.

Qué hacer:

  1. Mantén al menos 15 GB de espacio libre en disco (imágenes 4,5 GB, modelos 5 GB, sobrecarga de Docker).
  2. Sigue el progreso en lugar de esperar a ciegas:
  3. docker compose logs -f backend
  4. Detrás de un proxy: configúralo en Docker Desktop > Settings > Resources > Proxies. Errores como «failed to resolve source metadata» o errores TLS apuntan a una red bloqueada; prueba con otra red.
  5. Cuando hayas arreglado la causa, vuelve a ejecutar el comando de inicio; las capas ya terminadas se reutilizan.
8. La ventana dice «StarkLLM could not start» (o la v2.0.0 se queda en «Connecting to local engine...»)

Causa probable: Desde la v2.0.1 la aplicación inicia por sí sola Docker Desktop, Ollama y el motor, y muestra esta página cuando un paso falla. La v2.0.0 no iniciaba nada y solo esperaba.

Qué hacer:

  1. Lee la línea roja de la página: nombra la pieza que falta (Docker Desktop sin instalar o sin iniciar, Ollama, un puerto ocupado o un error del motor con sus últimas líneas de registro).
  2. Soluciona esa pieza y pulsa Retry (reintentar). El registro completo está en %APPDATA%\StarkLLM\engine.log.
  3. ¿Sigues con la v2.0.0? Instala la v2.0.1 desde la página de descarga.
  4. docker info
curl http://localhost:5173
9. El navegador muestra «502 Bad Gateway» o una página vacía en localhost:5173

Causa probable: La interfaz web está en marcha, pero el backend todavía está arrancando o se ha caído.

Qué hacer:

  1. Espera uno o dos minutos después de iniciar y vuelve a cargar la página.
  2. Lee las últimas líneas del registro del backend; el error suele estar en las últimas 20 líneas.
  3. Reinicia solo el backend.
  4. docker compose logs --tail 50 backend
docker compose restart backend

Uso del chat y de los modelos

10. «Model ... not found in Ollama. Please ensure it is pulled»

Causa probable: El chat pide un modelo que no está instalado (el predeterminado es qwen2.5:7b). En la v2.0.1 el chat pedía llama3.2:3b en cada instalación nueva («Model 'llama3.2:3b' not found»); la v2.0.2 usa el modelo que descarga la aplicación.

Qué hacer:

  1. Actualiza a la v2.0.2, o elige un modelo instalado en el selector de modelos (AI MODEL, abajo a la izquierda).
  2. Lista los modelos instalados y descarga el que falte.
  3. ollama list
ollama pull qwen2.5:7b
11. «Not enough free memory to run model ...», «Error generating response: 500 Server Error ...» o la respuesta no llega nunca

Causa probable: El modelo no cabía en la memoria libre y Ollama lo detuvo. Un modelo de 7B necesita unos 5 a 6 GB de RAM libre; con muy poca memoria, Windows también se vuelve muy lento. Desde la v2.0.1 el chat lo dice con palabras claras; la v2.0.0 mostraba el «500 Server Error» en bruto.

Qué hacer:

  1. Cierra navegadores, juegos y otros programas grandes y vuelve a intentarlo.
  2. Elige un modelo más pequeño, por ejemplo qwen2.5:3b (unos 2 GB), y selecciónalo en el chat.
  3. Comprueba qué tiene cargado Ollama.
  4. ollama pull qwen2.5:3b
ollama ps
12. «Cannot connect to Ollama» o el chat no responde en absoluto

Causa probable: Ollama no está en ejecución, o un cortafuegos bloquea la conexión del contenedor de Docker con el PC. El backend llega a Ollama en host.docker.internal:11434.

Qué hacer:

  1. Inicia Ollama y compruébalo desde el PC:
  2. curl http://localhost:11434/api/tags
docker compose restart backend
  3. Permite Docker Desktop y Ollama en tu cortafuegos o software de seguridad.
  4. Después, reinicia los contenedores.
13. Las respuestas son muy lentas

Causa probable: Sin una GPU adecuada, Ollama calcula con la CPU. Además, la primera respuesta tiene que cargar el modelo (en nuestra prueba, unos 20 segundos). En un sobremesa de 16 núcleos, una respuesta corta tardó entre 10 y 40 segundos; los portátiles son más lentos.

Qué hacer:

  1. Usa un modelo más pequeño (qwen2.5:3b) en PC poco potentes.
  2. Haz preguntas cortas y concretas; las respuestas largas son las que más tiempo cuestan.
  3. Una GPU NVIDIA dedicada con 8 GB o más de VRAM lo acelera mucho.
  4. La indexación también es lenta: cada trozo de texto de un documento se envía al modelo de embeddings.
14. La respuesta queda vacía o los puntos de «pensando» no terminan nunca (qwen3, deepseek-r1 y otros modelos que piensan)

Causa probable: Los modelos que piensan primero razonan en un texto oculto. Hasta la v2.0.2 podían gastar en eso todo el límite de tokens y no devolver ninguna respuesta. La v2.0.3 le pide a Ollama la respuesta sin el paso de pensar, y una respuesta vacía se muestra como un error.

Qué hacer:

  1. Actualiza a la v2.0.3.
  2. Si quieres que el modelo piense primero: define la variable de entorno de Windows OLLAMA_THINK=true, sube Max Tokens en Settings y reinicia StarkLLM.

Documentos y calidad de las respuestas

15. El asistente ignora mis documentos y responde con conocimientos generales (o se inventa algo)

Causa probable: En la v2.0.0 la búsqueda en los documentos solo se iniciaba cuando el mensaje contenía una palabra desencadenante en inglés, como document o file. Desde la v2.0.1 se buscan los documentos del Workspace en cada pregunta. Si aun así ocurre, lo normal es que la pregunta y el documento usen palabras o idiomas distintos.

Qué hacer:

  1. Actualiza a la v2.0.1.
  2. Pregunta en el idioma del documento y usa las palabras que usa el documento.
  3. Comprueba siempre que la respuesta nombra un archivo de origen. Si no hay archivo de origen, tus documentos no se han usado.
16. Un archivo no se sube o termina con el estado «failed»

Causa probable: El tipo de archivo no es compatible, el archivo está vacío o dañado, o pesa más de 100 MB.

Qué hacer:

  1. Compatibles: PDF, DOCX, XLSX, TXT, MD, CSV, JSON, HTML, PNG, JPG.
  2. Abre primero el archivo en tu PC; un PDF dañado también falla aquí.
  3. Los PDF escaneados y las imágenes necesitan reconocimiento de texto (OCR) y son más lentos; si tienes el archivo de texto original, es preferible.
  4. Los trucos de cambiar solo el nombre (por ejemplo de .exe a .txt) no sirven.
17. Un archivo CSV, Excel o JSON aparece como «indexed», pero nunca se encuentra nada de lo que contiene (también las tablas dentro de archivos de Word)

Causa probable: Era un problema de la v2.0.0: estos archivos se marcaban como indexados sin nada en el índice. Desde la v2.0.1 se indexan CSV, XLSX, JSON, XML, registros, Markdown y las tablas dentro de archivos de Word (comprobado con un archivo de prueba de cada tipo).

Qué hacer:

  1. Actualiza a la v2.0.1 y vuelve a subir el archivo.
  2. Prueba cada archivo nuevo con una pregunta cuya respuesta conozcas antes de fiarte de él.
18. La respuesta dice «not found in the documents», pero el dato está en el documento

Causa probable: La recuperación elige solo unos pocos pasajes. Puede pasar por alto un dato cuando la pregunta usa otras palabras, cuando la pregunta está en un idioma distinto al del documento (una pregunta en inglés sobre un contrato en alemán a menudo no se encuentra) o cuando se indexó un archivo largo sin frases ni signos de puntuación (por ejemplo un registro de máquina).

Qué hacer:

  1. Pregunta en el idioma del documento y usa el término, el número o el ID exactos que aparecen en él.
  2. Haz la pregunta más específica (nombra el archivo, la sección o el número de modelo).
  3. Para registros o tablas largos, divide el archivo en archivos más pequeños por periodo o tema.
  4. La respuesta cita su archivo de origen; ábrelo y compruébalo.
19. La respuesta mezcla una versión antigua y una nueva de un documento

Causa probable: Se busca a la vez en todos los documentos subidos de un Workspace. Sin una fecha o una nota de «sustituido», el modelo no puede saber qué versión es la vigente.

Qué hacer:

  1. Borra del Workspace los documentos obsoletos, o guarda las versiones antiguas en otro Workspace.
  2. Indica la vigencia en el texto («válido desde ...», «sustituido por ...»).
  3. Pregunta de forma explícita: «Según el contrato de 2026 ...».
20. Se confunden nombres, números o números de pieza parecidos

Causa probable: Un modelo de 7B que se ejecuta en local puede confundir valores parecidos (por ejemplo FT-48 y FT-480) o calcular mal. En nuestras propias pruebas, la misma pregunta se respondió bien en unas ejecuciones y mal en otras.

Qué hacer:

  1. Para cualquier cosa importante, abre la fuente citada y comprueba tú mismo el número.
  2. Haz una pregunta cada vez y nombra el modelo o el número de pieza exactos.
  3. Un modelo más grande (qwen2.5:14b, necesita unos 10 GB de RAM) es más fiable si tu PC puede ejecutarlo.
21. Los resúmenes dejan fuera puntos importantes, o las respuestas en idiomas distintos del inglés y el alemán se leen mal

Causa probable: Los modelos pequeños resumen de forma imprecisa y son más débiles fuera del inglés y el alemán.

Qué hacer:

  1. Nombra los puntos que necesitas: «Resume en tres puntos: duración, precio, plazo de preaviso».
  2. Usa un modelo más grande para estas tareas.
  3. Escribe la pregunta en el idioma del documento; la respuesta sigue el idioma de tu pregunta.
22. Un documento contiene instrucciones («ignore all previous instructions ...»)

Causa probable: El texto dentro de los documentos puede intentar manipular al modelo (inyección de prompts). En nuestra prueba el modelo ignoró una frase así y respondió a la pregunta real, pero no hay ninguna garantía.

Qué hacer:

  1. Indexa solo documentos de confianza.
  2. Trata con cuidado las respuestas que proceden de documentos de origen desconocido.

Cuenta, datos y desinstalación

23. He olvidado mi contraseña

Causa probable: StarkLLM todavía no tiene restablecimiento de contraseña (solo «cambiar contraseña» con la sesión iniciada).

Qué hacer:

  1. Prueba las contraseñas que sueles usar.
  2. Como último recurso, registra una cuenta nueva. Sus Workspaces son independientes: la cuenta antigua conserva sus datos en la misma carpeta de datos, pero no puedes abrirla.
24. ¿Dónde están mis datos? ¿Cómo hago una copia de seguridad?

Causa probable: Todo se queda en tu PC.

Qué hacer:

  1. Aplicación de escritorio (v2.0.1): la base de datos, el índice de búsqueda y los archivos subidos están en %APPDATA%\StarkLLM\data; la carpeta de tu Knowledge Base es Documents\StarkLLM Knowledge Base. Desde el código fuente: data\ y knowledge_base_data\ dentro de la carpeta del proyecto.
  2. Settings tiene una función de copia de seguridad y restauración. Desde la v2.0.1 solo puede usarla la primera cuenta (la administradora); una copia de seguridad contiene los datos de todas las cuentas, así que guárdala en un lugar seguro.
  3. Cierra StarkLLM antes de copiar las carpetas a mano.
25. ¿Cómo detengo o desinstalo StarkLLM?

Causa probable: Hay varias partes independientes, y cada una se elimina por separado.

Qué hacer:

  1. Detener: docker compose down (tus datos en data\ se conservan).
  2. Quitar el programa: Configuración de Windows > Aplicaciones > StarkLLM. Borra la carpeta del proyecto solo cuando ya no necesites tus datos.
  3. Liberar espacio en disco: docker image prune -a elimina las imágenes sin usar; ollama rm <name> elimina un modelo.
  4. docker compose down
docker image prune -a
ollama rm qwen2.5:7b

¿Sigues atascado? Envíanos esto

Ejecuta estos comandos en la carpeta del proyecto y envíanos la salida con una breve descripción de lo que hiciste y de lo que viste. Antes, elimina cualquier dato privado.

winver
wsl --status
docker version
docker compose ps
docker compose logs --tail 100 backend
ollama list
ollama ps

Escribe a info@starkllm.com o abre una incidencia (issue) en GitHub. Indícanos tu versión de Windows, la cantidad de RAM y si tienes una GPU NVIDIA.

Límites conocidos de la v2.1.2

Preferimos decirlo abiertamente:

  • El primer arranque tarda mucho: Se descargan y se construyen unos 5 GB de modelos más el motor (de 10 a 20 minutos, hace falta internet). Docker Desktop y Ollama los tienes que instalar tú una vez.
  • Las respuestas pueden ser incorrectas: El modelo de 7B por defecto puede confundir valores parecidos, calcular mal o pasar por alto un dato. Comprueba siempre la fuente citada en las decisiones importantes.
  • Preguntas en un idioma distinto al del documento: A menudo no se responde una pregunta en inglés sobre un documento en alemán, porque el modelo de embeddings es más fuerte en inglés. Pregunta en el idioma del documento.
  • La primera imagen descarga el modelo de imágenes: Cuando añades el primer PNG o JPG (o una página escaneada de un PDF), StarkLLM descarga una sola vez el modelo de imágenes llava (unos 4,4 GB). El documento muestra «Embedding» hasta que termina.
  • Archivos largos sin signos de puntuación: Los registros y archivos similares pueden indexarse como trozos muy grandes, así que resulta difícil encontrar los valores sueltos que contienen.
  • Versiones antiguas y nuevas: El asistente no sabe qué versión de un documento es la vigente a menos que lo diga el texto.
  • No probado en todos los PC con Windows: La aplicación de escritorio que se inicia sola se probó con la aplicación empaquetada en Linux y está compilada para Windows; si un paso falla en tu PC, avísanos en info@starkllm.com.
  • Servicios en segundo plano: El motor sigue ejecutándose en Docker después de cerrar la ventana, para que el siguiente arranque sea rápido. Deténlo en Docker Desktop si necesitas la memoria.
  • Un administrador por instalación: La primera cuenta puede hacer una copia de seguridad de toda la base de datos, incluidos los documentos de otras cuentas. Comparte una instalación solo con personas de confianza.
  • Sin restablecimiento de contraseña: Véase el problema 23.
  • Velocidad: Los PC que solo usan la CPU son lentos; véase el problema 13.
